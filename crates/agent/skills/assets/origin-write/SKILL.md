# 写作工作流

1. 按当前请求确定用途、读者、交付格式和文体。用户给定的专业写作方法、结构或格式优先。用户只在讨论观点或概念时，继续对话，保留对是否制作文件的决定。
2. 核对用户给出的材料及获准访问的来源。把已确认事实、推断和待确认的问题分别表达。技术文档核对专有术语和责任边界，研究报告核对方法、数据与证据范围。缺失的证据保留为未知，引用只指向实际见过的来源。
3. 按读者理解所需的顺序安排内容。设计说明先交代目的和设计思路，再按需要展开机制、接口和验证。研究报告让读者先理解问题，再判断方法、证据与结论。章节和例子由材料及用途决定。
4. 使用读者需要的书面风格完成正文，保留清晰的判断和取舍。聊天里的语气词、动作描写和玩笑留在适用的对话里。修改既有文档时保留用户未要求改动的事实和意图。
5. 交付前核对结构、术语、事实、引用和格式。明确要求保存时，只在获准的路径写入，然后实际重读文件，核对路径和内容。聊天反馈可简短交代交付状态与仍缺的证据。
