# 加入总量、并发与深度限制

## 目标与交付边界

在 Session 级统一管理 Agent 总量、同时运行数量和树深度，防止无限派生和资源超额。

本增量的交付是一个可以单独运行和观察的功能边界，包含实现、必要的状态/协议衔接、相关文档同步和下列验收。不实现 Runtime 卸载策略；驻留容量在后续单独处理。

## 设计与行为

总量预算、执行 permit、树深度计算、并发预留、Spawn 回滚、资源忙结果。

### 与现有架构的关系

该能力归入 Agentelier 已有的 `agent/runtime`、`agent/conversation`、`agent/turn_runner`、`agent/session_store`、`agent/tools`、`agent/llm_model`、`agent/prompts` 和 Bridge 边界中实际承担该职责的模块。不得为了照搬 Codex 目录而建立平行 Runtime、平行 Conversation 或第二套会话存储。跨领域依赖遵守 `rules/architecture.md`：允许 `ui → agent`、`ui → bridge`、`bridge → agent`，禁止反向依赖。

### 必须保持的不变量

三个限制语义分离；预留先于执行；许可 RAII/显式释放；真实回收后释放运行 permit；边界值明确。

## 验收场景与通过标准

设置可观察的低容量配置，分别触发总量上限、并发上限和最大深度；确认错误能指出具体限制而不是统一“失败”；并发 Spawn 竞争同一最后名额时只有一个成功；Spawn 在持久化前失败释放预留，持久化后失败保留失败身份但释放执行 permit；Agent 正在取消但未真实退出时仍占用并发名额；Root 是否计入子 Agent 总量/并发需按设计约定固定并验证。

## 验证方式

真实多 Agent 运行并发观察；日志/Registry 计数核对；不写 Benchmark。

项目禁止新增或维护自动化测试代码、Benchmark 和 Example。验收应使用真实应用、模型交互、日志、运行状态、存档核对和必要的 BRP，不把这些场景写成测试程序。Root 模型固定为 `gpt-6.2-sol`；需要子 Agent 时，只选择当前目录中已确认属于 GPT-6 及以上且非 Astra 级别的模型。实际 slug 和推理等级必须记录。

## 失败处理

所有失败都应保留 Agent ID、Session ID、Agent Path、原始 Turn/call ID、操作阶段和实际错误类别。若结果未知或持久化回执不确定，应阻断可能重复的副作用，先读取权威状态；不得通过重新 Spawn、重复消息或重放工具调用来掩盖不确定性。

## 许可的预留、持有与释放

总量预留保护 Agent Tree 的规模；并发许可保护实际执行资源；深度检查保护递归树结构。三者分别有独立计数和失败原因。创建流程可能同时申请多个许可，申请失败时释放此前所有未提交许可。执行许可随真实 Runner 生命周期持有，不能在发送 CancellationToken 时释放。

## 额外验收边界

- 总量上限计算明确是否包含 Root，并在所有创建/删除/关闭路径保持一致。
- 并发上限计算明确是否包含 Root；多个并发请求争抢最后一个名额时只能一个成功。
- 深度边界以 Root 深度 0 或 1 的约定固定，测试刚好等于上限成功、超过上限失败。
- Agent Completed 后是否释放并发许可、是否保留总量计数，按两种限制不同语义分别验证。
- 中断请求已发出但 Runner 尚未 join 时，并发许可仍占用；Join 确认后释放一次且只释放一次。
- Spawn 持久提交失败、Runtime 创建失败和调用方取消分别验证预留回滚，不出现计数负数或永久泄漏。
