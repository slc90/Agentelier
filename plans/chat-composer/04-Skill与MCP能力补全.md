# 加入 Skill 与 MCP 能力补全

设计依据：[相关设计文档](../../docs/design/modules/chat-composer.md)。

## 目标

输入 `$` 时，在同一个候选弹层中搜索 Skill、MCP Server 和 MCP Tool。选中后在当前光标位置插入可见引用，同时保存稳定的目标身份。

## 候选来源

Skill 候选来自现有 `agentelier_skills` 目录与内置 Skill 发现结果。候选至少展示名称、描述和来源；实际引用绑定来源路径，不能只保存显示名称。

已有会话的 MCP Server 与 Tool 候选使用会话创建时冻结的 ToolCatalog。当前连接状态决定已登记候选能否选择。Tool 候选绑定 `ToolSource::Mcp` 的 server、target 和 tool，并展示来源、描述和连接状态。未创建会话的草稿根据当前目录给出候选，在 `CreateAndSend` 接纳前用实际冻结的目录校验。

候选列表复用现有目录的 UI 投影，键入时在本地快照中筛选。Skill 目录或连接状态变化时刷新投影。发现的新增 MCP 工具进入后续新会话的目录。

## 选择行为

- 选择 Skill：插入 `$skill-name`，绑定 Skill 来源路径与身份；提交时沿现有 SelectedSkill / 正文快照机制处理。
- 选择 MCP Server：插入服务器引用并保存 Server 身份，提示 Agent 使用该服务提供的能力。
- 选择 MCP Tool：插入具体工具引用并保存 Server、target 和 tool 身份。
- 取消弹层：不改变文本和草稿内容。
- 候选名称重叠时保留类别和来源信息，不把一个 Skill 错解析为 MCP 工具。

手动输入的 `$name` 继续走现有 Skill 解析。弹层插入的结构化 Skill 或 MCP 引用按绑定身份解析，渲染出的 `$name` 区间排除在手动语法扫描之外。

## 选择不是执行

选中 Server 或 Tool 表达用户对本轮任务的显式提示。工具由会话冻结的 ToolCatalog 声明，模型决定是否调用，执行继续经过 ToolRouter 的权限检查。

直接发送时核对原身份和连接状态。队列接纳保存稳定引用，出队时按原会话目录和当时连接状态再次核对。服务器断开、原工具不在目录或身份变化时，指出失效引用并保留输入供处理。活动 Turn 中使用 Queue 或新 Turn 处理显式 Skill/MCP 引用。

## 完成条件

- `$` 弹层能同时显示 Skill、MCP Server 和 MCP Tool 分类。
- 输入字符后候选本地筛选，键盘和鼠标选择均可用。
- 选择结果在 Composer 中可见，且保存稳定身份。
- 同名 Skill 和 MCP Tool 能够区分。
- 旧会话与新会话按各自冻结的目录获取候选，连接可用性独立更新。
- MCP 选择不直接执行工具，不改变现有工具权限和结果持久化流程。
- 断开服务器、工具失效、Skill 重名和 Skill 不可用时均有明确反馈。

## 验证

通过 BRP 真实输入 `$`、筛选、选择、取消和删除引用。验证手写 Skill 语法、带来源的重名 Skill、多个服务器的同名工具、断开连接和队列出队时的失效引用。工具发现变化后核对既有会话与新会话的候选差异，并确认实际调用仍经过现有流程。
