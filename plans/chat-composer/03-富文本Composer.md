# 实现 Agentelier 富文本 Composer

设计依据：[相关设计文档](../../docs/design/modules/chat-composer.md)。

## 目标

在 `chat_ui` 中实现 Agentelier 自己的 Rich Chat Composer，使用户可以在同一输入区域中编辑文字、引用和媒体元素，并按插入顺序显示完整草稿。

## 控件归属

Composer 是聊天业务控件，不属于 bevy_widgetry。它使用 WidgetryTextField 的公开文本编辑能力和 WidgetryFileDialog 的文件选择能力，不向 Widgetry 添加 `$`、`@`、媒体附件或聊天专用补全 API。

BSN 场景组合负责布局和元素投影。WidgetryTextField 的 Editor 管理单个文本段内的编辑，Composer 负责元素顺序、焦点转移、引用身份和附件关联。

## 有序草稿与显示

Composer 使用结构化输入契约建立可编辑草稿。连续文字组成文本段，Skill/MCP/File 引用作为原子引用元素，图片和音频作为媒体元素。用户插入内容后，界面按原始顺序呈现。

一个草稿可以表现为：

```text
文字段 A
图片 A
文字段 B + @src/main.rs
音频 A
文字段 C + $code-review
```

编辑器可以按宽度和内容类型将媒体元素换行或以块状形式呈现，但不能把它们统一移动到文本末尾。显示层的布局不决定模型请求顺序。

本步交付有序编辑与焦点行为，使用现有文本和音频入口验证。能力候选、文件引用补全和新增媒体导入分别在后续阶段接入。

文本段使用 WidgetryTextField 的文本编辑、焦点和选择能力。Composer 负责相邻段之间的焦点切换，以及光标位于引用/媒体边界时的键盘行为。引用和媒体元素按原子项删除，不允许留下半个 token、丢失附件 ID 或失效绑定。

## 焦点与编辑行为

- 单个文本段内的选择、复制粘贴和中文输入法组合沿用 WidgetryTextField。Composer 首版支持跨元素移动光标和整项删除。跨元素选区及其复制粘贴、整份草稿撤销留作后续增量。
- Composer 为 `$` 与 `@` 弹层提供当前光标的锚点和焦点交接，实际候选交互在第 04、05 步验收。
- Enter、Escape、方向键和 Backspace 的行为在编辑器与弹层之间有明确归属。
- 选中引用后，光标回到插入点之后；删除引用时一次移除整个引用元素。
- 切换会话时恢复对应会话的草稿，不把上一个会话的附件或引用带入新会话。

## 媒体元素的呈现边界

图片元素使用 Session Store 的暂存引用展示缩略预览。第 06 步接入选图与正式附件，用户图片与工具生成图片保留各自的消息方向和附件身份。

音频元素复用当前音频附件展示、播放和波形控件。第 07 步把暂存附件作为草稿播放来源，并验证暂停续播、完成后重播和切换音频时重置前一段。

## 草稿提交与回执

Composer 在提交时生成不可变的 `ComposerSubmission` 快照。Conversation 确认接纳后，只清除该快照对应的草稿修订。若用户在请求等待期间继续输入，新内容保留为下一份草稿。

活动 Turn 中，纯文本沿现有 Steer 路径处理。含结构化引用或媒体的输入使用 Queue，或等待当前 Turn 结束后发送。

## 完成条件

- 聊天输入由 Agentelier 自有复合控件承载，bevy_widgetry 不增加聊天专用功能。
- 文本及本步可用的附件按插入顺序显示，后续引用和媒体使用同一组编辑规则。
- 可跨元素移动光标、整项删除并继续中文输入，单段内选择和复制粘贴可用。
- 切换会话、提交、接纳失败和提交期间继续输入时，草稿与附件身份不串会话、不丢失。
- 纯文本聊天、停止、Queue 和现有会话切换行为保持可用。

## 验证

通过 BRP 验证单段编辑、光标跨越现有附件、整项删除、切换会话以及提交期间继续输入。检查焦点与布局，确认接纳失败后仍能编辑原草稿。通过实际 Windows 中文输入法验证组合确认、取消和切段后的焦点。引用与新增媒体结合实际入口在对应阶段验收。
