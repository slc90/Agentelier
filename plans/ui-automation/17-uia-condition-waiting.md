# 实现事件驱动的 UIA 条件等待

## 目标与产出

提供等待 UIA 状态成立的能力，减少固定 `wait(ms)` 对时间的猜测。

## 设计

支持元素出现/消失、属性值匹配、IsEnabled、焦点变化和控件树结构变化。等待先注册事件，再读取一次当前条件；若未成立则等待事件通知，收到通知后重新查询实际状态。事件无法覆盖的条件采用有界检查间隔。

等待在 Rhai 脚本内同步执行，仍处于当前 `computer_execute` 的 ToolAdmission::Exclusive 许可期间。不要设计成“等待时释放桌面独占许可”，也不新增异步工具契约。

等待期限取请求 timeout 与现有 Rhai `Control.deadline` 的较小值。取消后清理等待项和临时订阅；正在执行的 COM 调用返回后再处理取消。

## Rhai API

提供 `uia_wait(element_ref, condition, timeout_ms)`，返回条件成立时的实际元素/属性状态；超时返回 `uia_timeout`，取消返回 `uia_cancelled`。

## 范围

包含事件关联、条件表达、注册后重查、必要的有界轮询、超时和取消。不实现通用任务调度器。

## 验收

- 能等待元素出现和消失。
- 能等待属性值和 IsEnabled 条件。
- 能等待焦点与结构变化。
- 注册与首次条件检查之间不会丢失唤醒。
- 收到事件后会重新查询实际状态，而不是把事件本身当作条件成立。
- 超时和取消返回不同错误。
- 取消后临时订阅和等待项被清理。
- Notepad 文本/焦点变化和 File Explorer 目录展开可触发等待；Provider 不发事件时验证有界轮询路径。
- 等待期间 ToolPermit 保持与现有 `wait(ms)` 一致的独占行为。
