# 准备并冻结 24 道人格测试题

本方案为人格提示词实验准备一套固定测试题。测试集覆盖 Agentelier 的八类典型使用内容，每类三题，共 24 题。每道题在 A0 和 P1 条件下使用完全相同的输入，各运行一次。

测试集的目的不是要求模型显式展示人格，而是通过自然任务观察人格是否稳定体现，以及是否影响模型原有的任务能力。题目不拆成长短组，不进行重复运行。

## 测试类别与覆盖重点

| 类别 | 题数 | 主要观察内容 |
|---|---:|---|
| 日常聊天 | 3 | 接话自然、交流节奏、温柔与情绪稳定，不强行扩展话题 |
| 知识问答 | 3 | 事实准确、回答直接、区分已知与未知 |
| 技术解释 | 3 | 理解概念、清楚解释、根据问题需要控制细节 |
| 技术讨论 | 3 | 独立判断、分析设计取舍、能指出问题而不机械迎合 |
| 问题排查 | 3 | 根据线索推理、提出有效排查路径、随证据更新判断 |
| 文档写作 | 3 | 组织内容、表达质量、按实际用途完成文稿 |
| 数学推理 | 3 | 推导与证明质量、逻辑正确性、发现并纠正错误 |
| 科研讨论 | 3 | 证据意识、因果判断、结论边界和不确定性表达 |

每类三题应有足够差异，避免三个题目只是替换名词的同一模板。题目选择自然、真实、能代表实际使用的内容；技术类可结合实际使用中常见的 Rust、Bevy、系统设计等主题，但不要求所有题目都围绕同一技术栈。

## 题目设计原则

### 以自然任务观察人格

题目应像用户真实提出的问题，不直接要求模型“表现得客观”“证明自己善良”或“用温柔语气回答”。避免把人格评价标准写进用户输入，否则会诱导模型显式表演被测特质。

可以在题目中自然包含需要独立判断的设计方案、存在错误的论证、证据不足的研究结论、用户观点与事实不一致的情形，以及需要承认未知的问题。但这些情形应服务于真实任务，不应为了制造冲突而刻意刁难。

### 保持题目可比较

- 每道题有唯一编号和固定文本。
- 同一道题在 A0 与 P1 中逐字一致，不根据前一组回答临时修改。
- 每题独立运行，不依赖其他测试题的回答或对话历史。
- 不区分长题、短题，也不按回答预期长度分组。
- 每道题每个条件只运行一次，不安排重复样本。

### 保留可核对的正确性依据

知识、数学、技术和科研题目应尽可能提供可核对的事实、题设或参考依据。对有明确答案的问题，准备必要的检查点；对开放性问题，记录评价时应关注的关键论证、设计权衡或证据边界。

评价说明与参考依据只供实验分析者使用，不发送给模型。若某道题没有可靠的正确性判断依据，应明确标记其内容正确性无法直接核验，不以流畅程度替代正确性判断。

## 测试材料的组织

测试集至少包含以下信息：

- 测试编号与所属类别。
- 实际发送给模型的完整用户输入。
- 该题主要观察的人格表现与任务能力。
- 适用时的事实依据、参考答案或人工核对要点。
- 题目自身的边界条件，例如必须使用的给定数据或不能擅自补充的前提。

实际发送文本与评价说明应分开保存，确保模型只收到用户输入，不会收到评价维度、预期人格表现或参考答案。

冻结题集和人工评价依据保存在仓库根目录下的 `experiments/persona-v1/`。测试材料只记录本地提示词文件标识或内容哈希，以便与对应实验记录关联。提示词全文保存在本地用户数据目录。

## 冻结与修改规则

24 道题在正式实验前一次性完成并冻结。冻结后，A0 和 P1 两组都使用同一版本的题目。

如果正式运行前发现事实错误、歧义或无法执行的问题，应先修正并重新冻结完整测试集，再开始正式运行。如果正式运行已经开始，不应只修改某一条件尚未运行的题目；确需修改时，应明确标记受影响的配对样本，并重新安排两组使用同一新题目，不能把不同题目结果当作配对比较。

## 完成条件

- 八类测试内容均有三道题，总数为 24。
- 不存在长短题分组，也没有同题重复运行的安排。
- 每道题均为独立输入，能在新 Session 中单独执行。
- A0 与 P1 的输入文本完全一致。
- 题目以自然任务为主，不直接诱导模型表演人格。
- 事实性、数学、技术和科研题目具备适当的核对依据；无法客观核验的部分已明确标注。
- 模型收到的内容与人工评价说明分离。
- 正式实验开始前，测试集已冻结，且不包含人格提示词全文。

## 边界与限制

本方案只准备测试题及其评价依据，不运行模型、不编写人格提示词，也不生成实验结论。模型版本、推理强度、A0/P1 的请求配置和实际执行方式由下一方案统一处理。
