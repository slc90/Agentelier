# 原位修复或更新自定义控件程序

用户反馈控件不正确时，Agent 应能修复原控件而非每次生成一个新的失败副本。复用稳定产物 ID、定义修订与更新机制，使 Agent 可以修改 Rhai 源文、参数、计算或绘制行为，准备和编译新的程序，确认新 Scene/事件安装与持久提交后才将其作为当前有效定义。程序更新沿现有模型工具及 Rhai 路径，不自动请求模型。

更新时明确新旧定义和用户状态的兼容关系：仍有相同语义的有效状态继续保留；新程序需要状态转换时通过其明确的初始化/恢复约定完成，不从旧 Scope 猜测数据。旧程序回调停止并回收，迟到结果不覆盖新代次。失败时尽量保留最后可用定义、图形和已确认状态，清理这次构造拥有的资源；如果通用 ECS 脚本此前完成了其他修改，按实际事实报告，不能承诺全局事务回滚。用户可根据原位置错误要求修复，Active Turn 内错误仍是普通真实工具回执。

更新后的历史恢复使用最后确认的会话脚本与对应状态。接入第 46 项后，关联 Skill 的实例按其来源选择规则恢复，会话内修复提交的脚本作为该实例的备份。定义修订记录该产物的业务版本，历史工具调用和媒体保有各自的记录。

## 验收

真实 Agent 修复已有控件的计算公式或事件逻辑，BRP 检查原位置、仍有效的输入状态及新行为。提交错误程序后仍可继续使用旧定义或看到真实错误，再修复成功；验证旧回调和重开恢复使用正确的已确认修订。

## 与相邻方案的关系

依赖自定义状态恢复和已有场景更新；下一项使用完整、可确认运行的控件程序作为可复用 Skill 材料。

## 工程约束

遵循 Windows x64 / DX12、PowerShell 7 与锁定 Workspace 依赖。UI 使用 BSN、Scene / SceneList、Widgetry 公开 API；Props 仅初始化，运行期状态由 Component 与相应业务所有者维护。Agent 不依赖 Bevy、UI 或 Bridge，Bridge 不依赖 UI；现有进程内通信与权限边界不变。按实际影响进行 Cargo 检查与真实应用验证，GUI 变化用 BRP 真实输入、截图和 ECS 状态确认，结束后释放 Pointer 并核对 inactive。禁止新增测试、Benchmark、Example 代码及仅用于这些目的的依赖；未经授权不改变登录、凭据或数据目录。实施中同步受影响的当前设计文档，不提前宣称其他增量已实现。
