# 让 Agent 原位更新已存在的动态控件

通过上一增量的稳定产物 ID 更新已有场景，而不是每次 `scene_despawn` 后创造另一条聊天消息。更新可以改变模板语义参数、数据或显示结构，来源与内容位置不变。定义修订与当前状态明确关联，若参数仍有效，更新后保留用户状态；仅在必要时替换受影响的 Scene 子树。

更新后仍存在的参数如果原值已失效，Agent 在同一次更新里显式提供符合新定义的当前值。新定义和参数值一起验证并提交。替换值缺失或无效时，结构化错误说明受影响的参数。

Runtime/Conversation 对来源身份及定义修订协调更新，沿 Session Store 单写入者保存新定义。普通绘制和流式文字变化不重建未变化控件。旧回执不能覆盖较新版本，也不能携带过时 Session 快照覆盖任务与历史。准备新定义及资源并实际确认构造后再公布有效替换；失败时保留最近一次有效内容，清理更新产生的半成品，报告真实错误。现有 ECS 请求/脚本非事务，不对已经成功的外部修改做虚假回滚承诺。

Agent 在运行任务时可获取结构化错误并修正，轮次结束后的控件错误在原位置可见，用户可要求修复，不隐式请求模型。恢复读取最后一次已确认定义。具体 schema 按现有通信和记录类型落地，不改写普通工具协议。

## 验收

真实 Agent 创建按钮后修改其标题或样式，BRP 检查仍是同一产物位置且其他消息与焦点不变。分别在 Agent 完成更新和停止任务后操作对应控件。非法修改保留最近有效定义，随后可以修复。连续更新、切换和重开后取最终已确认修订，回执按各自修订处理。

## 工程约束

遵循 Windows x64 / DX12、PowerShell 7 与锁定 Workspace 依赖。UI 使用 BSN、Scene / SceneList、Widgetry 公开 API；Props 仅初始化，运行期状态由 Component 与相应业务所有者维护。Agent 不依赖 Bevy、UI 或 Bridge，Bridge 不依赖 UI；现有进程内通信与权限边界不变。按实际影响进行 Cargo 检查与真实应用验证，GUI 变化用 BRP 真实输入、截图和 ECS 状态确认，结束后释放 Pointer 并核对 inactive。禁止新增测试、Benchmark、Example 代码及仅用于这些目的的依赖；未经授权不改变登录、凭据或数据目录。实施中同步受影响的当前设计文档，不提前宣称其他增量已实现。
