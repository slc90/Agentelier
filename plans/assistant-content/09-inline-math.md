# 让行内公式参与文字基线与换行

行内数学不是把一个独立公式卡片插到段落旁边。`InlineMath` 表示段落中的一个有宽度、ascent/descent 的排版对象，必须与现有 Markdown 行内文本、标题、列表和表格的布局一起工作。支持 `$...$`；模型常用的 `\(...\)` 作为兼容候选核实后适配，尊重转义、美元金额和代码区间。

使用上一方案的排版引擎和度量，以现有 `MarkdownView` 的段落、TextSpan 和增量更新为基础，核实 Bevy 0.20.1 对真正行内图形/布局对象的支持。需要必要的混合行内布局时按真实职责实现，不以把公式另起一行伪装成行内支持。中英文、粗体/斜体、公式上下标和分式、表格单元格及窄宽度时保持正确基线和断行。字体和 UI Scale 变化产生正确的布局与显示资源；原文复制仍是完整 Markdown。

未闭合公式保留原文，闭合后对应项局部更新；未知命令、不支持的符号或资源加载失败显示原文，不阻断段落。对普通金额、反斜杠、行内代码和围栏保留原语义。

## 验收

实际生成“函数 $f(x)=x^2$ 的导数是 $2x$”等中英文混合、多层分式、列表及表格公式；BRP 截图检查对齐、真实换行、窄宽度和缩放。流式更新只影响对应块，复制仍为原始 LaTeX，普通美元和代码内容未被吞掉。

## 与相邻方案的关系

依赖独立公式共享排版能力；专业符号与宏的覆盖在下一项增加，而非重新设计行内布局。

## 工程约束

遵循 Windows x64 / DX12、PowerShell 7 与锁定 Workspace 依赖。UI 使用 BSN、Scene / SceneList、Widgetry 公开 API；Props 仅初始化，运行期状态由 Component 与相应业务所有者维护。Agent 不依赖 Bevy、UI 或 Bridge，Bridge 不依赖 UI；现有进程内通信与权限边界不变。按实际影响进行 Cargo 检查与真实应用验证，GUI 变化用 BRP 真实输入、截图和 ECS 状态确认，结束后释放 Pointer 并核对 inactive。禁止新增测试、Benchmark、Example 代码及仅用于这些目的的依赖；未经授权不改变登录、凭据或数据目录。实施中同步受影响的当前设计文档，不提前宣称其他增量已实现。
