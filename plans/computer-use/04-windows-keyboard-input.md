# Windows 键盘与文字输入

## 目标与产出

建立 Windows 原生键盘输入能力，覆盖单键、组合键、按下与释放以及文字输入。完成后，Rust Driver 能够在真实 Windows 应用中输入快捷键和普通文本，并在执行结束或取消时清理本次操作留下的按键状态。

## 单键与组合键

Driver 支持明确的按键按下和释放操作，以及常用组合键。组合键必须定义按下顺序和释放顺序，避免修饰键在组合操作后残留。

例如 Ctrl、Shift、Alt 和 Win 等修饰键不能仅通过“发送一次组合键”而忽略持续状态。Driver 需要跟踪本次执行注入的按键，并能够在异常退出时完成释放。

按键标识使用稳定且明确的键语义，不让模型依赖不透明的底层扫描码。具体 Rhai API 的名称和参数结构由 Computer API 方案确定。

## 文字输入

Driver 提供普通文字输入能力，适用于文本框、编辑器和应用内文本区域。文字输入与键盘快捷键是不同操作：前者表达一段文本，后者表达按键事件。

中文输入需要单独检查 Windows 输入法行为。不能假设将 Unicode 字符转换成模拟键击，在所有输入法和应用状态下都等价于粘贴文本。实际输入方式应以运行时行为为准；如果输入法状态或目标控件导致文本未正确进入，应返回可观察结果，交由模型继续判断。

本方案不引入剪贴板管理功能作为额外子系统；如果实现中需要借助 Windows 现有输入能力完成文字输入，应保持在 Driver 的文字输入职责内。

## 按键状态收尾

按键具有持续状态。Driver 跟踪本次执行按下但尚未释放的键。正常结束、脚本取消或任务退出时，只释放 Driver 本次持有的按键，不盲目释放用户物理键盘原本按下的状态。

组合键完成后，修饰键必须恢复释放。输入中途取消时，Driver 仍要执行收尾，不能因为上层任务已经停止就遗留 Ctrl、Shift、Alt 或 Win 等状态。

## 与现有工程的关系

键盘输入属于 `agent/tools` 中 Windows Driver 的本地能力，供后续 Computer API 调用。它与鼠标 Driver 共用桌面输入状态管理，但不建立新的 Agent 工具或运行时。

浏览器自动化继续使用 MCP；本方案只面向 Windows 桌面键盘输入，不实现网页 DOM 或浏览器专用键盘协议。

## 完成条件与运行验证

- 单键按下和释放行为与实际 Windows 输入一致。
- 常用组合键按预期触发，组合完成后没有修饰键残留。
- 普通文字能在记事本或其他普通文本编辑器中正确输入。
- 对中文输入法进行实际输入检查，记录输入法开启与关闭时的行为差异。
- 输入中途取消后，Driver 能释放本次持有的按键。
- 连续多次输入不会继承上一次操作的残留键状态。
- 在 Krita 中验证常用快捷键、工具切换和文本输入场景。
- 通过真实 Windows 应用运行验证，不编写测试代码、Benchmark 或 Example。

## 与后续方案的关系

键盘能力与鼠标基础能力一起构成 Computer API 的输入部分。连续鼠标轨迹不依赖键盘实现；Rhai API 会在两者完成后统一暴露输入接口。
