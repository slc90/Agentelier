# Windows 鼠标基础操作

## 目标与产出

建立 Windows 原生鼠标输入能力，覆盖普通桌面交互所需的移动、按钮、点击、滚动和基础拖动。完成后，Rust Driver 能在真实 Windows 桌面和普通应用中执行常见鼠标操作，并为后续连续轨迹输入提供可靠的按钮状态基础。

本方案依赖[窗口发现与激活](01-window-discovery-and-activation.md)和[桌面截图与坐标体系](02-desktop-capture-and-coordinates.md)。

## 鼠标移动与按钮

Driver 支持鼠标移动，以及左键、右键和中键的按下与释放。点击和双击由明确的按下/释放序列构成，不将“移动到坐标”与“点击目标”混为一个隐式动作。

输入目标可以使用虚拟桌面屏幕坐标，也可以使用指定窗口局部坐标。窗口局部坐标必须根据当前窗口边界转换；窗口移动或尺寸变化后，应使用新的窗口状态重新计算。

## 点击、滚动和拖动

基础鼠标能力包括：

- 左键、右键和中键单击。
- 双击。
- 垂直滚动。
- 水平滚动。
- 从起点到终点的普通拖动。

滚动方向和滚动量需要有明确的输入语义，不能将滚轮增量误当成像素距离。普通拖动用于拖动窗口、选中项目或移动画布等简单场景；它只表达起点和终点，不替代绘画需要的多点连续轨迹。

## 按钮状态

鼠标按钮具有持续按下状态。Driver 必须知道本次执行由自己按下了哪些按钮，并在正常结束、取消或失败收尾时释放仍由本次执行持有的按钮。

清理只针对 Driver 自己注入且尚未释放的按钮，不盲目释放用户在物理鼠标上原本持有的输入状态。一次点击完成后，按钮应恢复为释放状态；普通拖动结束后也必须释放按钮。

## 与连续轨迹的边界

本方案实现普通移动、点击、滚动和单段拖动。绘画笔画需要多个按时间顺序排列的坐标点，并在整个点序列期间维持按钮按下，属于独立的连续轨迹能力，放在下一份鼠标轨迹方案中实现。

## 与现有工程的关系

鼠标能力属于 `agent/tools` 中的 Windows Driver，供后续 Computer API 调用。复用现有 Workspace Windows 依赖；不引入 Bevy Pointer、BRP 输入系统或第三方 Computer Use 库。

桌面独占由现有 `ToolAdmission::Exclusive` 处理，本方案不另建鼠标并发调度系统。底层 Driver 仍需正确管理本次操作的按钮状态，不能依赖上层互斥代替输入释放。

## 完成条件与运行验证

- 在普通 Windows 窗口内移动鼠标，实际指针位置与目标坐标一致。
- 左键、右键和中键的按下、释放、单击与双击行为正确。
- 垂直和水平滚动方向及滚动量符合定义。
- 普通拖动能从起点持续按住并移动至终点，结束后释放按钮。
- 使用屏幕坐标和窗口局部坐标时，点击位置与截图观察到的目标一致。
- 执行中途取消点击或拖动，按钮状态完成收尾。
- 在 Krita 中验证画布点击、画布拖动和普通工具交互。
- 通过真实应用运行验证，不编写测试代码、Benchmark 或 Example。

## 与下一方案的关系

本方案交付鼠标基础输入和按钮状态管理。键盘输入独立实现；连续轨迹方案复用本方案的鼠标按钮和移动能力。
