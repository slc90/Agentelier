# Windows 连续鼠标轨迹输入

## 目标与产出

为 Windows Driver 增加连续多点鼠标轨迹能力，支持绘画笔画、自由曲线和需要按路径持续拖动的桌面交互。完成后，Driver 不仅能执行从起点到终点的普通拖动，还能在鼠标按钮保持按下的状态下沿多个坐标点连续移动。

本方案依赖[Windows 鼠标基础操作](03-windows-mouse-control.md)提供的移动和按钮状态管理。

## 轨迹模型

一条轨迹由按时间顺序排列的多个点组成。每个点至少表达位置；轨迹还需要表达点之间的时间间隔或可等效表达速度的时间信息。轨迹可以使用屏幕坐标，也可以使用窗口局部坐标，但必须沿用统一坐标体系，并在执行前确定坐标目标。

轨迹不是一组独立点击。执行时，Driver 按顺序移动到各点，并在整个轨迹期间保持指定鼠标按钮按下。只有到达轨迹终点或轨迹被取消并完成收尾后，按钮才释放。

轨迹点可以由模型直接提供，也可以由 Rhai 根据模型给出的控制点计算曲线和采样点。Rhai 负责组织路径数据，Windows Driver 负责按时间顺序执行输入，不替模型决定画面中应该画什么。

## 轨迹连续性与速度

绘画笔画需要相邻点之间足够连续，不能退化成离散点击，也不能因为点间等待或坐标转换错误而形成明显断裂。

轨迹执行应尊重点间时间间隔，使不同笔画可以有不同速度。时间信息用于控制输入节奏，不等同于真实数位笔压。第一版使用普通鼠标输入，不要求真实压力感应，也不模拟倾斜、旋转等数位板专属属性。

如果轨迹点数量或持续时间较大，执行仍应允许上层取消。Driver 在取消后停止后续点输入并释放本次按下的按钮。

## 轨迹中断与输入收尾

轨迹开始前确认目标坐标空间和按钮。轨迹执行期间按钮处于按下状态；正常完成时释放按钮。执行失败、窗口失效或任务取消时，Driver 必须停止后续点并释放本次轨迹持有的按钮。

收尾不能依赖模型再发一次 release 调用，因为模型可能已经停止生成或工具任务已经被取消。Driver 必须在本次轨迹执行边界内完成必要释放。

## 与现有工程的关系

连续轨迹属于 Windows 鼠标 Driver，不建立独立的绘图工具或绘画专用运行时。Computer API 后续将它作为普通鼠标能力暴露给 Rhai。

Krita 是最终验收软件，轨迹能力需要在 Krita 实际画布上验证。该能力不依赖 Windows UI Automation，也不需要读取 Krita 内部控件树。

## 完成条件与运行验证

- 一条轨迹可以包含多个按顺序执行的点，并在整条路径期间保持鼠标按钮按下。
- 在 Krita 画布上绘制圆弧、折线和不规则曲线时，结果是连续笔画，而不是多个离散点击。
- 点间时间间隔能够影响笔画执行速度。
- 普通拖动仍保持其起点到终点语义，不被轨迹功能破坏。
- 轨迹结束后鼠标按钮释放。
- 轨迹中途取消时，停止后续点并释放按钮，不遗留按下状态。
- 使用窗口局部坐标和屏幕坐标时，轨迹都落在预期画布位置。
- 通过 Krita 实际绘画验证，不编写测试代码、Benchmark 或 Example。

## 与后续方案的关系

连续轨迹与窗口观察、截图、鼠标基础操作和键盘输入共同构成底层桌面能力。Rhai Runtime 将在这些能力完成后提供脚本执行环境，Computer API 再把它们统一注册到 Rhai。
