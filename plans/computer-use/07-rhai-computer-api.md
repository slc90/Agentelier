# Rhai Computer API

## 目标与产出

将已实现的 Windows Desktop Driver 能力注册到持续 Rhai Runtime，形成模型脚本访问 Windows 桌面的统一 Computer API。完成后，模型通过 Rhai 脚本调用窗口观察、截图、鼠标、键盘、等待和连续轨迹能力，而不直接接触 Win32 原始对象或 Windows 句柄生命周期。

本方案依赖窗口发现、桌面截图、鼠标、键盘、连续轨迹以及持续 Rhai Runtime 的实施结果。

## API 的能力范围

Computer API 至少覆盖以下能力：

**桌面与窗口观察**

- 枚举当前顶层窗口。
- 读取窗口标题、句柄、位置、尺寸及必要状态。
- 激活指定窗口。
- 获取完整虚拟桌面截图。
- 获取指定窗口截图。

**鼠标输入**

- 移动指针。
- 左键、右键和中键按下与释放。
- 单击、双击。
- 垂直和水平滚动。
- 普通拖动。
- 连续多点轨迹。

**键盘输入**

- 单键按下与释放。
- 组合键。
- 文字输入。

**执行辅助**

- 等待指定时长。
- 查询必要的操作结果或执行状态。
- 将错误以脚本可处理的形式返回。

API 函数名称、参数结构、返回类型和错误类别在实现时确定。本方案不预先固定所有函数签名，但要求不同操作遵循一致的坐标约定、错误表达和输入状态规则。

## 脚本与 Driver 的边界

Rhai 脚本只使用 Computer API。脚本不直接调用 Win32 函数、不构造 COM 对象、不管理窗口句柄释放，也不直接持有底层输入设备资源。

Computer API 负责把脚本参数转换为 Driver 所需的输入，并将 Driver 的实际结果转换成 Rhai 可理解的值。窗口句柄可以作为短期目标引用暴露，但 API 必须在使用时确认它仍然对应有效窗口。

坐标参数遵循桌面截图方案定义的虚拟桌面、截图像素和窗口局部坐标体系。不得在不同 API 中分别采用含义相同但转换规则不同的坐标。

## 图片与脚本结果

截图是模型视觉反馈的一部分，不是普通文本。API 的截图操作需要将图像内容交给外层工具执行器，并保留 MIME、尺寸和编码信息。

现有 `ToolPayload::Image` 同时包含文字摘要和 `ImagePayload`，可以沿用现有模型图片反馈路径。脚本可以产生文字执行摘要，并选择返回一张最终截图。一次工具结果只携带一张图片；需要模型根据新画面重新决策时，应结束当前脚本，将截图交回模型。

当前 `ImagePayload` 只接受 PNG/JPEG，编码上限 4 MiB、最长边 2048 像素。截图 API 返回给模型的图片必须遵循该约束，不能绕过图片载荷验证直接构造未受限图片字节。

## 错误与状态

Computer API 需要区分参数不合法、目标窗口失效、输入执行失败、截图失败、等待被取消和脚本执行取消等情况。错误应能从 Rhai 脚本中被处理或传播到工具结果，不能把失败操作伪装成成功返回。

操作结果表示 Driver 实际执行到的状态。发出窗口激活请求不代表窗口一定已成为前台窗口；发送输入也不代表目标应用一定按预期响应。模型需要通过后续窗口信息或截图观察结果。

## 与现有工程的关系

Computer API 与 Rhai Runtime、Windows Driver 一起归属 `agent/tools`。它不新增模型 Function Tool；模型仍通过一个脚本入口调用整个 API。现有 `agent/runtime` 管理脚本任务，现有 `ToolPayload` 承载结果。

本方案不实现 UI Automation，也不通过控件树或语义元素定位弥补坐标操作。浏览器仍由 MCP 处理。

## 完成条件与运行验证

- Rhai 脚本能够枚举窗口、读取窗口信息并激活目标窗口。
- 脚本能够获取完整桌面和指定窗口截图。
- 截图能够以图片附件从执行器返回，而不是变成 Base64 文本。
- 脚本能够调用所有已实现的鼠标和键盘操作。
- 脚本能够提交多点连续轨迹，并控制点间时间。
- 坐标在窗口移动、截图缩放和多显示器场景下保持一致。
- 无效窗口、错误参数和 Driver 失败能够返回明确错误。
- 在真实 Windows 应用中组合执行多步脚本，检查结果和截图。
- 通过实际运行应用验证，不编写测试代码、Benchmark 或 Example。
