# Windows 窗口发现与激活

## 目标与产出

建立 Windows 桌面窗口发现和目标激活能力。完成后，Rust 侧能够枚举当前桌面的顶层窗口，读取识别和定位所需的基本信息，并根据选定窗口执行激活。后续截图、鼠标输入和键盘输入可以共享同一套窗口目标信息。

本方案只处理窗口级信息，不实现窗口内部控件树或 UI Automation。

## 窗口枚举

Driver 需要能够读取当前桌面可见的顶层窗口，并为每个结果提供：

- 当前窗口句柄。
- 窗口标题。
- 窗口在桌面上的位置与尺寸。
- 窗口当前是否可见、是否最小化等与选择目标直接相关的状态。

枚举结果应区分有效窗口和不适合作为用户操作目标的系统窗口。窗口列表用于模型理解当前桌面上有哪些应用，不承担进程管理或应用启动职责。

窗口句柄是当前窗口实例的标识，不是永久身份。窗口关闭后重新创建的实例可能使用不同句柄；模型保存的旧句柄不能被视为仍然有效。每次执行窗口操作前都应根据当前桌面状态确认目标仍存在。

## 窗口信息与坐标基础

窗口位置和尺寸使用统一的桌面屏幕坐标表达。窗口边界应能用于后续的截图裁剪、局部坐标转换和激活后状态核对。

本方案提供窗口矩形及必要的基本信息，不在这里定义完整截图坐标算法。多显示器虚拟桌面原点、DPI/缩放与窗口客户区坐标的转换由下一份桌面截图与坐标方案统一处理。

## 窗口激活

模型可以从枚举结果中选择目标窗口并请求激活。激活结果应能区分目标窗口不存在、激活请求失败和窗口已成为前台目标等情况。激活后应重新读取窗口状态，而不是假设调用成功就意味着焦点一定已切换。

窗口激活只改变桌面焦点，不负责启动程序、恢复账号、处理应用弹窗或自动关闭其他窗口。模型需要根据后续截图决定下一步操作。

## 与现有工程的关系

窗口发现属于 `agent/tools` 中 Windows Computer Driver 的本地能力，使用 Workspace 已有的 Windows 依赖。当前 `windows` 依赖位于根 `Cargo.toml`，现有 Feature 仅覆盖线程相关 API；本方案只在确有需要时增加窗口枚举和激活所需的 Windows API Feature，不引入第三方 Computer Use 或 UIA 库。

该能力先作为 Rust 内部能力提供，不注册模型工具、不引入 Rhai，也不改变 Turn Runner。

## 完成条件与运行验证

- 在 Windows x64 实际运行应用时，能够枚举当前桌面的有效顶层窗口。
- 窗口标题、句柄、位置和尺寸与桌面实际状态相符。
- 能从枚举结果选择一个普通应用窗口并激活。
- 激活后再次读取窗口状态，能够核对目标窗口是否真正成为前台窗口。
- 关闭目标窗口后，使用旧句柄的操作能够明确报告目标失效，不误操作另一个窗口。
- 最小化、隐藏或无标题窗口不会被错误描述成普通可见应用窗口。
- 通过真实应用运行和日志/状态检查验证，不编写测试代码、Benchmark 或 Example。
