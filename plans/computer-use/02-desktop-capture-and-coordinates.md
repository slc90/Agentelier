# Windows 桌面截图与坐标体系

## 目标与产出

建立 Computer Use 的视觉观察基础：完整桌面截图、指定窗口截图，以及截图像素、虚拟桌面屏幕坐标和窗口局部坐标之间的一致映射。完成后，模型能通过现有图片结果机制观察真实 Windows 桌面，后续鼠标操作能够使用与画面一致的坐标。

本方案依赖[窗口发现与激活](01-window-discovery-and-activation.md)提供的窗口句柄与边界信息。

## 两种截图范围

Driver 提供两种截图：

- **完整虚拟桌面截图**：覆盖当前 Windows 虚拟桌面中的显示器布局，而不只截取主显示器。
- **指定窗口截图**：根据目标窗口当前实际边界捕获窗口画面。

截图反映真实显示内容。窗口最小化、被遮挡、超出屏幕或捕获 API 无法提供内容时，应返回实际捕获结果或明确失败，不把空白图像描述为成功的有效窗口截图。

窗口截图以窗口边界为基础；完整桌面截图以虚拟桌面范围为基础。两种截图的原点和尺寸可能不同，不能把窗口截图中的像素坐标直接当作桌面坐标。

## 坐标体系

本设计明确区分三类坐标：

1. **虚拟桌面屏幕坐标**：Windows 桌面输入使用的坐标空间。
2. **截图像素坐标**：截图图像中的像素位置。
3. **窗口局部坐标**：相对于指定窗口边界的局部位置。

多显示器桌面的虚拟原点可能不是 `(0, 0)`，副显示器可能位于主显示器左侧或上方，因此坐标可能为负数。实现不能假设桌面总是从主显示器左上角开始。

坐标转换需要明确使用当前截图的尺寸、虚拟桌面边界和目标窗口边界。窗口移动、缩放或显示器布局变化后，之前保存的窗口坐标映射不应被继续使用。截图与坐标元数据应来自同一次捕获状态，避免画面和输入位置使用不同时间点的窗口矩形。

## 图片载荷与模型反馈

截图以 PNG 或 JPEG 图片载荷返回，不转成普通文本或大型 JSON/Base64 字符串。Agentelier 现有 `ToolPayload::Image` 可以携带文字摘要和 `ImagePayload`，现有模型协议历史能够把图片作为 `input_image` 反馈给模型。

现有图片载荷约束需要纳入截图处理：

- 编码格式为 PNG 或 JPEG。
- 编码图片最长边不超过 2048 像素。
- 单张编码图片不超过 4 MiB。
- 图片描述保留 MIME、尺寸、摘要和编码字节信息。

因此，高分辨率或多显示器截图需要按当前图片载荷约束缩放或重新编码。截图坐标映射必须同步反映缩放比例，不能把缩放后的截图像素坐标直接当成原始屏幕像素坐标。

一次 `ToolPayload::Image` 当前只承载一张图片。一次工具调用需要向模型反馈的截图以一张最终观察图为单位；需要模型查看新状态时，结束本次脚本并通过下一次调用继续。

## 与现有工程的关系

截图能力属于 `agent/tools` 中的 Windows Driver，复用现有 `windows` 和 `image` 依赖。若 Windows API Feature 不足，只扩展当前需要的 Feature，不引入第三方 Computer Use 库或 UI Automation crate。

本方案不注册 Rhai API，也不声明 Function Tool。它只交付可供后续 Computer API 使用的截图与坐标能力。

## 完成条件与运行验证

- 能捕获完整虚拟桌面，图像范围覆盖实际连接的显示器布局。
- 能捕获指定窗口，并与窗口实际边界相符。
- 在多显示器环境下检查非零原点、负坐标和不同显示器排列。
- 截图像素坐标、虚拟桌面屏幕坐标和窗口局部坐标转换一致。
- 在窗口移动、缩放或显示器布局变化后重新获取边界和映射，避免使用旧映射。
- 输出图片能够通过现有 `ToolPayload::Image` 路径保留正确 MIME、尺寸和内容，并能作为模型 `input_image` 进入下一次请求。
- 高分辨率截图按现有图片载荷限制归一化，坐标映射与实际图像尺寸一致。
- 通过实际 Windows 桌面、窗口和多显示器环境验证，不编写测试代码、Benchmark 或 Example。

## 与后续方案的关系

窗口和截图坐标将被鼠标输入使用。鼠标基础操作和键盘输入完成后，Rhai Computer API 再将这些能力组合成脚本接口。
