# 使用 Codex OAuth 完成模型目录和普通对话

## 这一增量完成什么

使用已经接入的 Codex OAuth 外部凭据，让现有模型准备、连接验证和普通文本聊天通过 `https://chatgpt.com/backend-api/codex` 工作。这是迁移到 Codex OAuth 的第一步。过渡期内，用户显式选择的授权决定请求地址，原 SIWC 路径继续服务依赖它的现有使用场景。

模型接入沿用现有 Account、CredentialClient 和聊天会话。两条请求路径的过渡适配随 SIWC 下线收束。

## 来源与请求绑定

Account 向 LLM Model 交付带来源、主体、工作区和生命周期身份的凭据快照。LLM Model 按来源选择模型目录、请求端点、实际支持的传输和响应解释，不直接打开授权文件。当前模型目录的字段解析依照实际 Codex 返回格式调整，不把 SIWC 的 `GET /v1/models` 结构硬套过去。

- 模型选择只取当前授权来源真实可用、具有明确 slug 和推理能力的项；不因出现 GPT-6 名称就假定其工具、音频或图像能力。
- 连接验证与普通聊天共享当前来源；`store: false`、请求材料的固定顺序、SSE 完整终态校验、HTTP 401 的有界恢复语义都要保留适用部分。服务路由确有不同的字段、传输限制时，单独定义适配，不擅自重写已有历史格式。
- 已冻结请求带上来源与模型身份；同一次请求的凭据恢复不能改变账号、工作区或后端路由。错误应保留 HTTP 状态、服务代码和请求标识，不自动切到另一种登录方式。
- Chat UI 使用已有模型准备区与会话设置快照，显示当前来源的模型目录。旧会话保留原模型与工具声明。只有在当前模型、历史协议、工具声明和身份均符合接续条件时才发送下一请求，无法接续的存档仍可查阅。

用户选择外部 Codex 文件后，可以读取模型目录、显式选定模型，在现有聊天窗口接收完整文字回复并继续下一轮。

## 验收

用当前有效外部凭据完成目录读取、独立连接验证和两轮文字聊天，观察实际完成事件与模型选择回显。过渡回归确认显式切回 SIWC 后原目录与聊天仍可用。观察到真实 401、额度不足或模型不可用时，检查保留的状态与错误，按实际观察记录覆盖范围。聊天界面使用 BRP 验证，并执行必要的 Cargo 检查。验证遵守项目关于测试、Benchmark 与 Example 的约束。
