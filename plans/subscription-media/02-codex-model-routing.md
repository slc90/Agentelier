# 使用 Codex OAuth 完成模型目录和普通对话

## 这一增量完成什么

使用上一步已经读取的 Codex OAuth 凭据，让现有模型准备、连接验证和普通文本聊天可以走 `https://chatgpt.com/backend-api/codex`。现有 SIWC 继续访问 `api.openai.com/v1`，用户明确选择哪条来源，模型请求就走对应路径。

这是**模型服务接入**，而不是另建一套聊天会话或第二个账号管理器。

## 来源与请求绑定

Account 向 LLM Model 交付带来源、主体、工作区和生命周期身份的凭据快照。LLM Model 按来源选择模型目录、请求端点、实际支持的传输和响应解释，不直接打开授权文件。当前模型目录的字段解析依照实际 Codex 返回格式调整，不把 SIWC 的 `GET /v1/models` 结构硬套过去。

- 模型选择只取当前授权来源真实可用、具有明确 slug 和推理能力的项；不因出现 GPT-6 名称就假定其工具、音频或图像能力。
- 连接验证与普通聊天共享当前来源；`store: false`、请求材料的固定顺序、SSE 完整终态校验、HTTP 401 的有界恢复语义都要保留适用部分。服务路由确有不同的字段、传输限制时，单独定义适配，不擅自重写已有历史格式。
- 已冻结请求带上来源与模型身份；同一次请求的凭据恢复不能改变账号、工作区或后端路由。错误应保留 HTTP 状态、服务代码和请求标识，不自动切到另一种登录方式。
- Chat UI 使用已有模型准备区与会话设置快照，显示当前来源的模型目录，旧会话保留原模型与工具声明；新请求兼容性按实际服务响应裁决。

最小完整场景是：用户选择外部 Codex 文件、获取它能用的模型目录、显式选择一个模型、在现有聊天窗口接收一次完整文字回复，并能继续下一轮，而不影响原 SIWC。

## 验收

用当前有效外部凭据完成目录读取、独立连接验证、两轮文字聊天；观察实际完成事件与模型选择回显。切回 SIWC 后确认原目录与聊天调用行为没有被覆盖。对真实 401、额度不足或模型不可用情况检查保留的状态与错误；没有发生的故障不宣称已验证。聊天界面影响使用 BRP，必要的 Cargo 检查照工程规则执行，不新增自动化测试代码。
