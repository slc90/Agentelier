# 在聊天中查看、恢复和导出生成图片

## 这一增量完成什么

让 GPT Image 2 的结果从工具文字记录变成用户可以实际查看和保存的聊天产物。完整范围包括生成中状态、成功预览、失败反馈、重启恢复，以及用户明确选择外部路径进行导出。

## 继续使用现有任务与工具时间线

Chat UI 已有工具时间线、状态投影和可重建会话阅读结构。图片生成应以原始工具调用身份出现在相同位置，而不是另开一个与模型历史无关联的图片列表。

- 开始时展示生成状态及安全的提示摘要；完成后显示真实图像预览、尺寸、格式及可操作的保存入口。失败与取消保留原调用位置和明确状态，不显示不存在的图片。
- 预览从 Session Store 的已确认附件读取。UI 与 Bridge 仅持有安全元数据、状态和受控可显示资源，不把文件 Base64 写入 ECS Reflect、窗口诊断或日志。
- 用户主动“另存为”时使用现有 Widgetry 文件选择能力，导出保存的只是**原图副本**；取消选择或写盘失败不删除、覆盖会话内原图。其他应用中的导出文件被修改不改变旧会话结果。
- 返回旧会话时，同一张已保存的图片仍位于原工具结果位置，图文排列与原始 `call_id` 不变化。后台状态更新不抢输入焦点、不清空草稿、不强制将阅读位置滚到末尾。

图像预览和导出只负责展示与用户文件操作，不直接向模型请求新图，不执行与本任务无关的图片编辑功能。Bevy 的显示资源由现有 UI/Assets 职责管理，Session Store 不依赖 Bevy。

## 验收

在实际运行应用中生成一张图片，通过 BRP 检查任务开始、完成、预览和按钮状态；从文件选择器导出，确认输出文件能正确解码且与原附件一致。重启恢复并打开旧会话，验证图片仍显示、原聊天输入与阅读状态保持。取消导出、文件不可写和结果失败时显示真实反馈。依项目禁令不新增测试、Benchmark 或 Example 代码。

## 与前后方案的关系

图片能力在此完成用户可见闭环。接下来的音频文件选择完全独立于图片生成；这里的文件对话框与附件展示经验可以复用，但不形成新的统一媒体组件框架。
