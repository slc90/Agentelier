# 将已有音频文件作为不可变会话附件

## 这一增量完成什么

用户可从本地选择已经存在的音频文件，将其绑定到当前会话输入，并在重新打开会话时看到**同一份文件内容**的附件记录。本阶段不声称模型已经理解或转写它。

这是后续音频理解的可靠起点：文件路径是用户选择时的来源，而不是以后每次分析的权威内容。

## 文件进入会话的过程

界面通过 Widgetry 已有 FileDialog 选择文件，保留原始路径完成后台读取、格式检查和大小约束，再将受控的不可变字节提交给 Session Store。存档关联会话、所属输入、原文件名、内容摘要、实际 MIME、大小与可取得的时长信息。文件名用于安全展示，协议使用附件身份，不把外部路径当成永久回放路径。

```mermaid
flowchart LR
    Pick["本地选中文件"] --> Read["后台读取与实际格式检查"]
    Read --> Save["Session Store 保存不可变附件"]
    Save --> Ref["会话输入的附件引用"]
    Ref --> UI["聊天中的音频附件卡片"]
```

- 首次选取失败、用户取消、文件损坏、不符合允许格式、超过按选定音频路径确定的大小上限，都要明确反馈；没有完整保存成功就不创建有效附件引用。
- 后台读取不阻塞 Bevy 主线程。读取到的音频字节不通过 Bridge、Reflect 状态或日志暴露，UI 只处理身份和安全元数据。
- 目前既有图片结果存储具有自己的编码与尺寸限额，不能让音频复用 PNG/JPEG 载荷类型。这里按真实音频文件类型建立独立附件语义，同时继续使用会话的单写入者和提交确认机制。
- 用户后续覆盖、删除或移动原始文件，旧会话仍引用保存时的内容；账号来源切换不删除已经持久化的本地附件。

当前仅考虑已完成的有界文件输入，不添加麦克风、录音、播放控制、直播流或语音输出。文件选择器可以列出准备支持的音频扩展名，但界面不能把尚未可处理的格式标为“已支持理解”。

## 验收

选择实际 MP3/WAV 等候选文件，确认附件卡片出现、基本元数据正确、保存后重启可读取；随后移动或替换原文件，确认会话中的附件不发生变化。格式或大小失败返回真实原因，选择取消不留下空引用。新 GUI 使用 BRP 验证选择、取消和恢复，文件与数据目录行为使用真实应用核查；不添加持久化测试或 Example 代码。

## 与前后方案的关系

它与图片生成没有技术依赖。下一项在这份不可变文件之上接入真正可用的转写处理路径；处理引擎尚未选定，不应提前把音频载荷直接拼进普通 GPT 文本请求。
