# 处理外部凭据更新与跨账号执行边界

## 这一增量完成什么

让 Codex 外部来源在 Token 到期、官方客户端更新文件、用户切换账号或断开来源时，保持明确且可恢复的业务状态。核心目标是**旧任务不拿新账号的凭据继续运行**，而不在 Agentelier 中抢占外部文件的刷新所有权。

## 同一所有者处理外部变化

外部 `auth.json` 是 Codex 客户端管理的资料：Agentelier 只读重开与校验，不修改 Refresh Token，不在别的文件里另存可用凭据，不为了省一次文件访问而建立跨账号的第二份授权缓存。

读取时取得同一次文件状态下自洽的账号、工作区和 Token 信息。官方 Codex 客户端正常轮换同一主体的 Token 后，下一次业务请求可读取更新后的凭据并沿原来源继续；如果文件未更新而 Access Token 已失效，明确提示用户通过官方 Codex 登录环境恢复，不暗中发起浏览器授权或使用 SIWC 兜底。

当前 CredentialClient 已区分执行身份与凭据版本。Codex 来源沿用同一思路：

- 任务开始前冻结授权来源、主体/工作区与失效生命周期。
- 请求发送、认证恢复和工具真正执行前核对仍属于原执行身份；同一账号的合法 Token 更新可以继续，账号变化不能继续。
- 退出、断开或主动选择另一来源时，先按既有 Runner/Runtime 的任务停止与持久化回执收尾，再对新业务启用新的来源。已经确认保存的会话历史保持可读，不因授权变化被删除。
- 原 SIWC 的按需续期与远端退出保持原逻辑。外部来源的“断开”只是取消选择，不被显示成“远端已退出登录”。

正在运行的 GPT-6 异步工具由已有任务、Turn 和会话身份管理；外部授权突然变化时不能把旧 `call_id` 结果自动提交到另一身份的新请求。存档的原始调用与本地结果仍按现有会话恢复规则保存。

## 验收

在无需主动退出或重新登录的前提下，确认文件只读、重启可恢复来源、手动断开后原文件和 SIWC 凭据均不变化。若官方客户端自然更新同一账号的凭据，观察下一请求接受新文件；若发生实际过期或账号变化，确认旧任务停止、错误准确、历史仍在。未出现的轮换或跨账号场景保留为未验证，不为了制造现象擅自切换用户账号。涉及 UI 的过渡阶段用 BRP 核对，遵守不写测试、Example 和 Benchmark 的工程限制。

## 与后续方案的关系

稳定的来源与身份边界是图片生成和跨 Turn 请求使用同一授权的基础。之后仅扩展模型协议与媒体能力，不在每个工具内再写独立刷新器。
