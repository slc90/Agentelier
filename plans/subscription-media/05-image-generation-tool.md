# 通过 Function Tool 生成并持久保存 GPT Image 2 图片

## 这一增量完成什么

新增一个可被模型调用的图片生成 Function Tool：用户要求生成图片时，Agentelier 使用本次任务绑定的 Codex OAuth 来源调用 `gpt-image-2`，取得真实图像，并在会话中持久保存**原始产物**。工具返回能够辨认生成状态及产物身份的结果；此时即使没有专用预览界面，也可以通过已确认的本地文件查看产物。

## 用现有工具契约接入独立图像服务

普通 GPT 模型负责决定何时调用工具；图像工具使用 Codex Images 路径 `https://chatgpt.com/backend-api/codex/images/generations`，目标模型固定为已经实测的 `gpt-image-2`。工具不要求服务端原生 `image_generation` 类型，因此可沿用现有 Function Tool 和 `call_id` 对应关系。

- 第一版支持文字描述生成单张图片，不增加编辑、参考图、GIF、候选集、2.5/2.6 型号或其他未经这条授权路径验证的参数。
- 只有当前冻结授权支持 Codex Images 时才向模型声明可用工具；SIWC 下不会发出已知无权的生成请求。
- 工具在服务返回时检查结构、真实编码内容、格式与可解码尺寸。HTTP 200 没有有效图片属于失败；错误状态、额度限制和中断分别反馈，失败不自动重试造成重复生成。
- 依照现有异步资格规则注册，可异步时使用既有任务所有者和持久化回执；即使当前模型返回同步调用，也按同步工具结果交付。取消和任务停止沿用现有机制。

## 原图是会话产物，不是调试用临时文件

图片生成结果应通过 Session Store 的单写入者保存为不可变会话附件，附带所属会话、Turn、原始 `call_id`、提示词、实际图像模型、文件类型、尺寸、编码长度、内容摘要和完成状态。原图不为了满足 `view_image` 的 4 MiB 规范化结果限制而缩小；对新附件类型定义基于实际生成文件的明确上限与会话累计预算。需要检查或传给模型的派生图像由下一阶段负责。

文件提交与结果登记需要可恢复的关联。只有图像内容保存成功并得到持久确认，才把工具结果标记为成功；保存失败、取消或响应不完整都不能留下“工具完成但图片不可取”的成功状态。用户之后删除外部复制文件不会影响会话附件。

## 验收

在现有 Codex OAuth 来源下从聊天要求生成简单图片，观察实际 `gpt-image-2` 调用、完整解码、原始尺寸、文件保存、完成状态与工具回执；重启后原产物仍存在且会话引用有效。切换至 SIWC 时工具不会错误请求 Codex Images。取消、服务失败和存储错误按实际可观察情形确认；未发生场景如实标记。采用真实应用、日志和必要的 BRP 界面反馈，不写持久测试、Benchmark 或 Example 代码。
