# 围绕音频文稿开展多轮理解与问答

## 这一增量完成什么

用户在同一会话中选中音频文件、取得文稿后，可以直接要求 Agentelier“总结重点”“列出会议待办”“某位发言者讨论了什么”，并在后续 Turn 中继续针对**同一份来源材料**提问。完成这一增量后，语音类音频文件具备可以观察与恢复的内容理解闭环。

## 将文稿作为有出处的上下文

现有 LLM Model 根据冻结的指令、协议历史和用户输入构造模型请求。音频文稿进入这条路径时，必须保留它与原始音频附件的关联：会话引用、内容摘要、转写结果身份和实际文字，而不是把它扮成用户主动发送的普通文本消息。

- 用户第一次请求分析文件时，明确给模型提供选定文稿及任务指令；模型回答在会话时间线和协议历史中可恢复。
- 后续提问可重新引用保存的同一文稿，使用既有上下文容量、历史冻结及 Compaction 边界处理；不能把大段全文无限重复注入导致原本可用的会话被挤满。
- 模型输出属于对**文稿内容**的理解和推断；如果没有真正取得音频声学内容，回答不能声称已判断真实情绪、音色、背景声音或音乐结构。需要这些能力时必须先有实际可用且获得授权的直接音频理解路径，再单独纳入设计。
- 任务取消、文稿读取失败、文件附件损坏、授权来源切换和会话恢复都沿用已有身份与结果提交边界。历史中的附件引用不能被新的同名文件覆盖。
- Chat UI 展示源文件、文稿、模型回答各自的身份和状态，允许用户读懂回答来自哪段文件。查看已恢复的历史不必再次发送模型请求。

一个完整场景是：用户选取访谈录音，转写成功后要求“概括三条主要观点”，再问“第二条观点的理由是什么”。两轮回答使用同一原始音频附件与转写版本；用户即使已经删掉外部录音，旧会话仍能继续围绕保存的内容讨论。

## 验收与收口

在真实会话中完成选择、转写、总结、追问、取消或重新进入会话，核查模型实际收到的带来源文稿、前后回答的内容一致性及对声学信息的能力限制说明。复验 Codex 普通聊天和图片生成。受影响的聊天控件用 BRP 核对草稿、工具时间线和历史恢复。通过真实运行与相关 Cargo 检查验收，不新增测试、Example 或 Benchmark。

## 实际边界

本次交付的音频理解以**可成功转写的语音类音频文件**为明确完成面。其他声学内容理解需要已验证的直接音频模型输入渠道，当前并没有足以指定模型和授权的依据。该未决项不改变已经完成的文件保存、转写和文本分析能力，也不以未经许可的 API Key 方式偷偷补足。
