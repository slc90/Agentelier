# 把音频文件转写成有来源的文稿

## 这一增量完成什么

让会话中已保存的**语音类音频文件**能够转换为可靠的文字材料，保留其原始音频来源。用户可以查看、复制文稿；后续 Agent 以该材料做摘要和问答。

## 先确定真正可用的处理引擎

本阶段有一个影响能否实现的前提：**音频服务授权路径尚未验证**。现有第三方 SIWC 不支持音频输入和文件转写；官方 Codex 有 `/transcribe` 客户端源码，但这并不等于当前 Codex OAuth 凭据在该路由上有权限。

处理引擎只能在以下得到明确结果后确定：

- 如果当前 Codex OAuth 经过合法、有限的真实文件请求确实支持转写，则复用同一任务授权来源、服务地址、凭据身份与错误处理；不要改为独立 API Key 或另一账号。
- 如果未获该权限，且用户选择本地转写路线，则把可用的本地语音识别模型作为独立的音频执行能力。所选模型、资源限制、语言覆盖及安装方式属于此时需要补齐的设计前提，不能从此前的麦克风讨论擅自推断已确认。
- 两条路线都不可用或尚未选定时，附件仍可保存，但**不能把“转写完成”或“音频理解可用”显示为成功**。

执行方案不得通过伪装官方客户端、绕过服务端授权或自动使用独立计费 API 来完成这个目标。

## 转写结果与音频来源的关系

转写以 Session Store 中已经保存的原始附件为输入，而非重新读取外部路径。调用发生在正常任务或已接纳的工具执行中，保留所属会话、附件摘要、处理引擎、真实结果状态以及可以关联到的原始调用身份。文本可与音频共同恢复，文件重复提问不要求每次重新上传或重新转写。

- 成功表示获得完整文稿，而非仅仅收到 HTTP 200 或部分流事件。空内容、识别失败、取消和超过额度分别表达实际结果；用户未授权新的账号路径时不得自动换服务重试。
- 大文件支持范围必须遵循最终采用的处理引擎的真实格式、大小与时长限制。需要分段时，必须保持片段来源、顺序和合并边界，不把不完整拼接误标为完整。
- 转写生成的文字是一份**来源于文件的模型材料**，不是用户自己在文本框输入的陈述；后续修正或重新转写应保留明确的新结果身份，不改写已有对话证据。
- 长时间处理可利用现有异步任务、取消、结果持久化和恢复规则，不新增另一套音频后台调度器。

## 验收

在最终选定的真实引擎上，使用包含清楚语句的音频文件取得全文，确认文字与音频对应、可查看和复制、关闭重开后不丢失；检查识别错误、取消和不完整结果的反馈。使用日志、真实文件和模型/引擎返回值验收，不编写测试程序或 Benchmark。若未能验证授权或选定本地引擎，明确记录该前提未闭合，不宣称整个功能完成。
