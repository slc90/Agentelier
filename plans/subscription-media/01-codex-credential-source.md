# 选择并读取现有 Codex OAuth 凭据

## 这一增量完成什么

让用户在现有账号界面主动选择一个本地 Codex `auth.json`，Agentelier 能只读解析出合法的 ChatGPT 授权来源和安全账号摘要，并在界面里区分它与现有 SIWC。暂不把该凭据用于模型网络请求。

这样先建立可观察的**来源身份**，避免一边接入模型后端、一边重新解释现有 SIWC 的认证文件语义。

## 凭据来源的具体边界

当前 Account 继续是唯一执行侧账号所有者。新增来源只表示“用户明确指定的外部 Codex 凭据文件”，不新增第二个独立账号拥有者；Login 负责解析官方 `auth.json` 的结构与字段合法性，Account 保存当前来源选择与其安全摘要，Bridge 只转换展示所需信息。

- 用户在 Bevy 账号区域选取本地绝对路径，优先复用 Widgetry 已有文件选择器；路径支持合法 Windows 字符、空格和中文。
- 接受真正的 ChatGPT OAuth 凭据表示，拒绝 API Key 模式、缺失 Token、无法识别的结构或不匹配的账号/工作区标识。官方结构包含 `auth_mode` 和 `tokens`，实际校验不能依赖邮箱相同就视为同一授权。
- 指定文件保持原位、只读，不复制为 Agentelier 的现有认证文件，也不覆盖、轮换、撤销其中的 Token。保存到应用配置的仅是来源类型及文件路径。
- 不自动查找 `$CODEX_HOME`、其他用户目录或别的认证文件；不因为文件无效就退回 SIWC。
- 提供可见的“当前来源”“账号/工作区摘要”“无法读取/不支持/已失效”等状态；秘密数据不进入 ECS、Bridge、普通日志或聊天记录。

已有 SIWC 登录、退出、授权开启、文件恢复和续期入口维持既有含义。选择外部来源不等于把原有 SIWC 账号退出登录。

## 可交付的可观察行为

用户选择有效文件后，账号卡片显示“Codex OAuth（外部凭据）”及可展示的主体信息。关闭并重新打开 Agentelier，所选路径仍在，重新读取并校验；删除、移动或替换文件后，界面显示实际读取状态，原 SIWC 文件没有变化。用户主动断开外部来源时，只移除该文件引用，不调用远端撤销或删除外部文件。

## 验收

使用用户明确许可的真实文件，在 Windows 上选择含空格或中文的路径，确认有效账号摘要与来源状态；断开和重启后确认路径选择行为。核对运行前后外部 `auth.json` 文件内容未被 Agentelier 修改，观察 SIWC 账号恢复仍可使用。对不存在的文件与 API Key 模式只检查错误路径，不制作持久化的测试文件。新增 GUI 用 BRP 验证选择、取消和状态反馈；按项目规则做必要 Cargo 检查，不新增测试、Benchmark 或 Example 代码。

## 与后续方案的关系

下一项在这个来源身份基础上请求 Codex 模型服务。独立的 OAuth 浏览器登录、申请新授权和 Refresh Token 轮换不属于本项，也不被伪装为已完成。
