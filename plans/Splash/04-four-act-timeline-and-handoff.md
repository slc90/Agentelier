# 实现四幕时间线与最终窗口交接

## 目标

将 Bevy 原生字形场景组织为最终确认的 4.82 秒启动演出，并通过 Widgetry Splash 会话交接到使用同一张背景图的 Agentelier 主窗口。

四个时间区段只用于内部时间线组织和调试定位。正式 Splash 不显示阶段名称、中英文副标题、进度条、播放控制或其他开发辅助 UI。

## 四幕时间线

| 时间 | 画面 |
|---|---|
| 0.00–0.65s | 多领域知识碎片在暗绿色空间中自然流动，形成具有远近层次的数据海。 |
| 0.65–1.36s | 四个局部涡流逐渐活跃，规模、旋转方向和密度不同，信息流在不同区域之间交错。 |
| 1.36–2.54s | 多个涡流分出细流，将字符沿曲线送入人物构图；眼睛、发束、衣纹和身体轮廓在不同区域交错显形。 |
| 2.54–4.82s | 字符笔画逐渐落定并取得背景对应位置的明暗；暗绿色数据世界亮成浅薄荷绿，字符逐渐变为墨色并融入原始背景图。 |

四个时间区段在同一个连续空间中完成，不切换成四段独立视频，也不在幕次之间停顿。整个动画由 Bevy 原生渲染路径实时生成，不引入 GStreamer、视频容器、视频解码器或外部视频播放 Pipeline。正式 Splash 只显示动画画面，不叠加幕次名称、字幕或用于试验观察的控制界面。

## 时间线按真实时间推进

时间线在 `SplashShown` 到达后开始，使用 Bevy `Time` 的实际经过时间计算进度，不使用“每帧增加固定数值”的方式。目标流畅度为 60 FPS；实际渲染帧率跟随显示器刷新率和设备性能变化，动画总时长仍然是 4.82 秒。

演出期间保持持续更新/渲染模式，避免隐藏主窗口、未聚焦 Splash Window 或桌面应用低功耗策略使动画停顿。`SplashCompleted` 或取消后恢复 `WinitSettings::desktop_app()`。

四个时间区段共享同一个时间基准，幕次切换不创建独立计时器，避免涡流、字符和背景变化出现时间错位。

## 人物成像与涡流运动

四个涡流在不同时间逐渐增强，并根据各自的方向、尺度和密度吸引数据碎片。涡流之间保留桥接信息流，使它们最终可以共同形成一个人物，而不是四个互不相关的局部对象。

字符从自由流动状态进入汇聚路径，再沿人物目标的轮廓方向接近目标位置。目标字形到达后逐渐稳定，保留局部亮度、角度和深度层次。人物成像由字符本身完成，不显示独立彩色立绘。

## 最终背景过渡

最终背景过渡从约 3.28 秒开始，持续到 4.82 秒。

这一段中：

- 暗绿色数据海逐渐降低存在感。
- 人物目标字形从发光字符转为更接近背景图的墨色笔画。
- 字形逐渐融入 `main-window-background.png` 对应位置的明暗和纹理。
- 场景整体亮度过渡到浅薄荷绿。
- 最终可见帧直接显示共享背景原图。

Splash 和主窗口使用同一个背景图片资源、相同的 16:9 画面比例和相同的裁切映射。不要在 Splash 末尾重新生成一张近似图片，也不要在主窗口单独调整人物位置。

## Widgetry 主窗口交接

时间线结束时调用：

```rust
Splash::finished(world, splash)?;
```

主窗口基础 UI 挂载后，由 application 提交 `Splash::main_ready`。它不等待数据目录检查或用户选择。两个条件可以任意先后到达：

- 主窗口先就绪：Splash 继续播放完整 4.82 秒。
- 演出先结束：Splash 保持最终共享背景帧，等待主窗口就绪。
- 两者都就绪：Widgetry 等待隐藏主窗口的有效帧，显示主窗口，确认主窗口显示后的新帧，再移除 Splash 并发送 `SplashCompleted`。

收到 `SplashCompleted` 后，application 才通知 login_ui 开始数据目录恢复或选择。没有保存目录时，login_ui 在已显示的主窗口前创建模态目录选择窗口；已经保存目录时则检查该目录。Splash 不等待用户交互，也不在数据目录选择窗口背后播放。

窗口交接本身使用同图、同构图和帧确认完成，不需要再叠加一段独立的跨窗口透明度动画。视觉上的暗绿到浅薄荷绿变化已经包含在第四幕内部。

## 失败与退出

如果时间线、Shader 或资源初始化失败，application 取消 Splash 会话并显式显示主窗口，然后通知 login_ui 开始数据目录初始化。`Splash::cancel` 不会替应用显示主窗口，因此回退逻辑必须由 application 执行。

应用在 Splash 播放期间收到 `AppExit` 时，先清理 Splash 会话和场景资源，再交给现有 shutdown 流程。Splash 不单独持有 AgentHost、Runtime 或 JobManager 的关闭逻辑。

## 完成条件

- 演出总时长为 4.82 秒，四个内部时间区段边界正确。
- 正式 Splash 不显示四个区段的名称、中英文副标题、进度条、播放控制或开发辅助 UI。
- 动画按真实时间推进，不因帧率变化而延长或缩短总时长。
- 四个涡流的激活存在时间差，空间运动连续，人物由字形形成。
- 人物成像与背景采样目标一致，最终不出现独立彩色角色 PNG 图层。
- 第四幕从暗绿色空间过渡到浅薄荷绿共享背景，最终帧与主窗口背景图完全一致。
- Splash 完成早于主窗口就绪时，最终背景帧持续显示，不出现黑屏或随机停帧。
- 主窗口先就绪时，Splash 不会提前结束。
- Widgetry 完成主窗口帧确认后才移除 Splash。
- `SplashCompleted` 后 Camera、场景实体和播放资源得到清理。
- 从托盘恢复主窗口不会重新播放 Splash。
- 实际 Windows 启动时没有主窗口提前闪现、Splash 结束黑帧、背景人物跳动或尺寸变化。

验证使用实际 Windows 启动、BRP 状态观察和不同显示刷新率下的播放检查；遵循项目现有约束，不新增 Unit Test、Integration Test、Regression Test、Benchmark 或 Example 代码。
