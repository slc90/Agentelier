# 构建 Bevy 原生字符渲染场景

## 目标

将最终浏览器原型中的字形图集、知识碎片和人物成像机制移植到 Bevy
原生渲染路径，形成可以静态检查的字符少女画面。该场景直接渲染到 Widgetry
创建的 Splash Window，不使用 WebView、浏览器 Canvas 或预制视频。

## 从一张背景图得到字符目标

`main-window-background.png` 同时承担两个作用：

1.  它是 Splash 最终帧和 Agentelier 主窗口共用的背景。
2.  它提供人物字符成像的采样目标。

场景初始化时读取这张图片的像素信息，根据明暗、边缘和局部结构生成字形目标位置。目标位置包含归一化坐标、方向、大小、亮度和到达时序等信息。眼睛、头发、衣纹和服装等区域在字形分布中形成不同的结构，不把字符简单平均地填满一个人形遮罩。

采样只在场景初始化时执行一次。每帧只更新字形实例的位置、方向、大小、颜色和透明度，不重复读取整张图片或重新生成所有目标点。

## 字形图集与知识内容

将最终原型中的知识碎片组织方式保留下来，字形内容来自自然语言、代码、数学公式、化学式、物理与其他结构化知识。不同内容的长度、密度和视觉形态保持差异。

渲染器使用字形图集保存可复用的字符纹理。图集应覆盖中文、拉丁字母、数字、常用数学符号和代码标点；字体使用项目可控的资源，避免依赖每台
Windows 机器上不一致的系统字体。

每个字形实例只保存绘制所需的数据，例如图集矩形、位置、尺寸、旋转、颜色、透明度和深度层。不要为每个字符创建独立
Bevy UI Text Entity。

## Bevy 原生 GPU 渲染

当前浏览器原型使用 WebGL2、GLSL 和实例化字形四边形。Bevy 版本使用原生
RenderApp 和 WGSL Shader 表达相同的绘制关系。

渲染职责保持清晰：

- 字形图集提供字符纹理。
- 背景图片提供人物目标采样与最终背景。
- 实例数据保存每个字符当前的空间状态和目标状态。
- WGSL 根据实例数据完成位置变换、旋转、颜色、透明度、模糊和纹理采样。
- 字形使用批量/实例化绘制，保留远近层次和前中后景关系。

场景通过 `Camera2d` 渲染到 `Splash::start` 返回的 Window
Entity。幕次标题和字幕属于 Splash 场景的 UI 内容，目标 Camera 指向
Splash
Camera；浏览器原型中的播放、拖动、全屏和幕次定位控件不进入正式启动窗口。

## 字符少女的最终构图

最终人物仍然完全由文字、代码和知识碎片组成。浅薄荷绿背景图只作为采样目标和最终共享背景，不作为独立彩色角色图层显示。

人物的识别依赖：

- 长发和丝带沿自身形态延展的字形方向。
- 面部、眼睛、头发和衣纹之间不同的明暗与密度。
- 字形大小、角度、层次和留白形成的结构。
- 远看可辨认整体人物，近看仍能看到具体知识碎片。

静态渲染阶段应能直接显示最终字符构图，便于检查人物比例、头发外轮廓、面部辨识度、伸出的手和服装层次。此时不需要加入四幕时间变化；时间线由下一方案接入。

## 完成条件

- Splash 场景不依赖 WebView、WebGL 浏览器 Canvas 或 MP4 播放。
- 背景图片由 Assets crate 提供，并同时用于字符目标采样和最终背景。
- 字形图集覆盖中文、代码、数字和常用数学符号。
- 字符实例通过批量 GPU 渲染，不创建海量独立 UI Text Entity。
- Shader 使用 Bevy 原生 WGSL 渲染路径。
- 静态人物构图能够辨认助手的头发、面部、手部、服装和丝带。
- 字符在人物内部具有方向、密度和明暗层次，不呈现为平均填充的字符剪影。
- Splash 场景和主窗口使用同一背景图片坐标映射。
- 资源初始化失败能被 Splash 生命周期捕获并进入主窗口回退路径。

验证以实际 Splash Window 的静态画面、截图和 BRP
资源检查完成；遵循项目现有约束，不新增 Unit Test、Integration
Test、Regression Test、Benchmark 或 Example 代码。
