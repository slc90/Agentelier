# 查看目录并设置下次启动位置

本增量把已经存在的数据环境呈现在设置页中，并让用户指定下一次启动使用的位置。目录切换只更新应用配置中的目录选择；正在运行的账号与凭据继续使用原目录，应用配置和日志保持在可执行文件旁。

```mermaid
flowchart LR
    Current["本次数据环境"] --> View["设置中的当前路径"]
    View --> Explorer["打开资源管理器"]
    Pick["更改目录：Widgetry 选择器"] --> Check["检查候选路径"]
    Check --> Save["保存应用配置中的目录选择"]
    Save --> Next["显示下次启动路径"]
    Next --> Restart["下一次启动读取新目录"]
```

前一增量提供目录选择、应用配置保存和本次数据环境。本增量复用这些能力，交付可用的目录设置。后续认证运行接收的是本次数据环境中的路径，不依赖设置页面的内部结构。

## 当前路径与下一次选择分开表达

“设置 → 数据与存储”始终显示当前使用的完整路径，提供“打开目录”和“更改目录”。当前路径来源于启动后保持不变的数据环境，不能为了显示刚选的新位置就修改它。

当应用配置中的目录选择与当前根目录不同，页面另外显示“下次启动使用”和新路径，并显示“更改将在下次启动生效；文件由你自行复制和整理”。两者相同时不显示重复的待生效信息。较长路径允许换行或复制完整文本，不能让省略号成为唯一可读取的路径内容。

页面没有默认目录、恢复默认、迁移、合并或清理文件操作。它只显示目录、打开目录和保存下一次选择。完整交互关系见 [数据目录与启动](../../docs/design/mechanisms/application-data.md)。

## 文件夹选择只提交一次结果

沿用用户在第 01 项确认的功能划分与控件选择：`crates/login_ui` 使用 BSN 组合 Widgetry `PickDirectory`；`crates/login` 提供不持有第二份长期占用的候选检查和当前目录打开能力；`app` 保留通用配置和日志。点击“更改目录”后在同一窗口显示选择区域，目录检查和保存通过共享 JobManager 承接，不进入 Agent 的认证执行体系。

同一页面只存在一个待完成的目录选择操作。选择期间不提供重复发起入口，后台操作期间禁用打开与更改按钮。关闭页面会取消尚未确认的选择；已经确认的 I/O 继续收尾，重开期间不接纳新操作，直至其真实终态。结束应用时等待相关工作实际结束。结果必须匹配发起时的操作标识，迟到结果不能替换更晚的选择。

取消选择是正常结果，保留当前路径与此前已经保存的下次启动位置。选中路径也不立即改变运行环境：检查通过、应用配置成功落盘之后，才更新“下次启动使用”。

候选检查复用前一增量的目录访问检查，不对候选目录执行账号登记初始化或凭据恢复，也不持有第二个数据环境的长期占用。真正进入新环境和取得独占占用发生在下一次启动。此刻可访问的目录若后来变得不可用，下一次启动按已有的重试、重新选择流程处理。

## 保存选择与手动整理的关系

目录选择保存在可执行文件旁的 `config/config.ron` 中，与缩放、BRP 等设置共用同一份配置，不另设启动定位文件。更新目录字段时保留其余配置，使用完整写入后替换的提交方式，保存接口向调用层返回真实结果。目录选择保存与其他设置保存使用同一提交入口，避免并发保存用旧快照覆盖彼此的字段。

例如，当前使用 `D:\AgentelierData`，用户选择 `E:\WorkData`，设置页同时显示两个位置。本次运行仍读写 D 盘目录。用户关闭应用后手动复制所需文件，再次启动时才读取 E 盘目录。

选择当前路径表示撤回待生效的更改；应用配置重新保存当前路径，待生效提示消失。保存失败则保持旧配置和旧的待生效显示，错误出现在本次操作区域，不能先显示成功再依靠日志解释失败。

不主动扫描或同步两个目录，不自动重启，不在候选目录写入 `auth.json`。原目录中的账号登记与当前凭据继续由当前运行环境使用；应用配置和日志仍位于可执行文件旁。

## 打开目录与 UI 装配

“打开目录”打开的是当前使用的位置，不是尚未启用的新位置。向资源管理器传递真实路径参数，不把用户路径拼接成未经转义的 Shell 命令。启动失败或目录已失效时，在页面显示可读错误。

设置页使用 BSN 声明布局和 Widgetry 按钮、文本；只为这一个设置区域组织 Scene，不引入通用设置框架。按钮激活沿公开的 `Activate` 契约处理，等待和禁用使用控件公开状态。Props 只负责初始化，当前路径、候选操作和错误属于运行时 ECS 状态。

辅助 I/O 可使用 `bevy_widgetry::job`，其完成结果与页面操作标识关联。项目依赖中按实际使用开启控件和任务 Feature，版本在 Workspace 统一管理，沿用锁定的 Bevy、Widgetry 与 BRP 兼容组合。Widgetry 自身的 `FileDialog` 是本增量实际复用的 Bevy 文件选择控件，选择、取消与恢复均通过 BRP 验证。

## 实施参照

应用落点是现有配置路径管理、主窗口内容 Scene 和应用辅助任务装配。沿用 `app/src/config.rs` 中已有配置职责，但目录选择保存必须使用能够返回失败的提交入口。

Widgetry 的 `docs/features/button.md`、`docs/features/job.md` 及相关公开导出用于确认激活、任务完成和关闭契约。参考库保持只读，不复制其控件内部状态或为本功能修改上游实现。

## 可观察的完成条件

| 操作或条件 | 应取得的结果 |
| --- | --- |
| 打开设置 | 当前路径与本次数据环境相同，长路径可完整读取 |
| 点击打开目录 | 资源管理器打开当前目录，当前应用状态不变 |
| 更改后取消 | 不写入新选择，原来的待生效选择也保持不变 |
| 选择新目录并成功保存 | 当前路径不变，显示新路径和下次启动提示 |
| 保存目录选择后检查文件归属 | 只更新可执行文件旁的 `config/config.ron` 中的目录字段，其余设置保留；日志仍写入可执行文件旁的 `logs/` |
| 再次选择当前目录 | 待生效更改被撤回，重启仍使用当前目录 |
| 目录不可写或应用配置不可写 | 页面显示失败，旧配置保留，没有成功提示 |
| 连续点击更改目录 | 只存在一个有效选择操作，没有多个结果相互覆盖 |
| 关闭后重新启动 | 使用已保存的新目录，原目录文件未被搬运或删除 |

通过 BRP 对实际主窗口执行设置入口、按钮激活、取消后的页面恢复和长路径显示检查，结合截图及必要 ECS 状态观察。文件夹选择使用 BRP 对真实 Widgetry 控件操作；资源管理器窗口通过实际 Windows 行为验证，BRP Custom Pointer 不代替该操作系统界面的输入。

验证后执行 Pointer `release`，确认状态恢复到 `inactive`，再正常关闭应用。当前尚未接入账号的阶段只验证目录与文件归属；带凭据的切换在对应账号和模型增量中继续验证。

同步数据目录设计中已经落地的设置、下次启动和手动整理行为，保持 `docs/` 导航有效。提交前清理本任务临时进度记录，提交信息只表达最终功能变化。
