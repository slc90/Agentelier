# 由用户指定并恢复应用数据目录

本增量让应用在创建账号数据之前取得用户明确指定的根目录，并在下次启动复用这个选择。交付结果是能够真实运行的启动流程：先在可执行文件旁建立日志并加载应用配置；配置中没有目录选择就进入 Windows 原生文件夹选择，选择完成后才启动主窗口并恢复账号。

```mermaid
flowchart LR
    Logs["建立可执行文件旁的 logs/ 输出"] --> Config["读取 config/config.ron"]
    Config --> Choice{"配置中的数据目录可用"}
    Choice -->|是| Context["建立本次数据环境"]
    Choice -->|否| Picker["原生文件夹选择与错误处理"]
    Picker --> Context
    Context --> Save["将确认的目录写入应用配置"]
    Save --> App["现有 Bevy 主窗口"]
```

## 应用配置与账号数据各存什么

在可执行文件旁的 `config/config.ron` 中增加用户确认的数据目录绝对路径字段，与界面缩放、BRP 等应用设置统一保存，不另设启动定位文件。字段初始为空；已有配置缺少该字段时视为尚未选择，保留其余设置。没有目录选择时打开选择器，不回退用户主目录、安装目录或当前工作目录作为业务数据根目录。

所选目录只使用 `auth.json` 保存账号登记与当前凭据（含登记所需主机标识），实际记录由后续认证增量建立。应用配置保留在可执行文件旁的 `config/config.ron`，运行日志保留在可执行文件旁的 `logs/`。以一个具体的数据环境对象持有根路径、凭据路径和本次占用，不建立按任意数据类别注册路径的通用框架；必要锁与临时文件只用于占用和提交，不承载额外业务数据。

本次根目录确认后保持固定。目录选择写入应用配置时保留其余设置，使用完整写入后替换的提交方式；保存失败就报告失败并保留选择流程，不能把只在内存中采用新路径显示成“已记住”。

## 在现有装配中确定账号数据目录

`app/src/main.rs` 已在可执行文件旁建立日志并加载 `config/config.ron`。这里保留配置与日志的位置和先后关系，在加载配置后、主窗口启动前确认账号数据目录。继续复用已有日志、窗口、Asset、UI 缩放及 BRP 装配，不建立第二套应用运行时。

首次目录选择在文件日志初始化和配置加载之后、Bevy 主事件循环之前完成，采用安全 Rust 封装提供的 Windows 原生文件夹选择器。选择器标题明确用途；浏览到某个文件夹不等于确认该文件夹。用户取消时正常结束启动并完成日志收尾。目录选择错误通过原生提示和已建立的日志反馈；日志尚未建立时继续使用已有应急诊断出口。

`app/src/config.rs` 的配置内容在缩放和 BRP 之外增加数据目录选择。配置缺失时，在可执行文件旁的 `config/config.ron` 建立初始配置；解析或访问失败时保留原文件并报告具体原因，不用默认配置覆盖原文件。目录选择的持久化需要能够返回真实失败，不能复用只记录警告却向界面假报成功的保存方式。

日志继续采用可执行文件旁的 `logs/`，由应用统一安装一次输出体系。日志和应用配置可在根目录确认之前建立；账号登记与凭据读写只能在根目录确认并取得占用之后进行。

## 目录可用性的判定

确认路径存在且确实是目录，支持包含中文和空格的 Windows 路径。检查读取、创建和更新账号凭据文件所需的权限；应用配置的写入结果单独检查，不能用数据目录可写代替配置可保存。探测产生的临时文件只清理由本次检查创建的那一份。

同一数据目录保持一个进程级独占占用，使用操作系统随句柄生命周期释放的文件锁，而不是只依赖一个写有 PID 的文本标志。被占用时显示原因并允许重试或重新选择。应用退出时，在日志和后台任务结束后释放占用。

已保存目录缺失或不可访问时，显示原路径和原因。重试再次检查原路径；重新选择由用户明确确认新路径；取消结束启动。不要自动重建失踪的原目录，以免把暂时未连接的磁盘解释成新的数据环境。

已有目录中的无关文件保持原样。不读取其他客户端的用户目录，不导入旧配置，不自动迁移现有可执行文件旁的数据。

## 可直接利用的现有能力

应用侧结合 `app/src/main.rs`、`app/src/config.rs` 和 `app/src/diagnostics.rs` 调整启动顺序。日志参考 `crates/app_logging/src/` 的 `AppLogging`、`LoggingGuard` 及公开装配契约，保留显式 `finish()`。

目录选择发生在主应用装配之前，因此使用现成原生对话框安全封装；不为了这一步复制完整 FileDialog 控件或新增另一套 GUI 框架。所有外部依赖在 Workspace 统一声明，只启用当前 Windows 路径需要的 Feature。沿用锁定文件中的 Bevy、Widgetry 和 BRP 组合，保持 Runtime 与 MCP 工具兼容；不为本功能顺带升级渲染或 UI 依赖。

## 完成时应观察到的行为

| 实际操作 | 预期结果 |
| --- | --- |
| 配置中没有目录选择时启动并取消选择 | 正常退出并刷新日志，没有偷偷创建默认账号数据目录 |
| 选择空目录 | 现有主窗口正常启动，所选目录不生成应用配置或日志；配置和日志仍在可执行文件旁 |
| 选择包含无关文件的目录 | 无关文件内容和名称保持原样 |
| 关闭后再次启动 | 自动使用已保存路径，不重复要求选择 |
| 选择中文、空格路径 | 文件访问和窗口启动正常 |
| 使应用配置不可写 | 明确提示目录选择保存失败，原配置不变，不显示持久化成功 |
| 已有配置缺少目录字段 | 保留缩放与 BRP 设置，要求选择目录，成功保存后其余设置不变 |
| 已有配置解析失败 | 保留原文件并报告错误，不用默认配置覆盖原文件 |
| 移走已保存目录后启动 | 显示路径不可用，允许重试或重新选择，不重建旧目录 |
| 两个实例使用同一目录 | 后一个实例被明确阻止写入，前一个实例继续正常运行 |

原生对话框通过真实 Windows 运行验证。主窗口启动、缩放和 BRP 等受影响的 Bevy 行为，通过 `bevy_brp_mcp` 进行针对性输入与状态检查；不以 Custom Pointer 操作替代原生文件夹选择。完成 BRP 操作后释放 Pointer，并确认其状态为 `inactive`。

## 工程收口

实施环境保持 Windows x64、MSVC、DX12 和 PowerShell 7。遵守 `rules/project-context.md` 的测试、Benchmark、Example 禁令，使用必要的 Cargo 编译、格式、Clippy 和真实运行检查，不编写测试程序。

实际修改前按 `rules/development.md` 创建任务进度记录，采用 Type-Driven Development 描述目录状态和保存结果。保持 Workspace 的 `unsafe_code = forbid`、错误传播和最小可见性要求，不为对话框或文件锁放宽 Lint。

同步 `docs/design/mechanisms/application-data.md` 中已经落地的启动与存放结构；更改设置行为由下一增量加入。修改启动职责时同步总体架构说明和文档导航。完成必要验证及 `rules/code-review.md` 规定的独立静态 Review 后，按 `rules/git.md` 整理英文语义提交；进度记录不进入最终提交。
