# 由用户指定并恢复应用数据目录

本增量建立可运行的目录启动流程：先在可执行文件旁建立日志、加载应用配置，再启动现有 Bevy 运行时显示目录界面；确认、检查并保存后进入主业务界面。根据实施期间用户确认的调整，目录选择复用 Widgetry `PickDirectory`，功能拆分为 `crates/login` 与 `crates/login_ui`。不再采用事件循环前的 Windows 原生文件夹选择器。

```mermaid
flowchart LR
    Logs["建立 logs/ 输出"] --> Config["读取 config/config.ron"]
    Config --> Runtime["装配现有 Bevy 运行时"]
    Runtime --> Choice{"已有目录选择"}
    Choice -->|是| Check["后台检查并占用目录"]
    Choice -->|否| Picker["Widgetry 文件夹选择"]
    Picker --> Check
    Check --> Save["新选择提交到应用配置"]
    Save --> Main["复用窗口进入主界面"]
```

## 功能 crate 与宿主职责

`crates/login`（`agentelier_login`）集中数据环境、目录权限检查和占用锁，不依赖 Bevy。以具体 `DataEnvironment` 持有绝对根路径、凭据路径和本次占用，不建立按任意数据类别注册路径的通用框架。

`crates/login_ui`（`agentelier_login_ui`）集中登录相关 Bevy 界面；本次只交付目录启动界面。通过 BSN 复用 Widgetry 的文件夹选择、文字和按钮，目录检查及保存通过共享 JobManager 执行，不在 ECS 主线程阻塞文件 I/O。后台结果主动唤醒 Winit，完成后以事件通知宿主进入主界面。

`app` 保留程序入口、通用应用配置与日志、窗口、Asset、缩放和 BRP 装配。通过线程安全的保存操作向 `login_ui` 提供配置提交，不让功能 crate 依赖 `app`。只装配一套应用运行时、日志 Subscriber 与 BRP Transport。后续账号认证和设置行为继续按增量交付，不预建空接口。

## 应用配置与账号数据

在可执行文件旁的 `config/config.ron` 增加可缺省的目录绝对路径字段，与缩放和 BRP 设置统一保存，不另设启动定位文件。字段初始为空；旧配置缺少字段时视为尚未选择，保留其余设置。没有选择时打开 Widgetry 选择器，不将用户主目录、安装目录或当前工作目录自动采用为业务根目录。

所选目录只以 `auth.json` 承载账号登记与当前凭据，含登记所需主机标识；实际账号记录由后续认证增量建立。本次不创建或解析凭据。必要锁与临时文件只用于占用、检查和提交，不承载额外业务数据。配置和日志始终留在可执行文件旁。

配置缺失时建立初始配置；解析、校验或访问失败时保留原文件并报告具体原因，不用默认值覆盖。GUI 尚未建立时保留原生应急提示及既有诊断出口。配置保存返回真实失败，完整写入同目录唯一临时文件、同步后替换；初次创建不得覆盖已有文件。保存失败保留原配置和选择流程，不把内存中采用新路径显示成“已记住”。

## 目录确认、检查和生命周期

启动选择界面明确用途，浏览位置不代表确认。用户明确提交后才能检查和记住路径；取消正常结束启动，并等待后台任务实际结束、刷新关闭日志。正常目录错误由 Widgetry 界面显示完整路径和原因，提供重试、重新选择、取消。

检查路径已存在且为目录，支持中文和空格。分别检查目录读取、已有凭据读取与写入，以及本次临时文件的新建、写入、替换和读回。配置提交结果单独检查，不能用数据目录可写代替配置可保存；只清理本次创建的探测文件。

同一数据目录保持进程级独占占用，使用随句柄生命周期释放的操作系统文件锁，不能只依赖 PID 标志。被占用时明确阻止后一个实例，并允许重试或重新选择。采用后的目录保持固定，应用入口持有占用直到后台任务和日志收尾结束。退出超时不代表任务已结束，须继续等待真实收尾。

已保存目录缺失或不可访问时显示原路径及原因。重试检查原路径；重新选择必须明确确认；取消结束启动。不自动重建失踪目录，不读取其他客户端的凭据、不导入旧配置、不自动迁移已有数据，目录中的无关文件保持原样。

## 完成时应观察到的行为

| 操作 | 预期结果 |
| --- | --- |
| 无目录选择时启动并取消 | 正常退出，后台任务及日志收尾，不创建默认账号目录 |
| 选择空目录 | 进入现有主界面；目录不生成配置、日志或 auth.json |
| 选择含无关文件的目录 | 文件名称和内容保持原样 |
| 关闭后再次启动 | 检查后复用已保存路径，不重复要求选择 |
| 选择中文、空格路径 | 文件访问和界面正常 |
| 配置不可写 | 显示保存失败，原配置不变，不能进入主界面或假报成功 |
| 旧配置缺少目录字段 | 保留缩放和 BRP 设置，成功后其余设置不变 |
| 已有配置解析失败 | 原文件不变，明确报告失败 |
| 移走已保存目录 | 失败界面可重试或重新选择，不重建旧目录 |
| 两实例使用同一目录 | 后一个被明确阻止，前一个继续正常运行 |

通过 `bevy_brp_mcp` 对真实 Widgetry 选择、确认、取消、失败恢复及主界面进行针对性输入、截图和状态验证。不得直接修改 ECS 状态冒充交互。完成后 release Pointer 并确认 phase 为 `inactive`。GUI 装配前的应急原生提示使用真实 Windows 行为验证。

## 工程收口

环境保持 Windows x64、MSVC、DX12 和 PowerShell 7，禁止编写测试、Benchmark、Example。遵守 Workspace `unsafe_code = forbid`、错误传播、最小可见性、统一依赖和 Type-Driven Development 规则，不升级锁定的 Bevy、Widgetry 或 BRP 版本。

修改前维护根目录临时任务进度。同步当前总体架构、数据目录机制、功能契约和文档导航，区分未实现认证和设置。完成适用 Cargo 与真实运行验证及独立静态 Review 后整理英文语义提交，进度记录不进入最终提交。
