# 按来源取消任务并等到真实收尾

本增量让指定任务取消、Stop 当前 Turn、停止全部后台工作和应用关闭各有明确范围，并把取消请求、真实终态与资源回收分开表达。交付物是同步 `cancel_async_tasks`、会话串行裁决的取消路径、未知外部效果的继续确认，以及替换/身份切换/关闭所需的控制边界。

顺序承接 [08 · 查询和等待](08-task-query-and-wait.md)，随后进入 [10 · 进程生命周期](10-process-lifecycle.md)。取消沿用前一增量的稳定 ID、冻结可引用集合与独立控制调度；下一增量使函数返回后的进程资源具备完整的独立控制和退出结果消费。此处先把所有当前持有的真实资源纳入收尾，进程跨 Turn 及尾部登记随后接入相同控制范围。正常 final 暂仍按 07 的过渡行为等待收束，13 才释放前台/后台绑定。

## 取消请求不等于完成，更不等于副作用撤销

执行状态与交付状态分别表达，避免一个“成功”承担过多含义。

| 维度 | 状态与含义 |
| --- | --- |
| 执行 | 已登记、等待准入、运行、取消中、成功、失败、超时、已取消、未执行、结果未确认 |
| 资源 | 无活资源、仍持资源、正在回收、回收未确认 |
| 保存 | 结果尚未形成、已形成待保存、已持久提交、保存失败或未确认 |
| 协议 | 尚无对应 output、已唯一追加到历史 |
| 请求事实 | 尚未纳入请求、已纳入某冻结请求、已开始发送、该请求完整成功或结果未知 |

例如“执行成功，保存失败”意味着工作可能已经修改文件，但结果还不能交给模型。又如“结果已追加，尚未发请求”意味着输出已经可靠留在历史中，空闲界面仍应显示待处理。

这里的“已用于成功请求”仅表示包含该结果的请求得到了完整合法响应。它不把网络接纳推断成模型理解，也不宣称网络恰好交付一次。无状态重放本来就会再次携带以前的结果；必须禁止的是再次追加同一结果、再次启动同一调用或再次发送有副作用的进程输入。

## 自然完成与取消由同一所有者裁决

用户取消与任务自然完成可能同时到达。会话所有者串行裁决：已有持久完成结果时，取消为“已结束”；尚未开始时，记录未执行；正在运行时进入取消中，由执行器回报实际结果与回收情况。一次调用只形成一个协议结果。

已经产生的文件修改、已经写入的 stdin 和远端副作用继续如实记录。完成事实先到达并被确认时，不能用迟到的取消把成功改成取消；取消已经形成终态之后，迟到的进度/回报只用于核对同一执行实例与清理，不生成第二份结果。相互矛盾的终态阻断执行并保留诊断。

取消尚在准入或资源等待中的任务时，保存明确的未执行结果；即使随后释放许可，也不能再启动它。运行中的任务先进入取消中，重复请求幂等或明确回报已请求；不丢弃句柄以抢先显示终态，不因前台结束停止接收执行器的实际结果。

## 远端未确认需要独立的继续确认

MCP 的取消通知送达不等于远端工作已停止。超时、断连或无法确认取消时，记录本地等待结束和远端效果未确认，不自动重试。未知副作用的许可不能因本地 future 消失而假装安全释放：暂停冲突工具派发与自动 Queue，并显示需核查的来源。用户核查后通过明确的“确认继续执行”动作，持久记录所确认的任务与范围，才解除相应派发阻塞；普通发言或 Queue 恢复不替代这项确认。原始“远端未确认”记录仍保留，不能改写为已证实停止。

这项确认只解除已经没有本地执行句柄、但外部效果未知的派发门槛。当前仍持有的待回收进程必须继续实际收尾；身份冲突、存储未确认也不能用它绕过。重启后没有可恢复句柄的历史未知记录是终止证据，不永久占用运行槽或阻止只读打开、切换和正常关闭；它对新副作用的暂停要求仍保留到明确确认。

普通工具失败只结束该任务，其他独立任务仍可完成并保存；只有持久化、身份冲突、资源回收未确认等破坏继续执行前提的问题，才阻断相关派发或整个会话的模型续接。超时沿用执行器实际契约，例如当前 MCP 调用的 60 秒超时；不为所有工具强加一个虚假的统一时限。无命令寿命上限的进程依靠明确终止和退出收尾管理。

“确认继续执行”在本增量形成带任务/范围的业务动作、持久事实与真实回执，12 再接入对应 GUI。它不能与停止全部后的普通恢复混用：前者解除经过明确核查的未知副作用门槛，后者只解除用户暂停的新派发。原始未知终态不会因继续而变成成功或已证实停止。

## 模型取消、等待和列表共享身份，不共享结果

原工具的参数 schema 保持不变。应用接纳调用后分配任务 ID，通过三个自定义同步管理工具暴露控制能力。这些工具进入同一个 Direct 工具目录，使用同样的调用记录与结果保存路径。

| 工具 | 本次契约 |
| --- | --- |
| `list_async_tasks` | 查询本会话任务，返回任务 ID、原始 Turn、工具来源、安全参数摘要、执行/保存/交付状态和资源阻塞原因；不把真实工具结果复制成另一份输出 |
| `wait_for_tasks` | 接受非空、去重的已知任务 ID，`mode` 为 `any` 或 `all`，等待上限 30 秒；返回状态快照，超时只结束此次等待 |
| `cancel_async_tasks` | 接受明确 ID 集或明确的全部后台范围，回报取消请求与可确认状态；不把“已请求取消”伪装成资源已经停止 |

列表默认优先显示全部未完成交付项目，同时显示仍持有活进程或未消费退出结果的来源调用，即使原函数结果早已用于成功请求。此类行包含 `session_id`、来源任务/Turn、进程状态及许可阻塞，使模型在历史压缩后仍能发现需要控制的进程。已处理历史通过明确 ID 或有界分页查询。单页至多 64 项，超过时给出可继续查询的游标/剩余状态，不悄悄丢项；结果仍受 64 KiB 文本限制。参数摘要遵守现有脱敏和输出边界，不暴露凭据、推理密文或完整危险大载荷。

`wait_for_tasks` 的 `all` 是所有指定任务都达到可报告终态，`any` 是至少一项；失败、取消、超时和未执行都属于终态。执行器已结束但结果尚未持久提交时，任务仍不可报告为结果可用。相关新结果必须能通过唯一出口排在 wait 自身状态之前；保存失败使等待明确失败并阻断后续采样，而不是返回“完成”。

已终止任务立即返回状态，已进入历史的结果不再追加。空集、重复 ID、未知 ID、其他会话 ID 都直接产生控制工具错误，不等待未来某个同名任务。等待订阅先建立、再检查账本；收到唤醒后重新检查条件，不能用一次通知代替条件本身。

查询与等待已由 08 建立，本增量增加第三项并保持它们的状态边界。模型取消接受明确任务 ID 集或明确全部后台范围；空集、重复、未知和其他会话身份不被猜测修正。管理工具保持同步、原工具参数 schema 不变，结果通过各自原始调用提交；取消回报不能代替被取消任务的唯一真实终态。

### 同批登记不扩大模型已经知道的范围

同批调用先登记全部异步 launch，再执行管理工具。因此 `launch + list` 能看到本批任务。但应用分配的 ID 在模型生成这批输出时尚不可知：点名等待新任务需要先拿到列表，再发后续 wait。`launch + wait(猜测 ID)` 必须报未知 ID，不能自动匹配“最新任务”。

模型发出的显式 wait/cancel 以本次请求冻结时已存在的可引用任务集合校验，不能只查同批登记后的实时账本。即使猜测碰巧命中新分配 ID，也不得在这批中控制它；`list` 的结果在后续请求中才使新 ID 可用。模型的“全部后台”范围也按该冻结集合解释，UI 的全部停止则按用户动作被接纳时的真实会话范围解释。

普通调用等待独占许可时，不妨碍同批管理操作运行。尤其不能先同步 await 一个被旧进程阻塞的普通调用，再迟迟不处理能够终止该进程的控制操作；批次登记完成后，执行和管理各自推进，结果仍由统一历史出口收束。

等待期间继续处理 Stop 和 Steer。Stop 结束等待；Steer 接纳后结束旧等待，保存真实的等待状态/被补充中断事实，并在下一边界应用用户补充。两者都不借由“结束 wait”取消所有被等待的后台任务。

即使模型的取消请求排在普通同步工具之后，也不能先 await 被独占许可卡住的普通工作再处理取消。列表、等待和取消都计入当前 Turn 的工具调用预算，并受各自有界结果约束；管理路径本身不占普通工作槽。

## 取消仍遵守原资源许可

参考 Codex 对可并行和独占工具的区分，本次采用会话范围的共享只读与独占副作用许可。工具注册者声明可解释的并发策略；模型提供的参数、工具文字说明或 MCP 的只读提示，不直接提升权限。

| 类型 | 调度规则 |
| --- | --- |
| 经应用确认的独立只读操作 | 共享许可，可以和其他共享操作并行 |
| 任意 shell、文件修改、未知 Extension/MCP 副作用 | 独占许可，同一会话中的这类操作按接纳顺序执行 |
| 某个既有进程的输入输出 | 使用该进程自己的串行控制入口，可以控制其已经持有的许可 |
| 任务列表、等待、取消和 UI 控制 | 不占普通工作槽、不取得被等待工作的资源许可 |

这是一种保守的准入策略。它能避免应用自行制造的已知交错修改；任务可以同时登记，只有取得许可的任务真实执行。它不分析 PowerShell 文本来猜测任意文件访问，也不新增通用资源调度平台。

等待准入的任务可以取消。准入应维持先到顺序，避免后来的只读流量长期绕过已排队的独占工作。许可与工作槽应一并取得或在未能同时取得时释放，不能让一批等待资源的任务先占满所有工作槽。开始执行前再核对取消和会话执行状态。

执行器的终态载荷通过真实任务句柄归还，由 Runtime 收集并归并；它不依赖可以合并或丢弃的 UI 进度通知，也不因前台取消而停止投递。唤醒丢失时可从已完成句柄和账本重新检查，不能把唯一一份工具结果放在一个随旧 Turn 关闭的通知通道里。线程或 future 异常退出也必须转成有来源的未知/失败事实，并触发必要的资源回收。

任意 shell 创建的进程可能在函数返回后继续修改文件，因此它的副作用许可转交给进程所有者，直到进程真实结束并完成回收。工具调用的工作槽可以先释放。长驻进程因此可能让冲突工具等待，界面应显示阻塞来源，用户可以终止它；不能为了让计数好看而提前释放许可。

这里不把“本地等待结束”作为普通工作槽、资源许可、进程登记同时释放的单一信号。真实执行已结束但外部效果未知时，保存终止事实并按上文暂停冲突派发；仍有本次真实活句柄时，继续回收，不允许用确认按钮绕开。

## Stop 与新输入落在同一个会话边界

最终产品仍是一个活动 Turn，加上不占前台槽的后台工作。以下接纳规则已经由会话所有者保证；13 开放跨 Turn 前，本阶段保持等待收束的前台释放条件。

用户发送时若已有活动 Turn，继续走现有 Steer；显式排队继续走 Queue。没有活动 Turn 时才启动新 Turn。后台工具的存在不占用这个前台槽。

“关闭当前输入接纳”和“确认最终是否还有已接纳 Steer”必须在同一业务边界裁决。恰好撞上 final 的输入，要么明确属于当前 Turn 并在下一请求应用，要么得到已经结束的回执后保持草稿或由明确的新请求接纳；不能显示 Accepted 后静默丢弃，也不能既补充又新建一次。

参考 Codex 的 `start_or_steer`、输入队列与结束临界区，保留应用当前的 Accepted、Applied、NotApplied 差别。新输入不要求抢占或改写已经发出的 HTTP 请求，也不要求本次引入 WebSocket steering。

Stop、等待、工具结果和前台 final 都经过相同的会话控制边界。停止全部后台工作同时暂停新的副作用派发；正在返回的模型响应若又请求启动工作，应形成明确的未执行结果。只有用户明确恢复/开始新工作后才能解除这个派发暂停，避免“刚停止全部，模型又自动启动一批”。正在进行的前台文字回复可以收束。

停止全部时，模型正在返回的响应仍需经过完整校验和持久接纳，但其中新工作只能形成明确未执行结果，不能绕过派发暂停。前台文字可以说明结果；只有明确恢复或开始新工作才能解除这项暂停。未知外部副作用、身份冲突、存储未确认等其他阻断条件仍按各自规则存在。

## 不同结束动作保留不同范围

| 动作 | 前台 | 后台与资源 | 后续模型请求 |
| --- | --- | --- | --- |
| 正常 final | 关闭接纳并真实回收前台 | 已接纳任务继续；进程继续 | Queue 按原规则；空闲结果只提示 |
| Stop 当前 Turn | 停请求、等待和本 Turn 派发 | 取消本 Turn 创建的工作；旧来源工作保留 | Queue 暂停，不自动因结果完成重启 |
| 取消某项 | 当前等待可被唤醒 | 只处理指定任务；回报精确范围 | 后续在合法边界交付其终态 |
| 停止全部后台工作 | 不伪装为一个普通工具结果 | 停止全部后台调用与存活进程，等待回收 | 暂停自动 Queue；前台可继续说明状态 |
| 切换、Reset、删除 | 由替换操作统一核查 | 有活动工作、未保存结果、未确认清理时拒绝 | 不隐式停止或迁移后台工作 |
| 用户主动登出/切号 | 停前台并暂停接纳 | 取消并回收当前会话工作，保存原来源结果 | 新身份下只由用户明确发起续接 |
| 正常关闭应用 | 关闭新接纳与派发 | 停工具、进程和等待，保存终态并 join | 排空 Store，再关闭 Account、Tokio 和宿主 |

账号动作延续已有身份隔离；开发验收不得为了覆盖该行擅自退出登录或重置凭据。正常关闭失败应显示真实的回收/保存错误；强制结束后按恢复规则处理，不假称上次已经完成清理。

表中的正常 final 跨 Turn 行为到 13 才启用；此处的 Stop、取消、关闭和替换裁决从一开始保留原创建 Turn 身份，不依赖当前 UI 行、当前 request_index 或正在展示的 operation。

切换、Reset、删除先核查活动执行、本次待回收句柄、未保存结果与已开始的存储提交。任一存在就拒绝并说明来源，不隐式取消或迁移；仅有已保存待处理结果、没有活句柄的退出摘要或重启后的历史未知记录时，允许正常替换。未知外部效果的新派发门槛继续保存在原会话中，不能通过切走再打开清除。

正常关闭必须先停止新接纳和派发，终止等待并取消任务/进程，等实际执行与资源回收形成终态，保存这些事实并排空 Store，再完成账号必要提交、运行时线程 join 和宿主释放。提交未确认或回收失败要保留真实错误；强制结束后走恢复语义，不能宣称上次已经清理成功。账号身份切换使用相同来源隔离，不能把旧执行实例或旧凭据移交新身份。

| `agentelier_conversation` | 按原创建来源裁决取消、Stop/全部范围、终态竞争、替换门槛和持久继续确认；保存业务事实，不操作 OS 资源。 |

| `agentelier_session_store` | 单写入保存取消范围、实际终态、清理事实及明确继续确认；未知提交不能被按钮绕过。 |
| Conversation Bridge、Connection、Agent Host 与既有账号所有者 | 安全控制回执、正常关闭的实际完成与身份隔离；12 才接入新增任务操作控件。 |

实际行为落地后同步 [总体架构](../../docs/design/architecture.md)、[会话](../../docs/design/modules/conversation.md)、[会话存储](../../docs/design/modules/session-store.md)与 [Direct 工具调用](../../docs/design/tool_call.md)中的控制范围、取消/回收和关闭事实；账号协调路径确有改变时同步 [身份认证](../../docs/design/modules/authentication.md)。不把尚未落地的进程尾部、记忆或跨 Turn UI 写成当前事实，不新增逐功能目录。

不新增 Agent 总包、不把业务移到 `app/`，不修改 Bevy、Widgetry、BRP 上游。根 Workspace、当前锁定依赖及 Windows x64、DX12、PowerShell 7 约束不变。错误日志保留必要身份与提交关联，不公开认证、隐藏推理或压缩内容；正常等待与取消不被当成异常 WARN。

## 本增量如何取得证据

运行验收使用 Windows x64、DX12、PowerShell 7、当前锁定依赖和真实应用。涉及服务时使用现有 Sign in with ChatGPT 与 `gpt-6.2-sol`，不自动换模型或登录路径，不为凑边界次数重复调用服务。编译、格式和静态检查只覆盖本增量实际改动及直接影响；构建成功不能代替运行证据。

在现有数据环境中正常创建专用验收会话，可写命令限定于明确的验收工作目录，保留原有会话、文件和登录。恢复或损坏记录场景先备份该验收会话及附件，只处理已备份副本并记录实际读取位置。退出、切号、重新授权、凭据重置或以切换数据目录间接使登录失效，仍须已有明确授权；清单不提供这项授权。正常关闭后在同一环境重开与退出账号不同。

不编写或引入测试、Benchmark、Example、mock 服务、专用 harness 或仅为验收服务的依赖。可以直接运行应用、检查正常诊断状态，或在调试器中控制真实应用的完成、回执和事件处理边界。难以触发且没有观察入口的条件标为未覆盖。

| 标记 | 证据及其边界 |
| --- | --- |
| 静 | 实际源码、依赖方向、序列化与错误路径审阅，只证明规则被表达，不能替代交错运行或 GUI/服务结果。 |
| 调 | 调试器控制真实应用边界或查看正常诊断状态。人工响应、事件必须标明注入位置，不称为服务实际返回。 |
| 运 | 真实应用与正常工具、存储记录、进程事实、关联日志；GUI 行为还需要 BRP 的真实输入、截图或安全 ECS 查询。 |
| 服 | 真实 Responses 请求/响应的安全记录及原调用关联；需要验证结果使用时，由模型准确复述工具独有随机标记。HTTP 200 本身不足以证明非阻塞或生命周期正确。 |

每条记录场景 ID、实际前提、操作、预期事件顺序、观察结果、证据位置、通过状态及清理结果，以会话、来源 Turn、请求、任务、原 `call_id` 和提交序号关联。日志只留必要安全字段，不导出凭据、隐藏 reasoning/compaction 或敏感完整正文。未执行、故障前提未达到、证据不足均不标通过；后续修改只复核直接受影响的证据。

涉及新增按钮或可观察 GUI 行为的完整验收，使用实际安装的 `bevy_brp_mcp` 发现应用与方法，优先按稳定 `Name` 找控件。Pointer、Keyboard、Focus、Scroll 走真实输入，不直接改 ECS 后声称交互通过；分别核对工具接纳、输入执行完成和目标行为。检查有意义的中间帧及最终收敛。结束后通过已发现的 `brp_extras/pointer_control` 执行 `release`，查询 `status` 至 `phase=inactive` 并检查 `last_error`；`busy=false` 不能单独证明成功。BRP 无等价能力的 OS 行为另以真实环境证据说明。

### 控制事实先可验，跨 Turn 与按钮随后复核

K-01—K-03 当前通过真实任务和调试边界覆盖取消/完成竞争；K-05 当前验证全部停止、迟到响应与明确恢复的业务范围，实际任务按钮在 12 补 BRP。K-04 当前先核查原创建 Turn 集合与等待中断的裁决，13 再用两个真实 Turn 的任务/进程完成整条；不能把人工来源记录当作跨 Turn 已运行。

K-06—K-07 使用实际可用执行器验证其真实契约，不可达 MCP 故障标为未覆盖。继续确认的持久范围可在本阶段业务边界验证，12 补“确认继续执行”的真实按钮；10 接入函数返回后独立进程的控制，再复核本阶段相应回收范围。K-08 当前验证替换门槛及已保存记录恢复，新增界面提示和草稿/阅读保持由 12 覆盖。K-09 对本阶段实际拥有的任务、等待和资源执行正常关闭；10 引入进程终态/尾部登记后复核直接受影响的退出部分，13 再覆盖旧 Turn 资源。

K-10 不提供退出/切号权限。只有已获明确授权且用户主动执行该动作时补运证据；否则完成静态隔离审阅并把运行条件标为未执行。关闭后在同一数据环境重开不要求破坏登录。任何仍未取得真实操作证据的条件保留为待复核，不由控制回执或按钮变灰替代资源事实。

| ID | 前提与动作 | 明确通过标准与证据 |
| --- | --- | --- |
| K-01 | 对已登记但尚在准入/资源等待中的任务取消，并在许可释放前后观察。 | 任务形成明确未执行结果，始终没有执行开始后的副作用；许可释放后它也不重新启动。证据：运＋调，取消、开始记录与实际产物。 |
| K-02 | 对正在运行的任务发起取消，并重复同一控制；执行器延迟确认退出。 | 先显示取消中，重复请求幂等或明确已请求；直到实际退出/回收才释放资源并显示终态。只有一个协议结果，取消不撤销已发生副作用。证据：运＋调。 |
| K-03 | 分别安排完成确认先于取消、取消终态先于迟到进度，以及互相矛盾的终态。 | 前者回报已结束，不把成功改取消；迟到进度不复活任务；矛盾终态阻断执行并保留诊断，不凭到达较晚覆盖。证据：调＋运，单一裁决序列。 |
| K-04 | 旧 Turn A 的任务/进程仍存在，当前 Turn B 启动新工作和等待，然后 Stop B。 | B 的模型、等待、派发及 B 创建的未结束工作被停止；A 保留。Queue 暂停，后台完成不自动重启前台；已完成和未确认事实各自真实。证据：运＋调，来源与实际取消集合。 |
| K-05 | 执行停止全部后台工作时仍有前台响应在返回，其中请求启动更多工具；之后明确恢复/开始新工作。 | 全部后台调用与存活进程按范围停止并回收；新派发和自动 Queue 暂停，迟到响应的新工作形成未执行结果。前台可说明状态；只有明确恢复/新工作才解除暂停。证据：运＋调。 |
| K-06 | 观察不同执行器的正常超时/取消能力，包含没有命令寿命上限的进程和暂时不能立即退出的工作。 | 沿用执行器真实契约，不强加统一超时；超时与实际停止/清理状态分别表达，控制仍可接纳，不能丢掉未退出句柄以伪装已完成。证据：静＋运＋调。 |
| K-07 | 对实际 MCP 调用分别观察断连、现有 60 秒超时和取消送达但远端结束未确认；核查后点击“确认继续执行”。 | 未知效果暂停冲突派发/自动 Queue，不重试；确认的任务/范围持久保存后才解除对应门槛，普通发言/恢复 Queue 不能替代。旧未知记录保留；当前活句柄、身份冲突、存储未确认不能借此绕过。证据：运＋调；不可达条件标未覆盖。 |
| K-08 | 分别在活动工作、本次活句柄待回收、未保存结果、在途存储提交、仅有已保存待处理结果时尝试切换、Reset、删除。 | 前四类拒绝且说明具体阻塞，不隐式取消/搬迁；最后一类允许正常替换。没有活句柄的已存退出摘要/历史未知也不永久阻塞替换；重开记录仍在，未知副作用派发门槛保持。证据：运＋调。 |
| K-09 | 在有运行任务、等待、进程和待保存结果时正常关闭，再观察各所有者的退出。 | 停止新接纳/派发，取消并真实回收，保存终态、排空 Store、完成账号必要提交和线程 join 后才释放宿主资源；失败有真实错误，不能提前标清理成功。证据：运＋调，关闭日志和进程/线程事实。 |
| K-10 | 仅在已有明确授权、用户主动执行登出/切号时观察含后台任务的身份切换；否则仅做静态审阅并标未执行。 | 旧身份前台和后台停止接纳、取消回收并保存原来源结果；新身份不接收旧凭据/旧执行实例，续接仅由用户明确发起。不得为该项重置凭据或改变数据目录。证据：静；获授权后补运。 |

本增量完成时，每个控制动作都能说明它接纳了什么范围、哪些工作确实结束、哪些效果仍未知，以及哪些资源仍在回收。Stop 和全部停止不会误取消更早来源或被迟到响应重新开启；正常关闭只在真实回收和保存完成后释放宿主。跨 Turn 和新增界面的完整行为继续由后续增量按原场景 ID 复核。
