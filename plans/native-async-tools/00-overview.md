# 原生异步工具的实施顺序

目标是在同一会话中保持一个活动前台 Turn，同时让已经启动的工具跨过 Turn 继续工作。用户可以继续聊天、启动其他工具、查看和取消旧任务；每项结果仍通过原始调用身份进入正确历史。整体行为依据 [目标设计](../../docs/design/native-async-tools/README.md)，这里按可独立交付的能力组织实施。

## 会话保存事实，前台使用快照

Conversation 是永久的业务权威，持有历史、任务账本、输入接纳与来源关系；Runtime 在串行会话边界应用事实、协调持久回执并持有真实执行句柄。Runner 只驱动当前 Turn，向权威申请请求快照、报告新事实，不能把一整份旧 Session 带回后覆盖最新结果。

Tools 执行冻结了来源的调用，并管理进程及资源控制；Session Store 确认响应/登记、开始、结果、历史追加和清理。LLM Model 保留原生协议与原始输出。Bridge/Host/Connection 将安全状态和唤醒交给 UI，Memory 从最终来源证据提取。没有新增第二套任务数据库、全局 Agent 总包或 Widgetry 后台执行权威。

响应只有完整通过校验并持久接纳后才派发工具。结果实际取得、保存、追加历史、纳入请求、发送和被完整成功响应确认是不同边界。原始 `call_id` 与一次执行/一次 output 的约束贯穿所有步骤；请求重放不被解释成可以再次执行副作用。

## 为什么先建立边界，最后释放前台

原生 async 声明只解决服务允许调用暂时缺少结果，不能替应用持有进程、保存晚到结果或安排新 Turn。先把协议模式、唯一历史与数据恢复落实，独立执行才能有可靠的落点。执行上下文和容量/压缩边界建立后，再开放同 Turn 非阻塞；查询、等待、取消、进程和界面让后台工作可观察、可控制。记忆来源在跨 Turn 放行之前改为等待实际证据闭合。

中间增量可以继续等待背景工作收束后才释放前台槽，以便保留可验证的产品边界。最后一个增量真正移除 normal final 与后台生命周期的绑定，同时完成跨 Turn 续接场景；它有独立的功能产出，不是单设一个最终测试阶段。临时保守行为完成使命后收敛，不形成多套长期用户模式。

初次接入限定 Direct Mode、现有 Sign in with ChatGPT 和 `gpt-6.2-sol`。新原生会话把冻结工具目录作为每个请求的 `additional_tools` 首项。旧平铺同步会话保留保存的契约。工具模式、来源授权和 schema 在会话与调用边界固定。

整个序列维持同一产品行为：空闲结果只保存并提示，由用户发言或明确结果动作续接；Stop 当前 Turn 只停止其创建范围，旧任务仍可单独管理；恢复只还原数据；pending 调用保护原始关联并预留闭合容量。每个实施文档重复其需要的完整约束与验收前提，能够单独阅读，不依赖跳转才能知道一个边界怎样算完成。

## 验收随功能进入

设计的 [完整验收清单](../../docs/design/native-async-tools/06-validation.md) 包含 13 组、114 项。每组完整放入负责该能力的实施文档；后面功能才具备的前提标明待联动，在最后的真实功能增量补齐。没有运行、没有达到故障条件或只有较弱证据的条目，不标通过。

按 [项目约束](../../rules/project-context.md) 使用 Windows x64、DX12、PowerShell 7 与锁定依赖；不新增测试代码、Benchmark、Example、mock 服务、harness 或测试依赖。真实运行、调试器控制、静态检查和服务证据各自说明范围，GUI 必须使用 BRP 真实交互并核对清理。以专用验收会话保护现有用户资料，账号/凭据/数据目录等另有授权要求的动作不会因写进清单就自动获得授权。

每个增量记录实际变化、相关检查、验收证据和未完成条件，并在当前行为确实改变时同步已有模块/机制设计。只有文档完成时不宣称功能或验收通过；所有实现和验证都应遵守现有 [开发流程](../../rules/development.md)、[修改范围](../../rules/task-scope.md) 与适用专项规则。
