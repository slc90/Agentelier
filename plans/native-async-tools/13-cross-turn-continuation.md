# 结束前台后，让后台工作继续

前面的增量已经建立原生协议、会话权威、开放历史、恢复、独立执行、压缩保护、控制工具、进程、记忆和界面。本增量移除正常 Turn 结束与后台生命周期的最后一层绑定：工作 A 尚未完成时，用户可以开始下一 Turn，并让模型再启动工作 B。

这一步交付真实的跨 Turn 行为和显式结果续接，不是一个只收集检查结果的阶段。实现之后始终保留一个活动前台 Turn；多项后台任务共享会话账本，按各自来源执行和交付。此前为保守交付保留的“后台收束后才释放前台”逻辑在这里收敛，不形成多套长期产品模式。

依据：[目标总览](../../docs/design/native-async-tools/README.md)、[历史与交付](../../docs/design/native-async-tools/02-history-and-delivery.md)、[交互边界](../../docs/design/native-async-tools/05-interaction-and-integration.md)。前置为 [12 任务界面](12-task-interface.md)，并建立在此前全部增量已明确交付的能力上。

## 释放前台槽，不销毁会话工作

只有取得合法完整 final、同步依赖已收束且没有待应用的已接纳 Steer，才进入正常结束；未完成的异步调用不再构成这个屏障。正常 final 先在同一业务边界关闭当前 Turn 的输入接纳、裁决已经接纳的 Steer，持久确认前台终态并确认前台真实回收；之后才释放唯一前台槽。终态只是排队写入、提交失败或回执未知时，不能启动 Queue 或新 Turn；保持明确的阻塞状态、保留输入与所得结果，并继续必要资源回收。已接纳的异步调用和进程继续由会话运行资源持有，不能触发逐 Turn 统一 cleanup、取消其句柄或关闭唯一结果通道。

恰好到达 final 的用户输入，要么明确属于当前 Turn 并在下一请求应用，要么收到已结束/未应用的明确回执并保留草稿或按新的明确动作接纳。不能显示 Accepted 后丢弃，也不能一次输入同时成为 Steer 和新 Turn。

前台不存在时，普通发送可立即创建新 Turn；前台存在时继续 Steer，显式 Queue 继续按顺序等待。后台任务数量不占用前台槽，也不允许绕过它启动两个前台模型循环。新的 Turn 可以发起更多异步工具，但仍受固定调用上下文、会话资源许可和全部预算约束。

例如 Turn 1 启动 A 后 final，Turn 2 启动 B；B 先完成，A 后完成。两项始终保留原始 Turn、工具上下文、任务 ID、原始 `call_id` 和执行实例。后来的用户陈述、模型状态或草稿不能修改 A 的授权，也不能把 A 的输出归到 B。

## 晚到结果只经过唯一历史出口

工具终态由真实执行句柄可靠归还，Runtime 收集并保存，再由会话权威追加唯一 output。前台 operation 已切换不是拒收旧任务事实的理由；失去一次 UI 唤醒也不能丢掉唯一结果。普通工具失败只终结自己，其他独立工作继续保存。

每次请求冻结合法历史、相关结果集合、可引用控制任务集合和身份。请求 R 进行中 A 完成时，先保存 A 的终态事实；R 的完整响应通过验证后先接纳，再在合法边界追加 A 的结果。R 失败、取消或响应非法时，保留之前合法前缀，随后仍允许归并 A，不能因为不存在成功响应而永久卡住交付。

追加按已确认事实的稳定顺序进行，并先提交附件。每个调用只形成一个 output，多个请求完整重放同一历史不等于重复执行工具。请求发送不等于服务完成；只有合法完整成功响应，才结算其冻结集合包含的结果，且先结算旧交付，再准入响应中新调用。发送未知、无效或不完整响应不释放交付名额。

Runner 不再用返回的一整份 Session 替换会话最新状态，旧前台终态、请求快照或 checkpoint 都不能覆盖后来结果。正常 final 边界刚到达的结果可以留待下一次明确续接，不为追上它而额外自动发一次请求。

## 空闲完成后，由用户决定何时续接

前台空闲时，任务完成只保存、更新任务区并提示待处理。用户继续发言或点击“处理已完成结果”才启动聊天续接。该按钮产生独立的续接触发身份，选择已持久保存且尚未纳入完整成功请求的就绪结果，不构造虚假的用户消息，不授予新的工具或记忆权限；没有待处理结果就不发请求。

普通发送与结果按钮由相同接纳边界仲裁，只有一个取得前台槽；另一个动作得到明确回执，未接纳草稿保留。新请求纳入适合其边界的就绪结果，已经追加的 output 不再追加，已经执行的任务不重跑。

计数时区分请求来源。用户已经明确提交的 Queue 仍可按现有规则启动下一 Turn，既有记忆后台请求也保留；它们不能被错误记为后台完成通知启动聊天，也不能用混合总数掩盖新增自动续接。模型身份继续由前台 `ExecutionIdentity` 管理，工具完成不能自行续签另一身份或触发模型调用。

## 停止、替换与恢复使用不同边界

Stop 当前 Turn 停止本 Turn 的模型请求、等待和派发，并取消它创建的未结束工作及进程；旧来源工作保留。对旧进程的 poll/write 被当前 Stop 中断时，保留已经写入的事实并结束本次操作，不默认杀死旧进程。Queue 暂停，旧任务完成不会自动把它重新启动。

单任务取消按明确 ID 处理。停止全部后台工作按用户动作接纳时的会话范围停止调用与进程，同时暂停新副作用派发和自动 Queue；在途模型响应新产生的调用得到未执行结果。明确恢复/开始新工作才能解除这种暂停。未知外部副作用仍需要对应范围的“确认继续执行”，普通发言不能绕过它。

会话切换、Reset 和删除检查本次活动执行、待回收句柄、未保存结果和进行中的存储提交，有阻塞则明确拒绝并保留输入。任务终结且结果可靠保存后，未被模型处理也可切走。历史 `Unconfirmed` 没有本次活句柄时，不成为永远不能满足的清理条件；涉及未知外部副作用的派发门槛仍保留。

正常关闭先停止接纳与派发，取消并收集工具/进程终态、保存与 join，再排空 Store，最后结束 Account、Tokio 和宿主。重开只恢复数据和来源，不重跑副作用、不复活进程、不自动发聊天请求。已保存结果可在明确续接时继续使用；重复打开不产生重复恢复占位。账号变更仍维持既有隔离和用户授权边界。

## 长时间并存仍然有界

每 Turn 32 次模型请求与 64 次工具调用继续有效，管理调用也计数；会话最多 64 个获准后台执行且尚未完成交付的登记、8 个实际普通执行、8 个活进程与未消费退出登记。新响应先结算已成功交付的旧结果再准入，拒绝项保留调用和未执行 output，但不占第 65 个后台登记。

会话许可继续区分经确认只读与独占副作用，进程在 yield 后保留副作用许可。控制查询、等待和取消不占普通工作槽，也不能排在一个永远等待被控制资源的普通调用之后。并发存在不意味着任意 shell 或未知 MCP 可以同时修改共享环境。

pending 指历史中没有 output 配对的调用，不等于正在执行或进程仍活着。请求冻结时存在 pending 就不发送 Inline 压缩；现有历史、新输入、候选响应、全部预留结果及闭合余量必须一起受限。旧任务的结果预留不能被大响应吃掉，越界在接纳与派发前失败。

接近容量边界时保留草稿/Queue，停止扩大上下文的派发和请求；本地查看、等待和取消仍可使用，不要求模型先发一个管理工具才能解锁。结果闭合后，在合法普通请求中恢复压缩。checkpoint 只替换覆盖前缀，保留冻结之后的结果/输入尾部及原始存档，不能裁剪未配对调用或用摘要伪造补发。

记忆提取按原始 Turn 的连续完整来源推进，包含晚到结果和真实资源终态；早期未闭合来源只阻塞本会话的提取前缀。旧纪元任务不会因为跨 Turn 完成就获得新授权或重置后的记忆写权限。

## 真正落地后再同步当前设计

主要联动 Conversation 的前台接纳/结束、Runner 的 final 收束、Runtime 的会话生命周期和 UI 输入资格，使用前面已完成的账本、控制、投影与恢复能力。不新增通用后台任务平台，不引入 Custom Tool、Code Mode、服务端 Multi-agent 或 WebSocket steering，也不改变已验证模型/登录路径。

Direct 新原生会话使用冻结的 `additional_tools` 首项和 Function Tool 的异步声明。旧平铺同步会话保留已保存的契约。原生异步仅为已验证的 `gpt-6.2-sol` 启用，其他模型沿用同步路径。

同步实际受影响的总体架构、会话、Direct 调用、请求/压缩、存储、记忆及 UI 设计，使当前文档能够正确解释跨 Turn 行为。收敛之前增量保留的临时等待逻辑和不再成立的逐 Turn 所有权，不把中间方案留成需要用户理解的永久模式。

## 验收这一次新增的完整行为

在 Windows x64、DX12、PowerShell 7、锁定依赖与真实应用执行，继续使用现有 Sign in with ChatGPT 和 `gpt-6.2-sol`。在当前数据环境创建专用验收会话；命令限定在明确目录，恢复/损坏场景仅用备份的验收材料。不得自行登出、切号、重授权、重置凭据或替换数据目录。

不新增测试、Benchmark、Example、mock、harness 或专用依赖。以真实应用、服务、日志、进程和调试边界取得证据；GUI 必须经 BRP 真实输入与截图/安全 ECS 查询，release 后核对 inactive 和 last_error。被调试器注入的条件明确标注，不称为真实服务返回。

实际服务场景使用工具独有的随机标记，核对模型是否在正确原始 `call_id` 的结果基础上复述，并核对真实副作用次数。HTTP 200、卡片完成和构建成功都不能单独证明跨 Turn 正确。关联记录涵盖会话/来源 Turn/请求/任务/调用/提交序号，避免泄露凭据、隐藏 reasoning 或完整敏感载荷。

本步负责下表全部端到端行为，同时补齐此前因前台仍保守等待而保留的联动项。使用 [114 项总清单](../../docs/design/native-async-tools/06-validation.md) 逐项记录已有有效证据、受本步影响的必要复核和明确未完成原因；不重跑无关已验证路径，也不把几个正常场景当作故障边界全部通过。阻断问题未修复或必要证据缺失时，不能把整个功能标为已验收。
