# 让长期记忆读取完整的来源证据

前台已经回答，不代表它启动的工具与进程已经结束。继续使用第一份 Finished 快照提取长期记忆，会遗漏迟到结果，也可能把“命令已启动”记成“工作已完成”。

本增量让记忆来源按最终任务账本与持久日志闭合，保留原始 Turn 的顺序、用户授权和记忆纪元。前一步已建立进程的真实终止事实，本步使用这些事实判定何时可以提取。它不新增另一套记忆流程，不改变现有记忆后台请求的职责。

依据：[长期记忆来源边界](../../docs/design/native-async-tools/04-durability-and-context.md)。实施顺序为 [10 进程生命周期](10-process-lifecycle.md) → 本文 → [12 任务界面](12-task-interface.md)。

## 从前台终态走到来源闭合

每个来源 Turn 只有同时满足以下条件，才能进入可提取范围：前台已经结束；属于它的工具都有持久终态结果；所属资源都有可解释且已保存的终止说明；必要的历史归并不存在不确定提交。正常失败、取消、未执行和未知结果也可以成为完整证据，不能仅因为不是成功就永久等待。

工具执行结束但结果尚未保存，或仍持真实运行/待回收句柄时，来源仍未闭合。函数 yield 返回、原 output 已进入历史、模型已经给出 final，都不能替代这些条件。相反，来源完整不要求模型已经解释结果：保存可靠且来源闭合后，不必为了记忆提取自动发起一次聊天续接。

会话存储继续保留前台 Finished 的事实，但读取来源时从日志与最终任务账本组装材料，包含 Finished 之后保存的输出、失败、未知终态、取消和实际清理事实。不能延迟读取同一份旧快照却仍漏掉晚到材料，也不能由旧快照覆盖已保存的任务进展。

当前活句柄与恢复后的历史未知有不同含义。前者必须实际停止、回收并保存证据后才能闭合；后者没有可恢复执行句柄，持久的 `Unconfirmed` 或历史清理未确认说明可以结束等待。提取时保留不确定性，不把它改写为工具成功，不等待永远不会到来的旧 OS 回执。未知外部副作用对新执行的确认门槛仍独立保留，来源闭合不自动解除它。

## 连续前缀避免迟到结果被永久跳过

记忆提取仍以原始 Turn 顺序形成连续可提取前缀。若较早的 Turn A 还有后台任务，而较晚的 Turn B 已经完整，当前会话的提取游标先停在 A 之前。A 闭合后，可以连续纳入 A、B 及后续已经闭合的材料，不能先跨过 A 再让它的晚到输出永远失去机会。

这个等待只影响该会话的记忆来源推进，不能挡住其他会话可提取材料，也不占用前台聊天槽。长驻进程可能延迟来源闭合，任务状态应给出真实原因；不以定时伪造成功或丢弃进程证据来推进游标。

关联仍使用来源会话、原始 Turn、调用/任务、提交序号与资源事实。压缩仅替换模型工作窗口，不删除公开原始时间线、任务账本或来源附件；记忆材料不从压缩后的摘要反推已经丢失的原始调用。

## 迟到结果不能获得新的授权或纪元

记忆重置的 cutoff 依据原始用户输入/Turn 来源序号和记忆纪元，不能按工具实际完成时间判断。旧纪元启动的任务晚于 reset 完成，仍属于旧来源，不能以“新到达”名义重新导入已重置材料。

执行时冻结的用户陈述、显式技能来源与记忆纪元继续适用。新 Steer、新 Turn、结果处理按钮或重置后的当前上下文都不替旧任务扩充授权。读取工具可以按既有明确策略异步执行，记忆修改工具保持同步并走原有授权与纪元检查。

“处理已完成结果”是显式的结果续接动作，不生成一条虚构用户消息；它不会把“请查看结果”解释成用户允许任意记忆修改。真实新用户陈述需要按原规则判断，不能因为同一请求恰好包含旧工具结果就混淆来源。

## 接入既有存储与记忆链路

`agentelier_conversation` 负责来源闭合条件与稳定事实关联；`agentelier_session_store` 提供已确认日志、最终账本和附件引用；`agentelier_memory` 使用连续可提取前缀并执行既有 cutoff/epoch 规则。Runtime 继续提供真实资源状态，Runner 不持一份独立的“可提取完成”权威。

保存未确认时沿用既有阻断：保留实际结果、暂停新的模型请求和副作用派发，继续必要清理，不重跑工具补结果。来源读取不能绕过存储游标的未知状态。恢复重复打开也不能不断生成新占位，导致同一来源反复被提取。

同步更新实际受影响的长期记忆、来源抽取、会话存储和任务生命周期设计。当前阶段仍采用保守前台放行条件，最后一个增量才允许工具跨过 normal final；本步先提供可直接检查的闭合和来源读取能力，不新增临时的用户可选记忆模式。

## 验收方式与完成边界

使用 Windows x64、DX12、PowerShell 7、锁定依赖和真实应用，在现有数据环境的专用验收会话中核对来源记录、游标及授权。模型服务验证沿用现有 Sign in with ChatGPT 和 `gpt-6.2-sol`。不要为了制造 reset 场景重置真实个人记忆、注销账号、重新授权或更换数据目录；这些动作需要独立明确授权，清单本身不提供授权。

不新增测试、Benchmark、Example、mock、harness 或测试依赖。难以自然到达的闭合/纪元边界可通过调试器观察或控制真实应用，但记录必须区分静态审阅、局部调试、真实运行和服务证据。选择与改动相关的编译/静态检查；日志只保存安全关联和必要状态，不导出原始敏感记忆或认证材料。
