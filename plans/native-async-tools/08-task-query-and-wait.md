# 让模型查询真实任务并有界等待

本增量提供同步的 `list_async_tasks` 与 `wait_for_tasks`，使模型能够取得应用分配的真实任务 ID，并等待明确集合的可报告终态。交付物包括有界安全列表、请求冻结的可引用任务集合，以及不占普通执行槽且持续响应 Stop/Steer 的等待路径。等待返回状态；原工具的真实结果仍只向原 `call_id` 交付一次。

顺序承接 [07 · 同 Turn 非阻塞](07-nonblocking-tools.md)，随后进入 [09 · 任务取消](09-task-cancellation.md)。非阻塞执行使模型可能需要在任务未结束时继续请求，此处为它提供查找与等待能力。下一增量在相同身份、冻结集合和控制调度上增加取消；此处保留其目标契约，但不提前声明取消工具已经实现。

## 任务 ID 来自应用，不放进外部工具参数

原工具的参数 schema 保持不变。应用接纳调用后分配任务 ID，通过三个自定义同步管理工具暴露控制能力。这些工具进入同一个 Direct 工具目录，使用同样的调用记录与结果保存路径。

| 工具 | 本次契约 |
| --- | --- |
| `list_async_tasks` | 查询本会话任务，返回任务 ID、原始 Turn、工具来源、安全参数摘要、执行/保存/交付状态和资源阻塞原因；不把真实工具结果复制成另一份输出 |
| `wait_for_tasks` | 接受非空、去重的已知任务 ID，`mode` 为 `any` 或 `all`，等待上限 30 秒；返回状态快照，超时只结束此次等待 |
| `cancel_async_tasks` | 接受明确 ID 集或明确的全部后台范围，回报取消请求与可确认状态；不把“已请求取消”伪装成资源已经停止 |

本阶段实际新增前两项，`cancel_async_tasks` 在 09 交付。响应通过完整校验并把调用到任务的映射持久提交后，应用才公开任务 ID；原始 `call_id` 继续负责协议配对，输出项 `id` 负责完整响应一致性，不能把三者互换。

## 列表让未完成交付与仍持资源的工作可发现

列表默认优先显示全部未完成交付项目，同时显示仍持有活进程或未消费退出结果的来源调用，即使原函数结果早已用于成功请求。此类行包含 `session_id`、来源任务/Turn、进程状态及许可阻塞，使模型在历史压缩后仍能发现需要控制的进程。已处理历史通过明确 ID 或有界分页查询。单页至多 64 项，超过时给出可继续查询的游标/剩余状态，不悄悄丢项；结果仍受 64 KiB 文本限制。参数摘要遵守现有脱敏和输出边界，不暴露凭据、推理密文或完整危险大载荷。

因此一项函数结果已经用于成功请求，也不代表列表可以忘记它创建的活进程。进程有自己的 `session_id` 和终止记录；10 完成进程登记后，这些行仍由本列表提供发现入口。当前先落地任务状态和安全分页，不用虚构进程状态填充尚未存在的记录。

## 模型只能控制本次请求已经可引用的任务

同批调用先登记全部异步 launch，再执行管理工具。因此 `launch + list` 能看到本批任务。但应用分配的 ID 在模型生成这批输出时尚不可知：点名等待新任务需要先拿到列表，再发后续 wait。`launch + wait(猜测 ID)` 必须报未知 ID，不能自动匹配“最新任务”。

模型发出的显式 wait/cancel 以本次请求冻结时已存在的可引用任务集合校验，不能只查同批登记后的实时账本。即使猜测碰巧命中新分配 ID，也不得在这批中控制它；`list` 的结果在后续请求中才使新 ID 可用。模型的“全部后台”范围也按该冻结集合解释，UI 的全部停止则按用户动作被接纳时的真实会话范围解释。

应用内部同批登记完成只改变真实账本，不回写模型已经发出的输入。`list` 可以观察新登记，但显式 wait/cancel 仍按生成这批调用所依据的冻结集合验证。错误结果照常以管理调用自己的 `call_id` 保存，不等待未来恰好出现的任务，不以最新一项或界面行号猜目标。

## 等待的是已保存终态，而非一次完成通知

`wait_for_tasks` 的 `all` 是所有指定任务都达到可报告终态，`any` 是至少一项；失败、取消、超时和未执行都属于终态。执行器已结束但结果尚未持久提交时，任务仍不可报告为结果可用。相关新结果必须能通过唯一出口排在 wait 自身状态之前；保存失败使等待明确失败并阻断后续采样，而不是返回“完成”。

已终止任务立即返回状态，已进入历史的结果不再追加。空集、重复 ID、未知 ID、其他会话 ID 都直接产生控制工具错误，不等待未来某个同名任务。等待订阅先建立、再检查账本；收到唤醒后重新检查条件，不能用一次通知代替条件本身。

`wait_for_tasks` 接受非空、去重、已知的本会话任务 ID；`mode` 为 `any` 或 `all`，`timeout_ms` 不得超过 30000。空集、重复、未知/其他会话 ID、无效模式及超限参数产生明确的同步控制工具错误。达到期限只结束本次等待并返回当前状态，后台工作继续；等待器不会自行再等一轮，也不会产生模型轮询循环。

如果多个原始结果在等待期间就绪，它们先经过保存和唯一历史出口，再出现 wait 自己的状态结果。等待已经终止的任务应立即返回，重复等待不能再追加同一原始 output。结果保存失败会使 wait 明确失败并阻断后续采样，不能为了让等待结束而宣称结果已经可用。

## 控制不能排在被它阻塞的普通调用后面

普通调用等待独占许可时，不妨碍同批管理操作运行。尤其不能先同步 await 一个被旧进程阻塞的普通调用，再迟迟不处理能够终止该进程的控制操作；批次登记完成后，执行和管理各自推进，结果仍由统一历史出口收束。

等待期间继续处理 Stop 和 Steer。Stop 结束等待；Steer 接纳后结束旧等待，保存真实的等待状态/被补充中断事实，并在下一边界应用用户补充。两者都不借由“结束 wait”取消所有被等待的后台任务。

列表、等待、取消与 UI 控制不占普通工作槽，也不取得被等待任务的资源许可。即使八个普通槽已满，管理操作仍可处理；终态订阅先建立再查账本，唤醒后重新判断。Stop/Steer 接纳和正常工具完成都由会话控制边界裁决，wait 只结束自己的等待，取消目标的范围由 09 的控制规则决定。

## 管理工具沿用同一个冻结目录

异步资格是应用工具契约的一部分，实际并行许可另行决定。异步声明不等于“可以与任意其他副作用同时执行”。

| 工具来源 | 本次模式 | 原因和约束 |
| --- | --- | --- |
| `exec_command`、`view_image` | 原生异步 | 等待执行、读取和处理可以与前台推理分开；仍遵守资源与载荷限制 |
| `apply_patch`、`write_stdin` | 同步 | 保持文件修改反馈和单进程输入输出的明确顺序；它们仍经过统一调度与记录 |
| 长期记忆读取工具 | 可声明异步 | 读取使用固定来源快照和纪元；不获得新授权 |
| 长期记忆修改工具 | 同步 | 继续要求实际用户陈述与原有授权校验 |
| 应用映射的 MCP Function Tool | 适配完成后声明异步 | 保留原始 schema、来源与取消语义；默认按未知副作用独占调度，不能把只读提示直接当并发证明 |
| 其他本地 Extension | 默认同步，注册者明确选择异步 | 只有固定输入上下文、有界结果、受控取消及资源归属明确的执行器才可开启 |
| 任务查询、等待、取消工具 | 同步 | 它们是会话控制操作，等待条件必须有明确反馈 |

模型能力按已确认的精确模型标识选择。本轮开放 `gpt-6.2-sol` 的原生异步路径；其他模型沿用已有同步路径，后续依据实际能力扩展，不通过字符串前缀猜测，也不自动换模型或换登录方式。API 对声明的拒绝应展示真实错误，不自动重发一套不同契约掩盖问题。

会话创建时冻结来源契约、模式和模型设置。读取已有存档时，缺少模式的声明按原有同步语义解释，并以该保存契约绑定当前支持的执行器；不把旧会话静默升级为异步。无需建设版本迁移平台。来源/schema 真正不匹配时仍明确拒绝执行。

管理 schema 进入新原生会话的冻结 `additional_tools` 目录，保持同步声明，并计入请求大小和 usage 估算。查询与等待也计入当前 Turn 的 64 次工具调用预算，普通 Responses 请求受 32 次预算约束。来源或 schema 不匹配时明确拒绝，旧平铺同步存档按原契约读取。

## 变化落在哪些现有职责

| 模块与入口 | 本增量承担的变化 |
| --- | --- |

| `agentelier_conversation` | 提供稳定任务事实、安全列表、分页和请求冻结的可引用集合，保持任务 ID 与原调用关系。 |
| `agentelier_turn_runner`、`agentelier_agent_runtime` | 批次登记后并行推进普通调度与控制，订阅/检查 wait 条件，及时处理 Steer/Stop，使用统一提交出口。 |
| `agentelier_llm_model` | 把管理声明纳入冻结请求、模式验证与请求计量；不把等待结果当作原任务的工具 output。 |
| `agentelier_session_store` | 继续单写入并保存管理调用/结果、中断与实际原工具结果，提交未知时不假称完成。 |

行为落地时同步 [Direct 工具调用](../../docs/design/tool_call.md)、[会话](../../docs/design/modules/conversation.md)、[模型请求](../../docs/design/modules/model-request.md)中管理工具、同步依赖和请求集合的实际事实；职责改变时同步 [总体架构](../../docs/design/architecture.md)。不把后续取消按钮、进程尾部和跨 Turn 行为提前写成现有事实，不另建功能说明目录。

业务仍留在现有 crates：不新增总 Agent 包，不转移到 `app/`，不修改 Bevy、Widgetry 或 BRP 上游。使用根 Workspace 的当前锁定依赖，遵守 Windows x64、DX12、PowerShell 7 环境。Bridge/UI 只接安全投影，不接收隐藏推理、压缩项、认证材料或附件字节。

## 本增量如何取得证据

运行验收使用 Windows x64、DX12、PowerShell 7、当前锁定依赖和真实应用。涉及服务时使用现有 Sign in with ChatGPT 与 `gpt-6.2-sol`，不自动换模型或登录路径，不为凑边界次数重复调用服务。编译、格式和静态检查只覆盖本增量实际改动及直接影响；构建成功不能代替运行证据。

在现有数据环境中正常创建专用验收会话，可写命令限定于明确的验收工作目录，保留原有会话、文件和登录。恢复或损坏记录场景先备份该验收会话及附件，只处理已备份副本并记录实际读取位置。退出、切号、重新授权、凭据重置或以切换数据目录间接使登录失效，仍须已有明确授权；清单不提供这项授权。正常关闭后在同一环境重开与退出账号不同。

不编写或引入测试、Benchmark、Example、mock 服务、专用 harness 或仅为验收服务的依赖。可以直接运行应用、检查正常诊断状态，或在调试器中控制真实应用的完成、回执和事件处理边界。难以触发且没有观察入口的条件标为未覆盖。

| 标记 | 证据及其边界 |
| --- | --- |
| 静 | 实际源码、依赖方向、序列化与错误路径审阅，只证明规则被表达，不能替代交错运行或 GUI/服务结果。 |
| 调 | 调试器控制真实应用边界或查看正常诊断状态。人工响应、事件必须标明注入位置，不称为服务实际返回。 |
| 运 | 真实应用与正常工具、存储记录、进程事实、关联日志；GUI 行为还需要 BRP 的真实输入、截图或安全 ECS 查询。 |
| 服 | 真实 Responses 请求/响应的安全记录及原调用关联；需要验证结果使用时，由模型准确复述工具独有随机标记。HTTP 200 本身不足以证明非阻塞或生命周期正确。 |

每条记录场景 ID、实际前提、操作、预期事件顺序、观察结果、证据位置、通过状态及清理结果，以会话、来源 Turn、请求、任务、原 `call_id` 和提交序号关联。日志只留必要安全字段，不导出凭据、隐藏 reasoning/compaction 或敏感完整正文。未执行、故障前提未达到、证据不足均不标通过；后续修改只复核直接受影响的证据。

### 原场景保留，后续能力只登记待复核

W-02—W-07 的任务查询/等待路径在本阶段完整执行，正常 launch＋list＋后续 wait 取得真实服务证据；猜测 ID 和错误参数分支可由调试器控制。W-08 当前验证同 Turn 的 Steer/Stop 中断，等待旧 Turn 任务的部分留到 13。W-01 当前验证任务状态、安全分页与上限，进程仍存活/未消费尾部的发现能力在 10 接入后补实测。

W-09 当前核对 wait 的冻结集合与碰巧猜中新 ID 的拒绝；09 增加 cancel 后复核同一规则，12 核对 UI 动作接纳瞬间的范围，13 再覆盖跨 Turn 来源。W-10 当前核对普通执行与管理不互相阻塞的调度边界，10 的进程独立控制落地后执行完整真实进程场景。不能把调度审阅或注入的资源状态标成后续进程/UI 行为已经通过。

| ID | 前提与动作 | 明确通过标准与证据 |
| --- | --- | --- |
| W-01 | 创建包含运行、排队、取消中、待处理、历史终态及已交付但仍持进程/尾部结果的任务集合，调用列表。 | 优先覆盖未完成交付项及仍有资源的来源调用，返回稳定任务/进程身份、原始来源、状态和阻塞；单页至多 64 项，余项可继续查询，受 64 KiB 限制，不复制完整真实结果或敏感载荷。证据：运＋调。 |
| W-02 | 让同批响应包含 launch＋list，再在另一条分支尝试 launch＋wait(猜测 ID)；正常分支先取得列表再等待。 | 全批异步调用先登记，因此 list 看见本批任务；猜测未知 ID 明确报错，不自动映射到“最新任务”。取得真实 ID 后的后续 wait 才正常工作。证据：运＋服；猜测分支可调试。 |
| W-03 | 对 wait 提交空集、重复 ID、未知 ID、其他会话 ID 和无效模式/超出上限参数。 | 立即返回明确控制工具错误，不等待未来同名任务、不跨会话读取；错误作为该同步调用的正常结果保存，未误取消任务。证据：运＋调。 |
| W-04 | 对多个真实 ID 分别使用 any/all，组合成功、失败、超时、取消和未执行；将某个结果暂停在保存之前。 | any/all 按指定集合的可报告终态判断；各种失败终态均计入完成，结果待保存不当作可用。保存失败使等待明确失败并阻断采样，不返回全体完成。证据：运＋调。 |
| W-05 | 等待已经终止的任务，再重复等待；核对同边界中新结果和 wait 自身结果的顺序。 | 已有终态立即返回，相关新原始 output 先于 wait 状态出现；已追加结果不再追加。wait 返回的是状态，不替原 call_id 交付另一份真实结果。证据：运＋调，历史顺序。 |
| W-06 | 对超过等待期限的任务执行最长 30 秒等待，同时占用普通工作槽/独占许可。 | 只结束本次等待并返回当前状态，后台任务继续；wait 不占普通槽或被等待资源许可，不造成互等。等待器不自行重启等待/轮询；正常下一采样仍按前台循环和请求预算进行。证据：运＋调，实际期限、许可和请求计数。 |
| W-07 | 将任务完成分别安排在等待订阅前、订阅与状态检查之间、检查之后，并让一次通知遗漏。 | 先订阅再检查条件，唤醒后重查账本；三种顺序均能按条件返回，边界复查不依赖一次通知，不出现永久悬挂。证据：调＋运，明确调试控制位置。 |
| W-08 | wait 进行中分别发送 Steer 和 Stop，包含等待旧 Turn 任务的情况。 | 两者可及时接纳并结束旧等待；Steer 在下一边界应用，wait 中断事实保存；结束等待本身不取消所有被等任务，Stop 仍只按创建 Turn 范围处理。证据：运＋调，回执与取消集合。 |
| W-09 | 同批 launch 后的 wait/cancel 恰好猜中新分配 ID，或模型使用全部后台范围；同时比较 UI 全部停止动作。 | 模型控制按本次请求冻结时可引用集合校验，猜中新 ID 也不可同批控制；list 使其在后续请求可用。模型全部范围以冻结集合为准，UI 全部范围以动作接纳瞬间为准，不互相混用。证据：调＋运。 |
| W-10 | 同一响应先出现被旧进程独占许可阻塞的普通同步工具，后出现能够终止该进程的合法控制操作。 | 批次登记后普通执行和管理/进程控制各自推进，不能顺序 await 前者而永远不处理后者；控制解除阻塞后原工作按许可继续，结果仍走唯一历史出口。证据：运＋调，准入与控制时序。 |

本增量完成时，模型可以看见真实任务 ID、有界等待已保存结果，控制不会被普通槽或被等待资源阻塞。wait 的状态、原任务的真实输出和取消范围保持独立；所有后续复核项继续沿用原场景身份，不被本阶段完成状态覆盖。
