# 保留原生异步工具的传输契约

本增量让工具的原生异步模式从声明、请求、完整响应到存档保持一致。完成后，可以用现有授权向 `gpt-6.2-sol` 发送正确的新工具包装，识别真实返回模式，并按原 `call_id` 保存结果。

这一阶段仍保守等待整批工具结束，再继续模型请求；声明 `async:true` 不提前释放现有执行屏障。开放历史由方案 03 建立，同 Turn 非阻塞由方案 07 开放，跨 Turn 生命周期由方案 13 开放。传输契约先可验证，后续再改变何时继续执行。

上一份：[整体关系与顺序](00-overview.md)。下一份：[让会话保留唯一的状态与历史所有权](02-conversation-owner.md)。下一份需要本增量提供可保留的调用模式，但会话所有权改变本身不依赖提前启用并发；本增量也不包含下一份的整体状态搬迁。

## 现有闭环与本次改变

当前工具循环的基本单元是一批完整响应：得到全部调用，依次执行，再把响应和全部结果一起封闭。这个闭环便于确定下一次请求的历史，却同时把“响应已经合法完成”和“它启动的所有工作已经结束”绑在了一起。

| 当前事实 | 对目标行为的影响 | 核查入口 |
| --- | --- | --- |
| `ToolDefinition` 与 `FunctionCall` 没有异步模式 | 请求声明与流式解析无法保留原生异步语义 | `tools/src/catalog.rs`、`llm_model/src/stream.rs` |
| `ProtocolHistory::seal` 要求调用与结果逐项齐全 | 无法提交仍有未完成异步调用的合法响应 | `llm_model/src/protocol.rs` |
| `ActiveTurn` 持有整个会话历史及展示快照 | 后台结果与新 Turn 各自更新时会互相覆盖 | `conversation/src/active.rs`、`conversation.rs` |
| Runner 串行执行，Executor 全程借用可变上下文 | 仅增加 spawn 不能形成独立并发执行 | `turn_runner/src/runner.rs`、`tools/src/catalog.rs` |
| 每次 Turn 收尾都 cleanup 进程 | 前台结束可能杀掉仍有用的后台进程 | `turn_runner/src/runner.rs`、`tools/src/sessions.rs` |
| UI 按当前 operation 过滤聊天事件 | 旧 Turn 的后台结果会被当成过期事件丢弃 | `chat_ui/src/conversation.rs` |

这些事实来自[当前源码入口](../../docs/design/native-async-tools/sources.md#当前实现)。现有 Steer 和 Queue 已经可用：活动 Turn 可以接纳补充，排队输入在活动执行真实回收后进入下一 Turn。目标是在此基础上允许工具继续存在，并继续保持一个活动 Turn。

这里保留当前逐批收齐结果的运行方式，只补齐传输和保存契约。表中所有权、独立执行、进程收尾和旧 Turn 事件的问题各有后续增量，不能靠给字段加一个异步标志就认为已经解决。

## 结束的对象必须分清

先区分三个对象，后面的状态和控制才有明确归属。

| 对象 | 结束意味着什么 | 结束后可能仍然存在什么 |
| --- | --- | --- |
| Responses 请求 | 收到了通过校验的完整响应，或请求明确失败、停止 | 响应中的异步调用、会话、前台 Turn |
| 应用 Turn | 本次前台生成与同步依赖已经收束，输入接纳已关闭，句柄和终态提交完成 | 此 Turn 创建的异步调用、进程、待处理结果 |
| 工具调用 | 本次函数执行形成一个真实结果或明确错误 | 结果保存与交付，以及工具创建的独立进程资源 |

`exec_command` 还有第四种对象：进程会话。它在 yield 时返回 `session_id`，原函数调用此时就有了完整结果；进程可能还没有退出。后续输出通过新的 `write_stdin` 调用取得，不能再向原 `call_id` 填第二份“最终结果”。这项现有契约继续保留，改变的是资源可以跨 Turn 存活及被管理的范围。

上表描述最终目标边界。本增量不让未结束工具或进程越过当前 Turn；尤其不能把 `exec_command` 的 yield 当作原生异步已经跨 Turn 的证据。

## 声明与响应共同确定实际模式

[官方异步协议](https://developers.openai.com/api/docs/guides/async-tool-calling)允许声明为异步的应用工具在结果缺席时继续后续请求，最后用原 `call_id` 配对结果。执行器、调度、保存和取消都由应用承担。

本应用使用 Function Tool：请求保留 `type: function`，符合资格的声明增加 `async: true`；响应解析保留调用项的 `async` 标志，结果仍使用 `function_call_output`。`call_id`、输出项 `id` 和应用任务 ID 各有用途，不可互换。协议支持的 Custom Tool 不属于当前工具体系，本次不扩展它。

SIWC HTTP 继续使用 `store: false`、`stream: true` 和完整有序的 `input`，不发送 `previous_response_id`。异步指南中的服务器链式状态示例不改变本地历史重放路径。[SIWC 限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)、[会话状态](https://developers.openai.com/api/docs/guides/conversation-state)分别约束接入方式和历史材料。

新建 `gpt-6.2-sol` 会话将冻结的工具目录作为每次 HTTP 请求 `input` 的首项。该项使用 `type: "additional_tools"`、`role: "developer"` 和 `tools` 数组。顶层省略 `tools`，符合资格的 Function Tool 保留 `async: true`，叶子名称、参数 schema 和执行器参数沿用原契约。[Responses 请求结构](https://developers.openai.com/api/reference/resources/responses/methods/create)

每次全量重放从同一冻结目录生成这一项，后面依次使用已有指令、上下文和协议历史顺序。工具声明是请求材料，应用历史只保存实际发生的协议内容。完整调用按 `name` 绑定本次请求目录，未知名称或意外 namespace 在派发前拒绝。保留原始调用项及 `call_id`，已有平铺同步存档继续按保存契约重放。正式验收仍需要在应用的会话路径上观察服务调用和真实结果交付。

声明资格和实际返回模式分开处理：

- 同步声明不能接受服务端突然返回 `async: true`；在完整响应提交和工具派发之前报告协议错误。
- 已声明异步而最终调用省略标志或返回 `false` 时，按同步依赖处理并保留诊断事实；不擅自假设服务端已解除了等待。
- SSE 的完整调用项与最终响应必须在调用身份、名称、完整参数和异步模式上相容。`response.completed.output` 是提交依据；增量展示不触发副作用。
- 同一响应、历史重放或重复流事件中的同一 `call_id` 不得再次启动。相同完成事实可幂等归并；同 ID 不同来源或载荷是冲突。

第一版明确等待完整响应验证、保存之后再启动工具。它比完整流项到达就启动稍晚，却沿用了项目已经存在的“先保存合法响应，再允许副作用”的边界。Codex 的早派发实现可作为后续性能研究材料，当前不会同时引入这个额外失败窗口。

现有 `parallel_tool_calls: true` 可以继续用于这个 Direct 请求路径；本方案没有启用服务端 Multi-agent，也不会把该模式特有的组合限制误套到普通应用工具上。

## 工具目录是一份冻结的契约

异步资格是应用工具契约的一部分，实际并行许可另行决定。异步声明不等于“可以与任意其他副作用同时执行”。

| 工具来源 | 本次模式 | 原因和约束 |
| --- | --- | --- |
| `exec_command`、`view_image` | 原生异步 | 等待执行、读取和处理可以与前台推理分开；仍遵守资源与载荷限制 |
| `apply_patch`、`write_stdin` | 同步 | 保持文件修改反馈和单进程输入输出的明确顺序；它们仍经过统一调度与记录 |
| 长期记忆读取工具 | 可声明异步 | 读取使用固定来源快照和纪元；不获得新授权 |
| 长期记忆修改工具 | 同步 | 继续要求实际用户陈述与原有授权校验 |
| 应用映射的 MCP Function Tool | 适配完成后声明异步 | 保留原始 schema、来源与取消语义；默认按未知副作用独占调度，不能把只读提示直接当并发证明 |
| 其他本地 Extension | 默认同步，注册者明确选择异步 | 只有固定输入上下文、有界结果、受控取消及资源归属明确的执行器才可开启 |
| 任务查询、等待、取消工具 | 同步 | 它们是会话控制操作，等待条件必须有明确反馈 |

模型能力按已确认的精确模型标识选择。本轮开放 `gpt-6.2-sol` 的原生异步路径；其他模型沿用已有同步路径，后续依据实际能力扩展，不通过字符串前缀猜测，也不自动换模型或换登录方式。API 对声明的拒绝应展示真实错误，不自动重发一套不同契约掩盖问题。

会话创建时冻结来源契约、模式和模型设置。读取已有存档时，缺少模式的声明按原有同步语义解释，并以该保存契约绑定当前支持的执行器；不把旧会话静默升级为异步。无需建设版本迁移平台。来源/schema 真正不匹配时仍明确拒绝执行。

此表规定最终各来源的模式资格。当前已存在、具备结果边界的工具可以先把资格写入声明，运行仍收齐整批；MCP/Extension 必须等固定来源、取消和结果边界适配完成才启用对应资格。查询、等待、取消工具在它们各自增量落地时注册，不为完成本表制造占位工具。

## 修改落在现有传输和契约边界

| 实际边界 | 此增量需要形成的行为 |
| --- | --- |
| `crates/agent/tools/src/catalog.rs` 的工具定义、注册与重新绑定 | 保存声明资格、传输格式与来源契约。旧无模式声明按同步解释，保持参数 schema，Extension 默认同步 |
| `crates/agent/llm_model/src/generation.rs` 的请求准备 | 在新原生会话的每个请求中把冻结目录组成唯一的 developer `additional_tools` 首项。调用和用户历史保持原顺序，请求核对保留真实材料索引。继续使用 `store:false`、`stream:true` 和冻结发送字节 |
| `crates/agent/llm_model/src/stream.rs` 的完整项与最终输出 | 按冻结目录的名称校验无 namespace 调用，核对完整参数、身份和实际模式。保留原始项，非法批次在派发前结束，增量只更新展示 |
| `crates/agent/llm_model/src/protocol.rs`、`protocol/archive.rs` 与 `crates/agent/conversation/src/archive.rs` | 原始调用字段和不透明项原样存取；结果仍按原调用关联；旧 flat raw 不被改写成新包装，本阶段仍以完整批次封闭 |
| `crates/agent/turn_runner/src/runner.rs` 与 `crates/agent/conversation/src/active.rs` | 将实际模式传递至现有执行/保存边界；完整合法响应持久确认后才执行；过渡期无论声明如何都收齐当前批次，不用模式字段绕过当前历史能力 |

这里只建立 `agentelier_llm_model`、`agentelier_tools` 与其调用方对同一工具契约的认识；`agentelier_conversation` 和 `agentelier_session_store` 保持现有状态/写入职责，Runner 不自行发明另一份模式来源。

同步更新 `docs/design/modules/model-request.md`、`docs/design/tool_call.md` 以及受到存档契约改变影响的 `docs/design/modules/conversation.md`。它们说明已经落地的声明、校验、旧会话和保守执行事实，不能在此阶段写成已经支持跨 Turn。

不新增承担整个 Agent 的总包，不把业务移到 `app/`，不修改 Bevy、Widgetry 或 BRP 上游。根 Workspace 的依赖规则、Windows x64 / DX12 / PowerShell 7 目标以及当前锁定依赖继续适用。[结构与 UI 参考](../../docs/design/native-async-tools/sources.md#结构与界面参考)解释资料的采用范围。

实施时，随着相应行为真正落地，同步更新总体架构、会话、模型请求、会话存储、长期记忆和 Direct 工具调用等现有设计。这里的目标文档不能提前替换尚未改变的事实，也不新建一套逐项功能说明目录。

## 验收怎样区分协议成立与后台已经开放

运行验收使用 Windows x64、DX12、PowerShell 7、当前锁定依赖和真实应用。涉及模型服务时使用现有 Sign in with ChatGPT 与 `gpt-6.2-sol`，不自动替换模型、登录路径或工具契约；本方案形成的文档本身不代表已经通过构建或运行验收。编译和静态检查只覆盖此增量实际影响的范围，遵守 [项目约束](../../rules/project-context.md) 与 [常用命令](../../rules/common-commands.md)。

在现有数据环境中正常创建专用验收会话，保留其他会话、登录和文件；可写工具仅操作明确的验收工作目录。不得为验收重置数据目录、删除原会话或复制认证材料。登出、切号、重新授权、凭据重置以及会导致登录失效的数据目录变更，仍须已有明确授权；清单不是这类授权。未授权的分支保留静态证据并标为未执行。

不编写或引入测试、Benchmark、Example、mock 服务、专用 harness 或测试专用依赖。使用真实应用、正常工具、既有诊断和调试器边界观察；无法实际到达的条件记录为未覆盖。四类证据分别记录：

| 标记 | 证据与边界 |
| --- | --- |
| 静 | 源码、依赖方向、序列化、状态转换和错误路径审阅；不能证明真实交错、服务或界面已工作 |
| 调 | 调试器控制真实应用边界或检查正常诊断；人工替换响应/事件注明注入位置，不能称为服务实际返回 |
| 运 | 真实应用、正常工具、存储记录、进程事实和关联日志；涉及 GUI 时使用 BRP 真实输入与状态/截图，不能仅靠本地状态推断服务已使用结果 |
| 服 | 真实 Responses 请求/响应的安全记录及关联结果，必要时准确复述工具独有随机标记；HTTP 200 本身不足以证明完整行为 |

每项记录场景 ID、实际前提、操作、预期顺序、实际结果、证据位置、是否通过和清理结果；关联会话、来源 Turn、请求、任务、原 `call_id` 与提交序号。只记录必要的安全字段，不导出凭据、隐藏 reasoning/compaction 或完整敏感正文。实际日志沿用 [日志规则](../../rules/logging.md)。

未执行、故障条件未达到、只取得部分种类证据，均不把整项标为通过。后续增量改变这里的边界时，复核直接受影响的项目，保留未受影响证据，不机械重跑全仓检查。

正式会话的 `additional_tools` 声明和真实异步调用必须取得服务证据。非法响应通过调试真实应用的解析与接纳边界覆盖，并记录注入点。随机标记由正常工具产生并由模型复述。

N-02 中尚未注册的管理工具与尚未适配来源保持“待对应增量联动”，不伪造可调用项；已存在工具的模式和服务声明在本阶段核对。N-06、N-07 的当前完整响应持久确认、重复调用拒绝可以实际验证；它们涉及新任务映射、稳定任务账本的部分在方案 02–03 形成后补证。完整 N 项原标准保留在下表，部分覆盖不能填成整项通过。后续方案 07 和 13 必须复核本契约在真实非阻塞和跨 Turn 条件下仍成立。

本阶段的可交付完成条件是传输、模式校验、旧契约重放与保守执行成立。真实服务证据必须来自正式会话路径，独立协议实验作为接入依据。

## 原生协议与工具模式的完整验收清单

| ID | 前提与动作 | 明确通过标准与证据 |
| --- | --- | --- |
| N-01 | 使用现有授权和 `gpt-6.2-sol` 创建新会话，检查实际发送的准备请求。 | `input` 首项为唯一的 developer `additional_tools`。顶层省略 `tools` 和 `previous_response_id`。叶子保留 schema 和实际声明模式，后续输入顺序保持，`store:false`、`stream:true`。证据：服＋静，安全请求检查记录。 |
| N-02 | 在同一工具目录分别调用异步资格工具、`apply_patch`、`write_stdin`、记忆修改与管理工具；检查 Extension/MCP 映射。 | 模式符合设计表，控制与修改工具保持同步；未知 Extension 不自动异步，MCP 原参数 schema 未被加上任务 ID；同一来源的契约一致。证据：静＋运；服务请求中的工具声明。 |
| N-03 | 取得一次真实原生异步调用，比较 SSE 完整调用项、最终响应和持久记录。 | `async:true`、`call_id`、输出项 `id`、名称和完整参数一致保留。完成响应通过校验并持久确认后才派发。结果使用原 `call_id` 的 `function_call_output`。证据：服＋运。 |
| N-04 | 对已声明异步的调用，在调试器中分别令最终模式缺省和为 `false`；保持身份与载荷一致。 | 两者均按同步依赖处理，下一请求等待真实结果；记录返回模式，不擅自当作原生异步。注入材料单独标为本地分支验证。证据：调＋静。 |
| N-05 | 分别构造同步声明收到 `async:true`，以及 SSE 完整项与最终项的身份、名称、参数或模式冲突。 | 在完整响应正常提交、任务登记和派发之前拒绝整份响应；该批无任何工具副作用。错误保留具体冲突，不能以最终值静默覆盖。证据：调＋静，执行开始记录为空。 |
