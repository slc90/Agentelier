# 让进程在函数返回后仍有明确的所有者

异步函数完成与子进程退出不是同一件事。`exec_command` 可以先交付输出片段和 `session_id`，进程随后继续运行；如果函数结果、进程清理和后续输出消费都依附于一次 Turn，正常结束、取消轮询和迟到退出就会互相误伤。

本增量交付会话范围的进程登记、完整控制语义和有界退出结果保留。第 05 步在转交 shell 许可时已经保证同 Turn 的自有进程控制不自锁、读写串行且终止可达，前一步已经提供按来源取消任务及会话收尾；本步完善跨 Turn 归属、旧进程 poll 的取消范围、退出消费和恢复。它为后续记忆来源判断和最终跨 Turn 放行提供可核对的资源事实，不在这里提前开放所有跨 Turn 聊天行为。

依据：[执行与控制](../../docs/design/native-async-tools/03-execution-and-control.md)、[恢复与来源边界](../../docs/design/native-async-tools/04-durability-and-context.md)。实施顺序为 [09 任务取消](09-task-cancellation.md) → 本文 → [11 记忆来源](11-memory-evidence.md)。

## 一个调用结束，一份资源继续存在

每次 `exec_command` 仍只产生一个与原始 `call_id` 对应的完整 Function Tool 结果。yield 返回不等于整个命令结束，但已经闭合这次函数调用；后来的退出码和输出不能再次补到同一调用。需要继续读取时，模型通过新的 `write_stdin` 调用取得结果，后者有自己的调用与输出身份。

进程登记由会话的运行资源所有者管理，保留会话、创建 Turn、来源任务/调用、当前执行实例、真实句柄和持有的副作用许可。Conversation 保存可恢复业务事实，Tools 提供执行与控制，Runtime 持有、观察和回收句柄。Runner 与 UI 都不成为另一份进程表的权威。

合法控制限定在同一会话和本次有效实例。来源 Turn 已结束并不使仍存活的 `session_id` 失效；其他会话、旧执行实例、已经移除或恢复后的历史 ID 立即返回明确错误。退出 ID 不复用，不能让迟到操作命中新进程。

前面采用的保守调度继续有效：任意 shell 持独占副作用许可。函数在 yield 返回时可释放普通工具工作槽，许可却必须转交进程所有者，直到真实退出、完成必要回收且资源终止事实持久确认。冲突工具显示等待及其阻塞来源；不能为了放行后续任务而把仍会写文件的进程当作只读或已完成。

## 输入输出串行，终止另有通道

同一进程的所有 stdin 写入、输出读取和消费位置都由同一个所有者串行处理。多个 poll 不得读到相同的已消费字节；非空 stdin 已写出的部分需要如实记账，取消或响应不确定后不自动重发。操作失败不能把已经送入进程的输入解释成未发生。

`write_stdin` 控制的是该进程已持有的许可，不再竞争一份会被自己永久挡住的普通独占许可。这个例外只允许控制原进程，不允许多个读写操作绕过串行所有权。进程终止使用独立控制路径，正在等待输出的 poll 不能阻止 terminate 到达并驱动真实退出。

取消一次对旧进程的 poll/write，结束的是当前调用的等待或尚未完成的写入。已写字节保留事实，旧来源进程继续存在。只有明确 terminate、取消仍运行的创建任务，或者适用的会话收尾才终止它。Stop 当前 Turn 同样按创建来源处理：停止本 Turn 创建的进程，不因本 Turn 恰好轮询一个旧进程就把旧进程杀掉。

自然完成与取消仍由会话权威裁决，一次调用只能有一个不可变终态。函数仍运行时取消来源任务，需要停止它创建的进程并报告回收情况；函数已经完成时取消任务只能回报已结束，进程使用独立终止入口。晚到通知只核对同一执行实例和清理状态，不生成第二份工具结果。

## 退出结果保留到被读取或明确收起

进程自然退出时，由资源所有者完成 wait/reap、剩余输出捕获和退出状态保存。退出、尾部和清理事实都得到持久提交回执后才释放副作用许可，提交排队不算确认。回执延迟时冲突工作继续等待；保存失败或回执未知时保留材料并暂停相应派发，不能靠释放许可掩盖未确认事实。自动退出收集与正在进行的 `write_stdin` 共用消费位置；两者相遇时不能各自交付同一尾部。

沿用每流 512 KiB 捕获上限，保留明确的截断和替换标记；最终工具结果或界面展示材料仍受 64 KiB 文本结果边界约束。退出码、未消费尾部和清理事实写入资源终止记录；不能为了释放资源登记而静默丢掉尾部。

活进程与已退出但仍可继续读取的终态登记合计最多 8 个。实际退出、完成回收且终止事实保存确认后释放副作用许可，但进程登记名额要等尾部被一次消费，或用户明确收起/丢弃可读取登记后才释放。达到上限时拒绝新增进程并说明原因，不能形成第 9 个登记或以后台无限缓存绕过限制。收起只结束可读取登记，保留来源与已经持久化的退出证据。

已有 `list_async_tasks` 必须同时覆盖这些资源：原函数结果即使早已被模型使用，仍持活进程或未消费退出结果的来源行也可查询，带 `session_id`、创建来源、进程状态和许可阻塞。查询仍有界分页、安全摘要和 64 KiB 输出限制；历史压缩以后，模型也能找到需要控制的存活进程。

## 保存与恢复保持真实边界

切换或关闭之前，退出记录持久确认且没有活句柄即可，不要求用户先读完尾部。未保存结果、待回收句柄和提交不确定继续阻止替换；只有保存好的无句柄尾部缓存不阻止。保存失败保留内存材料、暂停新模型请求和副作用派发，并继续必要的资源清理。

重新打开会话时，保留来源、退出码、有界摘要和清理证据；不连接旧 PID，不恢复 stdin/stdout，不重用旧 `session_id`，不重新执行命令。查询可返回带来源的历史资源摘要，但不能把它伪装成原函数的新 output。恢复产生的历史未确认终止记录与本次真实待回收句柄分开，前者不能永久占运行槽或阻止只读打开与正常关闭。

正常应用关闭沿用前一步的顺序：关闭接纳和派发，停止工具/等待/进程，收集实际终态与资源证据并 join，排空 Store，最后关闭 Account、Tokio 和宿主。数据保存与资源清理均有回执；一次 terminate 请求被接受不能证明这个过程已经完成。

## 落入已有模块并保持阶段边界

本步主要调整 `agentelier_tools` 的进程所有权和执行接口、`agentelier_agent_runtime` 的真实句柄回收、Conversation 的资源关联事实及 Session Store 的终止记录；任务查询同步补齐资源投影。不新增通用进程平台，不把业务移到 `app/`，不修改上游或升级依赖。

最终目标是正常 final 不统一 cleanup，本步先使进程可以由会话独立管理，并保留当前阶段明确的前台放行限制。尚未完成最终增量时，不借临时开关向用户宣传完整跨 Turn 支持。与来源 Turn 解耦的真实运行、Stop 旧进程分支和空闲保留在最终增量复核；这里可以先证明进程独立所有权、控制并发、尾部和恢复事实。

随实际行为变化，同步已有本地开发工具、工具执行、会话生命周期和持久化设计；不要只更新本目标文档而让当前设计仍描述已移除的逐 Turn 进程表。

## 验收方式与完成边界

在 Windows x64、DX12、PowerShell 7 的真实应用上验证，保持锁定依赖、现有数据目录和登录；需要服务请求时使用 `gpt-6.2-sol`。仅在专用验收会话和明确工作目录运行可追踪命令，记录来源 ID、实际进程状态、写入字节、输出消费位置、提交顺序和最终回收。日志中文正文与英文结构化字段沿用宿主，不泄露认证、隐藏协议载荷或完整敏感输入。

不新增测试代码、Benchmark、Example、mock 服务、harness 或专用测试依赖。使用真实进程与现有诊断，必要时用调试器控制实际应用边界；注入不冒充真实服务。选择与本步 Rust 改动相关的格式、编译和静态检查，不机械重复全部检查。界面控制在第 12 步通过 BRP 核验，不能用直接修改 ECS 代替点击。
