# 在继续聊天时看清后台工作

模型正在回答时，可能同时有工具排队、运行、等待保存或等待结果处理。只显示一个互斥的 model/tool phase，无法表达这些事实；沿用前台 operation 过滤，又可能把旧 Turn 的合法任务更新一起丢弃。

本增量交付会话任务区、稳定的任务/进程控制和待处理结果入口，并把会话事件与前台事件分开投影。前面的步骤已经具备任务账本、取消、进程、恢复和来源边界，本步让用户能够看见并操作它们。最终跨 Turn 的前台放行仍由下一步完成，未开放的行为不提前标为可用。

依据：[交互与模块职责](../../docs/design/native-async-tools/05-interaction-and-integration.md)、[执行控制](../../docs/design/native-async-tools/03-execution-and-control.md)、[历史交付](../../docs/design/native-async-tools/02-history-and-delivery.md)。实施顺序为 [11 记忆来源](11-memory-evidence.md) → 本文 → [13 跨 Turn 续接](13-cross-turn-continuation.md)。

## 前台活动与后台任务同时展示

聊天区继续展示当前前台活动，会话任务区独立列出后台工作。优先展示运行、等待资源、取消中、保存异常、待处理和仍持进程的项目；历史完成项可折叠。每项有稳定任务 ID、工具名、原始 Turn、安全参数摘要、阻塞来源和执行/保存/交付状态，不能合并成一个“成功”。

原消息时间线保留调用的启动位置及最终结果。旧任务完成时更新原来源卡，不把它搬到最新 Turn 下。列表分页或折叠不能让未完成交付项目失去入口；数量与业务账本一致。长中文、代码、图片和接近上限的条目都受可读布局与安全摘要边界约束，摘要不作为完整协议结果发送。

`exec_command` 已返回而进程仍运行时，明确展示这两个状态。任务取消与进程终止使用各自身份：函数已结束则取消回报已结束，需要独立 terminate 才终止进程。已退出但尾部未消费时展示退出码、有界摘要和截断标记，允许查看或明确收起可读取登记；收起不删除持久来源证据。

## 控制入口表达真实范围

单任务取消、进程终止和停止全部后台工作都提交业务动作，等待真实回执。取消中抑制重复提交；点击与自然完成交错时展示已结束，不误伤列表中移动到相同行的其他任务。业务侧再次核对会话、稳定任务/进程身份与执行实例，UI 按钮禁用不是唯一防线。

Stop 当前 Turn 保留既定范围：停止本 Turn 的请求、等待及其创建的工作，较早来源任务保留。停止全部后台工作则按用户动作被接纳时的真实会话范围处理，同时暂停新副作用派发和自动 Queue；在途响应新生成的工具形成明确未执行结果。只有明确恢复或开始新工作才解除这项暂停，不能刚停止全部又自动启动一批。

未知外部副作用显示单独的“确认继续执行”，明确关联待确认任务与范围。该动作持久记录用户确认，解除相应外部未知派发门槛，但不改写历史为已证实停止；它不能绕过当前活句柄回收、存储未确认或身份冲突。

非法压缩响应只提供绑定失败请求及原输入身份的一次性“本次不压缩并继续”。若新 Turn 已取代该失败请求，入口失效；动作从当前合法历史继续、不重加输入/结果、不重跑先前副作用，新请求计入预算且本次省略压缩。容量不足或再次失败要明确停下，不能退回通用从头重试。

## 结果完成不自行启动聊天

空闲结果保存后，显示“已保存，待处理”及“处理已完成结果”。点击向 Runtime 提交明确的结果续接触发，不伪造用户话语，不授予新的记忆或其他副作用权限。没有待处理结果时不创建请求。

普通输入也可以消费适合下一请求的就绪结果。结果按钮与发言同时到达时，由同一前台接纳边界裁决，只有一个动作取得槽；另一动作得到清楚回执，保留尚未被接纳的草稿。结果输出仍由会话唯一出口追加，UI 不自己拼接第二份历史。

有活动 Turn 时发送继续走 Steer，显式排队继续走 Queue；没有活动 Turn 才启动新的 Turn。保持 Accepted、Applied、NotApplied 的差别。final 与最后一条输入相遇时，不能显示 Accepted 却既没有应用也没有明确失败，也不能既补充又新建一次。

正常保存且无活资源时，尚未模型处理的结果可以留在会话中，允许切换和关闭；再次打开仍显示待处理，不因恢复或任务完成自动发聊天续接请求。用户已经显式接纳的 Queue 与既有记忆后台请求按原规则和触发来源另计。有活动执行、未保存结果、当前待回收句柄或进行中的存储提交时，切换、Reset 和删除明确拒绝并指出来源，保留草稿和阅读位置。历史未知终止记录不能被误当成本次永远无法回收的句柄。

## 会话投影与前台 operation 分开

前台事件继续使用现有 `ChatState.operation`，拒绝过期正文、旧请求状态和错误。会话任务事件使用会话 UUID、任务 ID、执行实例与单调业务修订；先核对身份，再更新对应行。不能删除 operation 过滤来让旧任务显示，否则会让旧正文覆盖新 Turn。

较旧修订不回退当前状态，已经终结的任务不被迟到进度复活。其他会话和已关闭执行实例的事件被拒绝。任务清单排序/名称变化不是协议历史位置变化，不能用 UI 全局版本使合法请求或压缩检查点失效。

Bridge 只发布可展示字段。原始协议、隐藏 reasoning/compaction、认证信息和附件字节不进入 Reflect、ECS 投影、普通日志或可见详情。需要关联时使用会话、Turn、任务、请求、提交序号、状态和计数，保留现有安全摘要边界。

空闲完成和错误经过现有 Connection 与 Winit 唤醒链。用户没有键鼠输入时，任务状态也能刷新；工作结束后不靠永久刷新循环维持。后台执行仍归 Agent Runtime，Widgetry 的辅助 JobManager 不成为第二个 Agent 所有者。

## 更新行，不破坏用户正在做的事

沿用 BSN/Scene 组合，Props 只用于构造初始化。运行状态保存在持久 Component，经 Widgetry 公开控件接口更新；不通过重建整个聊天区、输入框或滚动容器刷新任务。

物理行复用始终绑定稳定业务身份，展开状态与控制动作不能串到邻行。任务更新不抢焦点、不清草稿、不改选区、不强制滚到底部、不收起用户正在查看的详情。已有底部跟随行为继续按用户阅读状态工作。

输入被接纳时只清理对应草稿版本，用户在回执到达前新增的文字保留；拒绝时原文字和焦点仍在。取消中、最终完成、迟到旧投影等关键中间帧与最终状态都要一致，Theme、文字、图标、禁用状态不能各自停在不同阶段。

## 落地范围与观察边界

修改范围集中在 Conversation Bridge、Connection、Agent Host 的事件/唤醒/回执及 `agentelier_chat_ui` 的会话任务呈现和输入状态；Runtime 继续执行控制。保持现有 crate 边界，不把业务移入 `app/`，不修改 Bevy、Widgetry、BRP 上游，也不新增一层逐项功能说明文档。

日志沿用宿主单一订阅与持久化，中文正文、英文结构化字段。用户控制和业务结果使用适当 INFO，执行阶段使用 DEBUG；正常等待和取消不是 WARN。真实错误保留来源和状态，临时 TRACE 在交付前移除，不新增专用日志框架。

本步接通安全投影、控件和控制入口。第 13 步才放开正常 final 后后台继续时，届时补齐 U-02、U-04、U-09 等完整跨 Turn/空闲交互；此前可验证已有真实状态和合法局部边界，不能在界面伪造业务状态来宣称跨 Turn 完成。随行为落地同步会话 UI、Bridge、Connection 和生命周期的当前设计。

## 验收必须经过真实 GUI

目标为 Windows x64、DX12、PowerShell 7 与锁定依赖。使用真实应用、现有数据环境和专用验收会话，需要服务时沿用 Sign in with ChatGPT、`gpt-6.2-sol`。不自行登出、切号、重授权、重置个人资料或更换数据目录；未获授权的相关场景保留未执行状态。

不增加测试、Benchmark、Example、mock、harness 或专用测试依赖。按实际改动选择格式、编译和静态检查，并按 [GUI 验证规则](../../rules/gui-debugging.md) 用已安装 `bevy_brp_mcp` 发现真实能力、应用与方法；优先稳定 `Name`，Pointer、Keyboard、Focus、Scroll 走真实输入。不得直接改 ECS 冒充交互，也不以不等价的 OS 输入替代标准 BRP 验收。

记录真实输入、关键中间帧/最终截图、安全 ECS/业务投影和控制回执。工具接受请求、Pointer 结束、UI 正确是三个证据，不能相互替代。完成后用实际发现的 `brp_extras/pointer_control` release，再查 status 至 `phase=inactive`，并检查 `last_error`；`busy=false` 不单独证明成功。

每项记录场景 ID、实际前提、动作、时序、观察、证据位置、是否通过与清理结果。调试器控制的局部故障需说明注入边界，静态或本地投影不能冒充 GUI/服务已通过。以下完整清单随本步负责，依赖下一步的条目保留明确待联动状态。
