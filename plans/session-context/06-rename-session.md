# 给会话改名而不改变它的身份

本增量为侧栏条目加入重命名，提交后的名称同时更新列表与当前聊天标题。它只改变会话元数据，不移动会话目录、不修改模型上下文，也不发起命名模型请求。

```mermaid
flowchart LR
    Action[目标 Session 的更多操作] --> Edit[单行名称草稿]
    Edit --> Submit[提交稳定 ID 与新名称]
    Submit --> Record[追加名称变更记录]
    Record --> Summary[更新可重建摘要]
    Summary --> Receipt[名称变更回执]
    Receipt --> UI[列表与当前标题同步]
```

## 名称不是路径或消息

进入编辑时固定目标 Session ID，并独立保存名称草稿。提交非空、适合单行显示的名称，保留中文和正常标点；处理换行等标题输入时只影响名称字段，不改原用户消息。清空或纯空白应显示校验错误，而不是生成无名目录。

同名会话允许存在，仍由不同 ID 区分。斜杠、反斜杠、引号和看似路径的字符串也只能作为名称处理，不能参与磁盘路径解析。存档目录保持原 UUID，附件引用完全不变。

名称变更进入权威会话记录，随后更新 summary.json。已有手动名称标记保留，后续用户消息不再用第一句话覆盖它。重命名不是对话活动，不更新最后活动时间，不导致条目跳到顶部。

## 保存与取消使用真实结果

确认发出后保留目标身份和操作身份，未收到成功回执不先提交 UI 名称。取消编辑不写记录；保存失败保留旧名称和输入草稿，显示具体原因。日志已提交而摘要更新失败时，以权威记录为准修复摘要，不重复追加同一次名称变更，也不误报内容完全未保存。

列表发生重排或用户打开了另一会话后，回执仍更新原目标。若原目标已被其他受控操作删除，重命名按实际存在性拒绝，不能创建一个同名替代 Session。当前打开的目标更新右侧标题；其他目标不改变当前聊天。

名称操作与任务记录经过同一写入者，记录顺序不会与活动工具结果发生冲突。它不触碰可写 ProtocolHistory，也不夺取 Runner 的执行权。工具仍运行时重命名只允许改变目录摘要和名称业务状态，不重建活动记录或影响停止入口。

## 文本编辑沿用当前交互

更多操作通过现有公开按钮和 BSN 内容组合显示，本增量只展示重命名。文本编辑复用 Widgetry TextField 的公开正文接口和焦点行为；取消、确认和错误区域按已有确认交互放置，不新建通用窗口框架。

编辑草稿与聊天草稿分开。打开和关闭编辑器不清空正在撰写的消息；按 Enter 的确认行为不能同时发送聊天。中文 IME 提交候选时不提前确认名称。列表虚拟行复用后，编辑目标仍然是稳定 ID。

## 验证名字变化不会改变会话内容

通过 BRP 实际点击更多操作，输入中文名称、长名称及含路径字符的名称，确认列表、当前标题和重新打开后的名称一致，物理目录未移动。建立两个同名会话，选择与后续操作仍能区分。

分别验证取消、空白输入和真实写入失败：原名称、活动时间、聊天草稿及消息内容保持正确；已提交记录与落后摘要的恢复不产生二次重命名。普通对话继续后手动名称不被覆盖，也没有额外模型调用。

在列表重排、滚动复用行和切换当前会话时完成名称提交，核对回执目标。工具运行期间重命名不取消任务，结果记录继续进入原 Session，Stop 不受编辑弹层错误禁用。

中文输入法使用实机补充检查；BRP 特殊键采用已知问题允许的完整 KeyboardInput 消息路径，不能修改编辑器 ECS 状态。截图和安全投影共同核对，结束释放 Pointer。运行于现有 Windows x64 与锁定依赖，执行受影响的静态检查，不创建测试代码、Benchmark 或 Example，不改变登录状态。
