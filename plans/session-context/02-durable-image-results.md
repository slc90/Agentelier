# 保存图片工具实际返回的不可变载荷

本增量让 view_image 的真实结果可以脱离原始项目文件保存。单独保存路径或工具卡片文字，会在源图片改动后恢复出另一份内容；因此这里保存模型当时实际收到的编码载荷，而不是以后重新读图。

```mermaid
flowchart LR
    Tool[view_image 实际结果] --> Payload[不可变 ImagePayload]
    Payload --> File[会话附件文件]
    File --> Check[内容与元数据核对]
    Check --> Ref[可提交的持久附件引用]
    Ref --> Record[类型化图片结果记录]
    Record --> Read[受控读取并还原载荷]
```

## 保存的是发送后的图片

沿用 Tools 已有的解码、方向处理、缩放和编码结果。持久载荷保存真实 MIME、发送尺寸、编码字节数及发送内容 SHA-256；原始路径、源尺寸和来源摘要作为执行说明保留，不作为恢复时必须重新打开的文件地址。

附件位于 `sessions/<id>/attachments/`，文件名由发送内容摘要等受控信息生成。先写入临时文件、完成内容确认和替换提交，再返回可以被会话记录引用的附件身份。引用不能抢在文件提交前进入权威日志，否则一次崩溃会留下看似完整、实际缺图的工具结果。

同会话的相同载荷可以复用。发现目标摘要文件已存在时，要核对实际内容而不是只相信文件名；不匹配是存储错误，不覆盖成“缓存命中”。不新增跨会话全局附件仓库或引用计数体系，这样删除一份会话不会触及另一份会话的图片。

## 类型和展示继续分开

ProtocolHistory 中的文字结果与图片结果保留原来的类型差别。持久引用经受控解码恢复 ImagePayload，下一次请求仍由 LLM Model 构造 input_text/input_image 内容数组和正确 MIME 的 data URL，不二次编码成普通 JSON 字符串。

UI 只取得路径说明、格式、尺寸、摘要及字节数等既有安全投影。图片字节、Base64 和加密协议正文不进入 ECS 反射或日志；不能通过 UI 卡片输出反推真实载荷。

引用只允许指向当前 Session 的附件范围，核对规范路径和实际文件归属，不能借绝对路径、上级路径或重解析目标读写其他目录。读取时检查摘要、长度、格式和尺寸，失败明确作用于该会话，不回到源路径取一张替代图，也不静默将图片结果降级为文字成功。

## 边界不会因持久化扩大

单图的原始读取、像素、发送边长和编码预算沿用现有工具契约，不为“存档”放开输入限额。当前累计 16 MiB 的图片预算在工作上下文中继续生效；完整存档保留的旧附件可以多于当前窗口实际携带的附件。压缩从工作窗口移除旧图时，不删除其磁盘记录。

完整请求仍受 32 MiB 序列化上限约束。磁盘上能保存图片，不表示图片可以无条件再次装入模型请求；多模态能力、活跃图片预算和请求字节预算分别检查。

附件写失败发生在工具已经读图之后，要保留读图事实和实际错误，不能宣称工具从未读取。未提交的临时文件由本次写入收尾；清理失败报告实际路径，不扩大到清理整个项目或数据根。持久附件引用只在提交成功后形成。

## 真实源文件变化验证

在实际应用中读取一张允许的 PNG 或 JPEG，核对保存的附件与 ImagePayload 的发送摘要、格式和尺寸一致。对同一张图再调用一次，确认同会话可以复用同载荷，不重复产生不同内容的引用。

使用本次验证专门准备的源图片，读取后移动或替换源文件，通过实际会话附件读取路径重新构造载荷，确认恢复的是原发送内容。这里验证附件 round-trip，不宣称尚未接入的完整会话恢复已经完成。

在真实应用的文件读取或提交边界注入缺失、写入失败和摘要不符，检查返回具体错误而不读取原路径兜底。确认未把完整 Base64 写进日志或安全投影。工具卡片受影响的可见内容用 BRP 截图和状态核对；不直接修改编辑器或业务状态充当用户调用。

实现位于 Tools 的载荷契约、LLM Model 的协议表示和 Session Store 的文件机制之间，不能让 Store 调用模型或让 UI 拥有附件真值。新增依赖只服务实际能力并由 Workspace 管理，继续 Windows x64 与锁定的依赖组合。验证使用真实应用和适用静态检查，不编写测试、Benchmark、Example 或模拟模型服务；保护现有登录。

同步会话、图片结果和存储设计中受影响的事实。前置为[稳定会话存档](01-stable-session-archive.md)；下一增量[记录任务历史](03-record-task-history.md)使用这里已经可持久引用的图片结果。
