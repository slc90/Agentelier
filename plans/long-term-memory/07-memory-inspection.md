# 在现有界面查看长期记忆

本增量让用户直接看到长期记忆当前保存了什么，并核对记忆来源和最近整理状态。它提供一个足够轻的只读入口，不把长期记忆改造成需要用户逐条维护的资料库。完成后，应用能够清楚区分“当前没有记忆”“有已发布记忆”“正在整理”和“读取失败”。

## 从已发布记忆生成安全的展示数据

Memory 的存储仍位于本次选定的数据目录；UI 不读取数据库或扫描 Markdown 目录。用户通过聊天界面的记忆入口发出查看请求，AgentHost/Bridge 交给 Runtime，Runtime 再通过 Memory 的只读接口取得当前**已发布**的摘要及来源定位信息。返回给 UI 的是受控展示投影，不是 SQLite 连接或可以任意修改的磁盘句柄。

```mermaid
flowchart LR
    U["用户打开记忆入口"] --> UI["chat_ui：只读展示"]
    UI --> B["Bridge / AgentHost：命令与安全投影"]
    B --> R["Runtime：操作关联"]
    R --> M["Memory：已发布摘要及来源"]
    M --> R
    R --> B
    B --> UI
```

摘要正文可以展示当前已确定的用户工作偏好、项目线索和历史任务指针。来源信息允许用户继续查看一份受控的 `rollout_summaries/` 记录，明确其 Session ID、工作目录和相应历史时间/状态。涉及当前项目事实时，界面只显示“记忆记录了什么”，不宣称过去的结论已经在当前代码中重新验证。

## 界面不成为记忆的新所有者

`chat_ui` 使用现有 BSN 与 Widgetry 公开控件展示只读文本和来源列表；运行时的打开状态、滚动与展开位置属于 ECS 界面状态，而 Memory 仍然决定数据是否存在、是否可读和处于哪个发布状态。页面关闭或重开时不能使后台提取/整合任务取消。无需为这项功能创建独立的全屏记忆管理应用、逐条编辑器或任何版本与启停开关。

查看请求的回执带既有 operation ID，UI 只接纳与当前打开状态对应的结果。第一次打开、随后刷新、快速切换会话或重复打开时，迟到结果不能覆盖更新的查看状态。内容太长时采用合理的只读滚动与展开，详细记录按用户选择取得，而不是把所有文件一次性塞入 ECS。敏感的 Token、原始会话全文、加密 reasoning 与后台内部事务状态不能进入可反射的展示结构。

## 解释空状态与后台处理中状态

全局整合尚未产生摘要时，展示正常的空记忆说明；后台提取已有结果但尚未整合时，可以展示正在整理，不能把提取中间结果伪装为已发布摘要。若后台整合正在更新另一版摘要，仍显示上一次成功发布的材料和真实的处理状态。文件缺失或读取失败作为独立错误展示，不要把失败当成“用户没有记忆”。

本增量只增加查看能力，当前已有记忆的使用、自动提取、整合与用户修订机制继续运行。查看历史不自动修改记忆；专门的详细读取使用反馈仍由此前的 Memory 受控查询行为决定，不能因为打开一个空面板而把所有来源标为已使用。

## 完成后的可观察结果

在真实应用中分别准备有已发布记忆、无记忆、正在整理和读取失败的状态；通过 BRP 打开记忆入口，检查对应文本、来源展开、刷新后的状态和错误提示。检查只读内容可滚动、选择与复制，但用户不能通过这个入口直接修改生成文件；切换会话后已结束的查看请求不能覆盖新的显示。

通过实际截图、必要的 ECS 状态和后台日志核对 UI 与 Memory 读结果的一致性。BRP 自动输入需使用现有 `bevy_brp_mcp`，完成后释放 Custom Pointer 并确认 `inactive`。同一增量完成适用 Cargo 格式、构建和 Clippy 检查；不新增测试、Benchmark、Example 或专用测试宿主。界面及 Bridge 的实际职责变化同步到相关设计文档。

重置记忆涉及清理文件和阻止旧历史重新生成，属于下一独立增量；本次查看操作不包含重置行为。
