# 05：让后续追问使用完整有效历史

本增量解除首轮交互的限制，让同一个 Session 连续执行多个 Turn。下一次请求的上下文由执行侧构造，而不是从 UI 文本读取。

## 历史的两个用途

Conversation 分别保存展示记录与已提交协议历史。展示记录用于回看所有尝试，包含失败与部分回复；协议历史用于下一轮，只包含完整成功的输入与输出。

一轮成功时，将这轮用户输入与完整模型输出一次性提交。失败或取消不提交这一对内容，UI 状态文字也不进入历史。后续请求由已提交历史和当前输入组成，模型和推理强度沿用 Session 固定设置，继续采用 store=false，不依赖服务端恢复会话。

## 协议内容不能退化为文字拼接

LLM Model 返回适合后续回传的类型化输出项。保留顺序、角色、标识和适用的 phase，包括公开 commentary 与 final_answer 的区别。不要把所有 output_text 拼成一条无阶段助手消息后丢弃其余数据。

对于所选模型与接口需要的无状态推理续接，按官方协议请求并回传加密 reasoning 项。它们作为不透明数据保存，不展示、翻译或写进日志。UI 只接收安全的正文与状态投影。

本阶段没有工具执行循环，不能通过伪造工具结果完成历史。合法拒绝内容照常作为完整回答处理，空文本完成只显示状态。未知输出必须按协议类别明确处理，不以静默丢弃掩盖问题。

## 连续提交的门槛

执行所有者确认上一轮终态并回收任务后才能接纳下一轮。生成期间不排队、不并行发送。每次请求捕获同一 Session 的设置与历史快照，目录刷新或准备区修改模型与推理选项不能改变在途请求。

上下文超限时明确失败并保留记录，不自动压缩、删旧消息或截短用户输入。身份变化后旧 Session 不可继续提交；正常凭据续期保持会话。

## 完成与验证

通过真实应用连续交流十几轮，包含指代前文、修订前文和整理文档。用安全运行状态核对历史项数量与顺序，确认用户、助手和非展示协议项没有重复。错误消息不出现在下一轮模型输入中。

通过 BRP 输入并观察 UI，静态检查覆盖 Conversation、LLM Model、Runtime 和 Bridge 的变化。当前无法真实触发的上下文超限或特定模型字段路径应如实记录，不编写模拟测试或 Example。同步已实现行为文档，保护登录和凭据。
