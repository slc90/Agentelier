# 03：把推理强度变成明确的请求设置

本增量给已有模型准备区增加推理选择，并保证界面选项与实际请求一致。它不根据模型名称猜测支持范围。

## 能力来自所选模型

LLM Model 保留目录中提供的 supported reasoning levels 与默认值。UI 在选择模型后更新对应选项；没有这类元数据时只显示“服务默认”，发送请求时省略 effort。

可用默认值解析为明确的选择。用户手动选择后，生成请求使用所选值；服务拒绝该值时返回原始错误，不悄悄降档。切换模型后重新校验选项，旧模型的档位不能泄漏给新模型。

能力标识与显示文案分开，既不把中文标签发给服务，也不硬编码全局 low/medium/high 列表。当前接口无法提供有效能力信息时，本增量仍能以默认模式工作，但必须让用户看见这一事实。

## 改动边界

协议参数与能力数据留在 agent/llm_model，UI 投影在 bridge/llm_model，准备区在 ui/chat_ui。与模型选择共享一次设置读取，不新增独立 Runtime 或账号缓存。

此时设置作用于模型验证；后续创建 Session 时复制同一份设置语义。不要提前实现中途切换推理档位。

## 完成与验证

通过真实应用选择支持的档位并完成请求，核对请求配置的非敏感投影。检查默认模式确实省略 effort；能获得不同能力模型时检查切换后的选项刷新。未知与不支持场景如果没有真实来源，不宣称已经验证。

BRP 验证下拉交互、禁用状态和错误显示，编译与静态检查覆盖修改范围。按现有规范记录实际结果、同步模型设置文档，不编写测试代码、Benchmark 或 Example，不改变登录状态。
