# 09：把 Markdown 正文显示为原生 UI

本增量先解决段落类阅读，让助手回复中的标题、强调、引用和链接有正确的视觉层次。它不引入浏览器或另一套 UI 框架。

## 解析与展示各负责一层

新增 `crates/ui/markdown/`，采用 pulldown-cmark 的官方版本解析事件，再转换为原生 Bevy 与 Widgetry 组合内容。依赖在根 Workspace 统一管理。解析器只理解结构，字体、布局、主题和交互由展示适配层负责。

UI 层原始 Markdown 字符串始终保留，不能把渲染后的文本写回 Session。初始结构与新增块使用 BSN、Scene/SceneList；持续更新通过组件和公开操作维护，不搭建另一套 spawn/with_children UI 构造体系。

## 本增量的语法范围

支持段落、软硬换行、标题、粗体、斜体、删除线、行内代码、引用、分隔线和链接。尚未实现的列表、表格和围栏代码保留可读原文，不能直接消失。HTML 显示为文本，图片显示替代文字和目标信息，不自动请求远端资源。

链接只在用户主动操作时打开 HTTP/HTTPS 地址，通过现有应用辅助任务方式调用系统能力。其它目标保留文本，不执行命令或自定义 URI。

## 流式更新保持内容与阅读位置

一帧内合并当前消息的文本变化，再整体解析这条活动消息。后续文本可能改变早先引用解释，因此不假定只解析尾部必然正确。完成消息不重复解析；更新尽量复用稳定块，不重建输入框和所有历史。

用户在底部时保持跟随，向上浏览后停止自动拉动，提供回到底部入口。切换设置页再回来保持运行消息。最终结果校准后重新解析一次。

## 完成与验证

在真实聊天中观察中文长段落、标题与强调、未闭合标记、引用链接和 HTML 文本。用 BRP 滚动历史并等待新片段，确认不会被强行拉回或丢焦点；操作链接只打开实际允许的目标。

执行静态检查与真实布局检查，明确记录无法覆盖的原生操作。更新 Markdown 能力及新 crate 架构文档。遵守 Windows x64、BSN、Widgetry 公共 API、无测试/Benchmark/Example 和登录保护要求。
