# 06：停止正在生成的回复

本增量增加用户可操作的停止入口。停止结束当前 Turn，不清空 Session，也不把已经显示的半截回复变成成功记录。

## 取消走独立控制路径

聊天界面发出停止请求后显示“正在停止”。Connection 与 Runtime 将操作关联到指定 Session/Turn，不能以停止当前任意模型任务替代身份检查。控制请求不等待正文队列腾出空间。

LLM Model 请求任务在网络读取、凭据等待和增量发送等待期间都能结束等待。Account 已经开始的凭据旋转和必要持久化独立继续，取消聊天不能丢弃这项提交。

## 终态只由执行所有者确认

停止请求不等于取消完成。Runtime 确认任务结束与回收后发布 Cancelled，UI 才恢复发送。此前显示的文本保留在对应尝试下，标记未完成且未进入下一轮上下文。

正常完成与取消同时到达时，按执行侧已确认结果发布唯一终态。不能先取消成功后再次完成，也不能让旧增量覆盖下一轮。成功已经确认时，迟来的停止不回滚已经提交的历史。

## 与现有退出链共存

停止一个 Turn 与关闭应用、退出账号保持不同含义。普通停止保留认证与当前聊天；普通关闭保留账号；用户主动退出账号沿用既有优先控制和撤销流程。不要为新的停止按钮另建 Task、认证缓存或线程。

## 完成与验证

通过 BRP 在长回答期间点击停止，观察按钮进入停止中、部分正文保留、任务回收、终态和发送恢复。随后发送一个新问题，确认未完成内容没有进入协议历史。

还要在界面翻阅历史时停止，检查高频文本不会让控制请求失效。完成边界竞争只能依据实际观察记录结果，不能把静态检查写成并发行为已验证。验证普通关闭而不擅自退出账号。

执行受影响范围静态检查、实际运行与文档同步，维护进度记录。遵守有界通道和真实错误传播，不新增测试代码、Benchmark 或 Example。
