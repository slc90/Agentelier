# 02：选择用于请求的模型

本增量让用户明确指定模型，不再依赖目录中的第一个条目。它交付可以实际调用的模型选择，而不是只有一个没有接入请求的下拉框。

## 已有条件

共享 UI 宿主已经接管连接。现有 LLM Model 能通过当前账号读取目录并完成一次独立连接验证。保留当前已经使用的认证与接口契约，不在本增量替换登录方式或服务端点。

## 从目录到一次验证

LLM Model 将模型目录读取与生成请求分开，向上提供模型 slug、显示名称和可用能力元数据。新增 `crates/ui/chat_ui/` 的准备区，通过共享宿主获取目录。Account 仍是凭据的唯一来源。

用户在准备区选择条目后，使用该 slug 发起简短验证请求，并在结果中展示实际使用的模型。目录刷新和选择都是显式动作，刷新不静默把一个已经选择的模型换成首项。

若所选条目消失或账号不可用，显示实际失败并保留可识别的选择状态。目录没有可用模型时禁用验证操作，不能用硬编码模型兜底。

模型目录与验证事件通过 `bridge/llm_model` 转换，Connection 继续只做关联与分发。准备区的模型列表不放进 login_ui，application 只装配页面。

## UI 与状态

使用 Widgetry 选择控件、按钮和状态文本，结构由 BSN 声明。目录读取中、读取失败、已选中与验证中分开表达。等待期间不阻塞 Winit，不增加第二套网络 Job。

## 完成与验证

在真实界面选择一个可用模型并验证，确认执行侧使用的 slug 与 UI 选择一致。账号目录提供多个条目时检查切换选择；只有一个条目时如实记录范围，不伪造多模型验证。检查刷新失败不会变成空白成功，也不会擅自改变选择。

执行受影响范围的编译、格式与 Clippy，使用 BRP 的真实点击、焦点与状态查询验证新控件。日志只记录模型标识和结果，不记录 Token 或完整回复。同步模型功能与架构文档，维护进度记录，不新增测试、Benchmark 或 Example。
