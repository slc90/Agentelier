# 交付设置窗口并连接原子配置

## 目标

完成设置窗口的常规设置与默认 Session 设置，连接现有 `ConfigStore`。头像和布局比例作为后续独立设置增量加入同一个设置窗口。

## 设置内容

首批设置分为两组：

| 分组 | 设置项 | 默认 / 生效方式 |
|---|---|---|
| 常规 | 应用数据目录 | 显示当前目录；更改下次启动生效 |
| 常规 | UI Scale | 默认 1.25；保存成功后立即生效 |
| 默认会话 | 默认模型 | `gpt-6.2-sol`；只影响新 Session |
| 默认会话 | 默认推理强度 | `high`；只影响新 Session |

默认工作目录不放在全局设置。Project 内 Session 默认继承 Project 目录；单独聊天由 Session 创建准备阶段指定。

应用数据目录沿用现有数据环境语义：更改只影响下次启动，不迁移当前目录文件、不切换当前 Runtime 的数据环境。模型与推理强度只影响新 Session，已有 Session 不因默认值变化而修改。

## 配置保存

配置文件继续使用程序目录下 `config/config.ron`。所有设置通过 Application 的 `ConfigStore` 原子保存：基于最新完整配置生成候选值、校验、写同目录临时文件、同步并替换目标文件；替换成功后才更新内存配置。保存失败保留旧配置并显示错误。多个设置更新串行合并，不使用过期快照覆盖其他字段。

## Widgetry 复用

Window、FileDialog、ComboBox / Segmented、Text、ReadOnlyTextField 和 AgentelierButton。

## 工程边界

- 依赖方向保持 `ui → agent / bridge`、`bridge → agent`；Agent 不依赖 Bevy、UI 或 Bridge，Bridge 不拥有 Agent 业务状态。
- UI 使用 BSN、Scene 和 SceneList 构造与组合；Props 只初始化，运行状态由持久 Component / Resource 管理。
- 复用 `bevy_widgetry` 公开 API，不修改 Widgetry 上游、不访问其私有状态。
- 目标环境沿用 Windows x64、DX12 和 PowerShell 7。
- 不新增 Unit Test、Integration Test、Regression Test、Benchmark 或 Example 代码。GUI 行为使用真实应用和 BRP 验证；原生窗口行为在实际 Windows 窗口中观察。
## 完成条件与验收

1. 点击 B 区设置按钮打开设置窗口，关闭后主窗口 Session 和任务状态不变。
2. 设置窗口首批只出现应用数据目录、UI Scale、默认模型和默认推理强度。
3. 不出现默认工作目录、提示词编辑、任务控制或 Skill / MCP 配置副本。
4. 应用数据目录显示当前真实使用的目录；选择新目录后显示下次启动使用的路径。
5. 取消 FileDialog 不改变目录配置。
6. 更改数据目录后，当前运行中的 Session、Memory、MCP 和凭据仍使用当前数据环境；重启后才使用新目录。
7. UI Scale 显示当前配置；保存合法档位后主窗口与辅助窗口立即更新。
8. UI Scale 保存失败时，控件恢复到最后一次成功保存值。
9. 默认模型列表来自当前模型目录；默认值为 `gpt-6.2-sol`。
10. 默认推理强度默认 `high`，选项遵循当前模型目录支持的 reasoning levels。
11. 当前模型不支持 `high` 时显示校验错误，不静默降低档位。
12. 修改默认模型或推理强度后，新 Session 使用新值，已有 Session 保持原值。
13. 快速连续修改多个字段时，ConfigStore 合并完整配置，不丢失已成功保存的其他字段。
14. 文件不可写、临时文件失败或替换失败时，显示错误并保留旧配置。
15. 关闭再打开设置窗口后，显示已提交配置，不把未保存草稿当作当前值。
16. UI Scale、ComboBox、FileDialog 和错误状态使用 BRP 实际操作验收；数据目录和 Session 默认值通过真实重启验证。
17. 路径显示不出现 `\\?\` 前缀，文件操作使用原始 PathBuf。
