# 使用 Widgetry Window 展示任务终态通知

## 目标

当后台任务成功、失败或需要用户操作时，显示小型非阻塞通知。通知复用 Widgetry 自定义 Window，不另建底层原生窗口系统。

## 触发条件

只在以下状态变化时产生通知：

- **成功：**Agent 确认任务成功终态。
- **失败：**Agent 确认任务失败终态。
- **需要用户操作：**任务进入明确等待用户审批、确认或补充输入的状态。

普通运行、排队、等待资源和取消过程不弹通知。取消请求不等于取消终态。通知文案必须对应真实 Agent 状态。

成功任务从 E 移除仍要求结果已交付；成功通知与 E 的可见性规则分别消费同一份任务事实。通知可以在成功终态确认后出现，而 E 在交付完成前仍显示该任务。

## 窗口行为

TaskToast 使用 Widgetry `owned_widgetry_window` / 自定义 Window，以非模态方式显示。内容包含所属 Session、任务名称和状态。最长显示 5 秒，用户可以手动关闭。关闭通知只关闭窗口，不改变任务。

多个通知同时到达时依次排列，避免相互覆盖；同一 Task ID 的同一终态只通知一次。应用恢复时重新读到的历史终态不重新弹出通知。

## 工程边界

- 依赖方向保持 `ui → agent / bridge`、`bridge → agent`；Agent 不依赖 Bevy、UI 或 Bridge，Bridge 不拥有 Agent 业务状态。
- UI 使用 BSN、Scene 和 SceneList 构造与组合；Props 只初始化，运行状态由持久 Component / Resource 管理。
- 复用 `bevy_widgetry` 公开 API，不修改 Widgetry 上游、不访问其私有状态。
- 目标环境沿用 Windows x64、DX12 和 PowerShell 7。
- 不新增 Unit Test、Integration Test、Regression Test、Benchmark 或 Example 代码。GUI 行为使用真实应用和 BRP 验证；原生窗口行为在实际 Windows 窗口中观察。
## 完成条件与验收

1. 任务进入成功终态时弹出成功通知，内容中的 Session、任务名称和状态正确。
2. 任务进入失败终态时弹出失败通知，内容与真实错误状态一致。
3. 任务进入明确需要用户操作状态时弹出通知。
4. 普通运行、排队、等待资源和取消中不弹通知。
5. 取消请求后任务仍运行时，不显示“已取消”；只有真实终态确认后才更新 E。
6. 成功但结果尚未交付时，通知准确描述执行成功；E 仍保留任务直到交付。
7. 通知是非模态窗口，显示期间主窗口仍可输入、滚动、切换 Session 和打开其他窗口。
8. 通知最长显示 5 秒，到时自动关闭；点击关闭按钮可以提前关闭。
9. 关闭通知不会取消任务、终止进程或改变 Session 状态。
10. 多个任务几乎同时触发通知时，通知依次排列，不互相覆盖、不丢失身份。
11. 同一 Task ID 的重复终态事件不重复弹出通知。
12. 应用重启后恢复的历史终态不重新通知。
13. 窗口关闭、父窗口关闭和应用退出时，通知窗口与计时资源正常回收。
14. 在不同 UI Scale 下检查窗口尺寸、关闭按钮和文字布局。
15. BRP 验收窗口内容、关闭按钮和主窗口非模态输入；5 秒自动关闭及多窗口层级在真实应用 / Windows 窗口中观察。
