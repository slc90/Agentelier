# 持久化主窗口分隔比例并加入布局设置

## 目标

让 C、D、右侧 E/F 的横向比例在重启后恢复，并在主窗口拖动分隔条与设置窗口之间双向同步。

## 比例模型

工作区横向空间由 C、D、E/F 三部分构成。配置保存 C 和右侧 E/F 相对于整个可分配工作区的归一化比例，D 占剩余比例。

以初始窗口 1920px、B 区 64px、C 区 280px、右侧区域 360px 为基准：

- C：约 15.1%。
- D：约 65.5%。
- E/F：约 19.4%。

两条 Widgetry Splitter 的实际分割比例由这三个宽度比例换算。窗口大小变化时保持比例；区域最小宽度约束优先，空间足够时恢复保存比例。

E/F 高度固定 50:50，不存储第三个比例，也不在设置窗口提供 E/F 比例控件。

## 主窗口与设置窗口双向联动

主窗口拖动分隔条时，拖动期间实时更新布局；拖动结束后保存当前比例。设置窗口增加“布局”区域，提供 C 区比例和右侧区域比例控件，D 自动占剩余空间。设置值变化后主窗口立即应用，保存成功后成为新的持久值。

两种入口共享同一份 `AppConfig`，不各自维护比例副本。保存失败时显示错误，并明确当前运行布局是否已保存；重启恢复最后一次成功保存的比例。

## Widgetry 复用

使用 Widgetry Splitter 的比例与 Pane 最小尺寸能力；设置页使用 Slider / NumberInput 等公开控件。配置更新继续通过 Application `ConfigStore` 原子保存。

## 工程边界

- 依赖方向保持 `ui → agent / bridge`、`bridge → agent`；Agent 不依赖 Bevy、UI 或 Bridge，Bridge 不拥有 Agent 业务状态。
- UI 使用 BSN、Scene 和 SceneList 构造与组合；Props 只初始化，运行状态由持久 Component / Resource 管理。
- 复用 `bevy_widgetry` 公开 API，不修改 Widgetry 上游、不访问其私有状态。
- 目标环境沿用 Windows x64、DX12 和 PowerShell 7。
- 不新增 Unit Test、Integration Test、Regression Test、Benchmark 或 Example 代码。GUI 行为使用真实应用和 BRP 验证；原生窗口行为在实际 Windows 窗口中观察。
## 完成条件与验收

1. 首次启动使用 C 约 15.1%、D 约 65.5%、E/F 约 19.4% 的初始比例。
2. 拖动 C/D 分隔条后，C 与其余区域的比例按新位置变化。
3. 拖动 D/E-F 分隔条后，D 与右侧区域的比例按新位置变化。
4. 拖动结束后比例保存到配置；重启后恢复上次成功保存的比例。
5. 设置窗口显示 C 和右侧区域比例，D 自动占剩余空间。
6. 设置窗口调整比例后，主窗口立即同步变化；再次拖动分隔条后设置值同步更新。
7. 配置保存时基于最新完整配置更新，不覆盖默认模型、头像或其他设置。
8. C 最小 220px、D 最小 640px、E/F 整体最小 320px；比例值不能使布局突破最小宽度。
9. 窗口临时缩小时，运行布局受最小宽度约束；窗口恢复后回到持久化比例。
10. E/F 始终 50:50，不因设置或横向拖动改变。
11. 配置缺少比例字段时使用初始默认比例；非法、NaN、无穷或总比例超限时拒绝并回退默认值。
12. 保存失败时不把新比例标记为已持久化；重启恢复最后一次成功保存值。
13. UI Scale 1.0、1.25、1.5、2.0 下检查 Slider、Splitter、最小宽度和拖动命中。
14. 使用 BRP 实际拖动两条分隔条并操作设置控件；通过重启确认比例持久化。
