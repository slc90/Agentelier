# 建立 A–F 主窗口与可调整工作区布局

## 目标

交付主窗口新的 A–F 空间结构、标题栏、导航栏和工作区分隔布局。新结构以已确定的区域职责为准，不沿用临时 UI 的旧固定侧栏组织。

## 窗口与固定区域

主窗口初始尺寸为 1920 × 1080，在默认显示器居中；UI Scale 从配置读取，默认 1.25。沿用当前程序的窗口尺寸与 Ui Scale 行为，不额外引入另一套尺寸换算。

A 高 40px，B 宽 64px，二者不参与工作区比例调整。标题栏右侧只放最小化和关闭按钮；不显示最大化按钮，双击标题栏不最大化或还原。标题栏空白可拖动窗口，原生窗口边缘继续支持 Resize。

A 为全局状态展示槽，首批预留账号额度和当前 Session 上下文使用量。B 从上到下放置登录、设置、Skill、MCP、记忆管理五个圆形纯图标按钮，统一使用 AgentelierButton。

## 工作区分隔

使用嵌套 `WidgetrySplitter`：

- C / D 之间一条可拖动竖向分隔条。
- D / E-F 之间一条可拖动竖向分隔条。
- E / F 固定 50:50 平分右侧高度，不允许拖动。

初始 C 宽 280px，最小 220px；D 最小 640px；E/F 右侧整体初始宽 360px，最小 320px。分隔条可见线纤细，命中区域足够宽。窗口最小宽度由 B、C、D、E/F 的最小宽度和分隔条共同约束。

分隔比例本增量先使用默认初始值；持久化和设置页双向联动由单独的布局设置增量交付。

F 只建立空白占位，不放助手形象或其他内容。

## Widgetry 复用

Window、Splitter、Ui Scale、AgentelierButton / Avatar 和 Theme / ColorOverrides。

## 工程边界

- 依赖方向保持 `ui → agent / bridge`、`bridge → agent`；Agent 不依赖 Bevy、UI 或 Bridge，Bridge 不拥有 Agent 业务状态。
- UI 使用 BSN、Scene 和 SceneList 构造与组合；Props 只初始化，运行状态由持久 Component / Resource 管理。
- 复用 `bevy_widgetry` 公开 API，不修改 Widgetry 上游、不访问其私有状态。
- 目标环境沿用 Windows x64、DX12 和 PowerShell 7。
- 不新增 Unit Test、Integration Test、Regression Test、Benchmark 或 Example 代码。GUI 行为使用真实应用和 BRP 验证；原生窗口行为在实际 Windows 窗口中观察。
- 未经用户明确授权，不执行登出、重新授权、切换账号或清理现有凭据的验收操作。
## 完成条件与验收

1. 应用启动后显示新的 A–F 主窗口，不再显示旧临时侧栏和旧页面布局。
2. 初始窗口尺寸为 1920 × 1080，并在默认显示器居中。
3. UI Scale 默认 1.25，读取配置中的实际值；不在本增量另行改变现有缩放语义。
4. A 高度保持 40px，B 宽度保持 64px。
5. C 初始宽度为 280px，最小宽度为 220px；D 最小宽度为 640px；E/F 整体初始宽 360px、最小宽 320px。
6. 拖动 C/D 分隔条只改变 C 和剩余区域；拖动 D/E-F 分隔条只改变 D 与右侧区域。
7. C、D 或 E/F 达到最小宽度后，分隔条不能继续向该方向压缩。
8. E/F 始终平分右侧高度，不出现可拖动的第三条分隔条。
9. 可见分隔线纤细，鼠标命中区域足够宽；拖动期间没有明显闪烁、覆盖或布局跳变。
10. 标题栏空白区域能拖动窗口；双击标题栏不最大化/还原。
11. 右侧只显示最小化和关闭按钮；原生窗口边缘仍能 Resize。
12. A 区上下文显示槽跟随当前 Session，B 区五个按钮顺序和纯图标样式正确。
13. F 保持空白占位。
14. 在 UI Scale 1.0、1.25、1.5、2.0 下检查标题栏、导航按钮、分隔条和最小宽度。
15. 使用 BRP 实际拖动两条 Splitter，结合截图和 ECS 状态确认布局；标题栏拖动、双击和原生 Resize 在真实 Windows 窗口中观察，不用 BRP Custom Pointer 冒充 OS 输入。
16. BRP 验收后释放 Pointer 并确认状态为 inactive。
