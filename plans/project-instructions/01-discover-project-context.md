# 发现并展示会话适用的项目规则

本增量完成一件事：从会话的工作目录发现适用的 `AGENTS.md`，取得有来源、范围和完整正文的项目快照，并让结果能够在真实应用中核对。采集和错误处理由执行侧负责，界面只展示结果。

本步先把“读到了什么”做实，尚不把新内容加入模型请求。后续的[项目指令注入](02-inject-project-instructions.md)使用这里形成的同一份快照与确定性表示，不另写一条文件读取路径。完整范围依据见[文件发现设计](../../docs/design/project-instructions/01-loading-scope.md)。

```mermaid
flowchart LR
    W["SessionSettings：固定工作目录"] --> R["Runner：首次请求准备"]
    R --> P["Project Context：发现、读取与快照"]
    P --> C["ActiveTurn：采集结果"]
    C --> B["Conversation Bridge：只读投影"]
    B --> U["现有核对入口：目录、来源与正文"]
```

## 项目范围从会话目录开始

当前会话的 `working_directory` 已在创建时校验并固定。本增量直接使用这个路径值，不重新读取应用进程的 cwd，也不根据聊天文字猜项目目录。某次 Shell 的 `workdir` 或 PowerShell 内部的目录变化只影响那次工具执行，不改变自动规则链。

从会话目录向上寻找最近一个 `.git` 标记。标记可以是文件或目录，以支持普通仓库和 worktree；不执行 Git 命令，也不解析标记内容。找到后，该目录就是本次发现的项目边界。没有标记时只检查会话目录，不把其他父目录、磁盘根、`Cargo.toml` 或 `package.json` 当作项目根。

沿项目根到会话目录逐层收集 `AGENTS.md`，顺序固定为父目录在前、子目录在后。每份文件保留自己的作用目录；子目录规则只作用于相应子树，不在加载阶段删除父规则或逐句计算覆盖关系。

例如会话目录为 `C:/work/game/src/ui`，最近标记为 `C:/work/game/.git`，预期自动链是根目录、`src`、`src/ui` 下存在的 `AGENTS.md`。`C:/work/AGENTS.md` 位于边界之外，`src/backend/AGENTS.md` 属于兄弟分支，`src/ui/panels/AGENTS.md` 位于当前目录之下，三者均不自动加载。

会话从项目根启动时，只自动加载根目录规则。模型后来操作 UI 文件，不会让客户端推测并切换到 UI 规则链；下级规则可以由模型通过已有工具按需阅读。这类读取属于工具历史，来源核对不能标成自动发现。

## 快照保留原文，而不是重新编写规则

每个条目保存来源路径、作用目录、完整正文与内容摘要。快照保存会话目录、项目边界、有序条目、确定的模型可见文本及其摘要。模型可见表示包含来源与范围，说明父子规则如何适用，但不概括、润色或补写文件正文。

文件按严格 UTF-8 解码，允许并去掉一个开头的 UTF-8 BOM，其他内容与换行保留。纯空白文件不形成规则正文，但核对投影可以注明对应文件为空。无效编码必须显式失败，不能用替换字符拼成看似有效的规则。

内容相等以原文、范围与顺序的确定性表示为依据。文件修改时间、采集时刻和界面展开状态不参与正文摘要。重新保存相同文本不会改变有效规则身份，也为后续动态刷新提供稳定的比较基础。

Windows 路径读取与比较使用既有规范路径语义，显示时才使用路径显示库。不能用显示文本重新打开文件，也不能用简单字符串前缀判断目录包含关系。源文件按普通文件语义读取链接目标，不因此递归访问目标目录；失效、循环或不可读链接保留实际错误。

## 读取预算和失败结果是一部分功能

当前规则链的源文件原始字节总和上限为 **32 KiB**，集中为内部限制，不增加配置界面。原始字节包括 BOM，读取过程应有界；不能先完整读入超大文件再检查大小。包装文字的最终请求成本由后续请求接入一并计算。

超过预算时返回带来源路径、已用大小和预算的错误，不截取前半份规则继续使用。这个取舍与 Codex 的截断方式不同：这里优先保证发送的是完整规则，长文档可以由根文件导航、再通过工具按需读取。

发现结果区分“未采集”“成功为空”“成功取得规则”和“失败”。找不到文件或读到空文件可以形成空快照；访问错误、目录失效、非普通文件、编码错误和超限不能降级为空。寻找 `.git` 时的读取错误也不能解释成无项目边界。

文件在探测后、打开前消失，可作为此次未发现处理；已经打开后的读取失败必须报告。多份文件依次采集，得到的是这次实际取得的内容；不添加监控服务，不建立跨文件事务。后续刷新增量会在下一请求重新采集。

## 让新职责进入原有所有者关系

增加 `crates/agent/project_context/`，包名为 `agentelier_project_context`。该库拥有边界发现、有界读取、来源快照与确定性表示；不拥有会话、网络、存储线程或提示词版本库，也不为未来预设 Provider 注册表。

Runner 在首次请求准备时调用加载能力，将结果交给独占活动记录的 ActiveTurn。空闲状态仍归 Conversation，Runtime 只负责调度、取消和回收。没有 Bevy 的 Agent 数据经 Conversation Bridge 显式转换，由 Chat UI 保存可重建的只读投影。文件 I/O 不进入 Bevy 主线程，不借 Widgetry JobManager 管理模型任务。

读取失败作为可修复的任务失败返回，不启动该次模型请求。它不是历史损坏，不能因为沿用了某个通用错误分支就永久设置 `execution_blocked`。已经开始的阻塞读取必须在取消和关闭时真实回收；不把丢弃等待 Future 当作任务已结束。

复用现有核对区域显示采集状态、会话目录、边界、来源顺序和原文。此时应明确区分“已加载”和“已加入请求”；本步不会声称模型已经收到规则。UI 使用 BSN 和持久状态，正文使用现有只读文本控件的公开 API，不新增另一套提示词编辑器。

## 完成时能直接验证的行为

在 Windows x64／DX12、PowerShell 7 环境中运行实际应用。用普通临时目录和 Markdown 文件准备输入数据，不编写测试、Benchmark、Example 或专用验证程序。通过现有界面选择目录、新建会话并触发采集，检查执行侧状态与只读展示，而不是让模型口头确认它读到了文件。

需要覆盖这些有区分力的场景：

- 根、中间、当前目录各有规则，项目外、兄弟和下级目录也有同名文件；只有预期链进入快照，顺序、正文和作用范围一致。分别核对 `.git` 文件和目录，以及无标记时仅检查 cwd。
- UTF-8 中文、一个开头 BOM、不同换行、纯空白与无效编码分别得到规定结果；相同正文重新保存后摘要不变。
- 不可读目标、同名目录、失效链接、目录删除与 32 KiB 边界得到明确状态。读取预算按实际原始字节执行，超限没有残缺正文，也没有新模型请求。
- 只改变工具的临时 `workdir` 不改变采集起点。取消不会留下未回收的读取工作，失败后修复输入可以正常再次执行，不需要重置会话。
- GUI 真实操作能够展开、选择和复制正文；切换界面不重建采集权威，也不把加载结果当成用户发送的聊天消息。

GUI 变化使用 `bevy_brp_mcp` 执行真实输入，结合截图及 ECS 只读状态核对；不能直接改 ECS 值代替用户操作。结束时释放 Pointer 并确认 inactive。无法真实覆盖的错误或系统行为在任务进度中保留实际验证边界。

## 本增量保持的工程边界

只识别项目链上的 `AGENTS.md`，不加载全局文件、override、fallback，不实现 Thread Instructions、Skills、MCP 或远端环境；Markdown 链接不自动递归展开。项目正文是模型上下文，不产生工具授权或新的沙箱策略。

Prompts 的基础快照和现有 supplements 不变。默认空配置仍为空，不擅自添加基础文本，也不将项目来源包装为 PromptRef。下一增量才接入实际 user 角色的项目消息。

新增库遵循 Workspace 依赖管理、Windows x64 入口检查和无循环依赖规则；Agent／Bridge 不依赖 Bevy。普通日志只记录身份、来源数量、摘要、大小和错误类别，不输出正文、凭据或不透明模型材料。开发维护临时进度记录，代码注释和提交信息使用英文，按影响同步总体架构与项目上下文职责说明并执行必要格式、编译、Clippy 检查。不通过重登、退出、切账号、重置凭据或切换数据目录制造验证条件。
