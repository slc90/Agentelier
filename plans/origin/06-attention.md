# 记录 Origin 值得继续关注的问题

本增量在现有 Memory 中增加关注记录，让 Origin 能保留真实交流中出现的未决问题。它不启动自动研究，也不创建后台调度器。

## 关注记录

每条关注保存稳定 ID、问题、提出者（用户、Origin、双方或未知）、Origin 表达过的关注理由、来源、范围、最近更新时间和状态。

- `continue`：仍有理由继续。
- `wait`：等待用户材料或相关新证据。
- `end`：已解决或不再值得继续。

每个有效范围最多三个活跃关注。超过时优先保留与新材料关系更强、尚未解决且来源充分的少数问题，其余留作历史。等待时间只是下一次相关交流的参考，不是定时任务或自动行动承诺。

用户委托的任务不自动成为 Origin 的个人愿望。Origin 在真实回答中明确表达的后续兴趣可以成为候选；后台推断必须标注为推断。没有值得关注的内容时允许空结果。

关注只在与当前输入或授权任务明显相关时进入请求材料。用户说今天不聊这个时正常停止；明确要求长期结束时通过现有记忆修订撤下。用户明确邀请 Origin 自己选问题探索时，才在普通 Turn Runner 内选一个有限子问题，使用当前可用资料和授权只读工具。

## 完成条件

- 通过真实聊天产生一条 Origin 明确表达过的关注、一条用户委托任务和一条仅由模型推断的候选，核对主体和证据类型不同。
- 验证继续、等待和结束状态在跨 Session、重启后仍可追溯；结束状态不会因为换日或新 Session 自动恢复。
- 用户说暂时不聊时当前对话自然停止；明确结束后其他话题不再强行拉回。
- 没有自动联网、定时唤醒、通知或平台操作；没有关注时允许空结果。
- 关注只在相关请求中加载，不变成 Developer 命令或工具授权。

## 工程边界

- 目标环境为 Windows x64、`x86_64-pc-windows-msvc`、DX12 与 PowerShell 7；不为未要求的平台增加兼容层。
- 遵守现有 Workspace / Crate 职责和依赖方向。业务实现放在 `crates/`，不在 `app/` 增加业务逻辑；不修改 Bevy、Widgetry、BRP 或 Codex 上游源码。
- 复用 Account、LLM Model、Runtime、Conversation、Session Store、Memory、Project Context、Skills、ToolCatalog 和现有异步任务机制；不建立平行 Agent Registry、任务数据库、记忆数据库或 Skill 管理器。
- 不恢复用户可见的提示词管理页面、Project Skill 或人格工作台。不得通过人格、记忆或 Skill 扩大工具权限。
- 不接入 B 站账号，不执行浏览、评论、私信、上传、直播、定时发布或其他平台运营。
- 未经用户明确授权，不退出登录、不重新登录、不切换账号、不重置凭据，也不通过更换数据目录破坏登录状态。
- 项目禁止新增或修改测试代码、Benchmark 和 Example。按变更范围使用 Cargo 编译、格式、Clippy、真实应用运行、日志/请求/存储状态核对；涉及 GUI 可观察行为时必须使用实际应用和 `bevy_brp_mcp` 验证。
- 不声称未执行的验证已经通过。发现问题在对应功能增量内修复并复验受影响范围，不另设纯验收阶段。
