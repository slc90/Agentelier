# 从已闭合交互提取有来源的长期经历

本增量扩展现有 Memory 来源提取，让有意义的日常交流、Origin 的真实表达和工作结果能够成为长期记忆证据。它不建立第二套聊天历史或记忆数据库。

## 来源选择与闭合条件

由 Session Store 提供已提交且闭合的真实 Turn；Conversation 提供 Session 身份、项目范围、顺序和结果状态。继续遵守现有闲置扫描、来源占有、每轮有界选取、取消与退避、记忆纪元和截止规则。

普通用户对话可以产生用户偏好、共同经历、工作事实、经验线索和注意力线索。只有使用 Origin 身份的新普通 Root Session 才能产生标注为 Origin 的自我观察。旧实验 Session、子 Agent 内部发言、标题任务、记忆管理对话和后台生成内容不作为 Origin 自我经历的直接来源。子任务结果只有在 Root 接收、核对并向用户交付后才按真实工作结果处理。

## 结构化观察

保留现有 `rollout_summary`，并在同一来源提取结果中增加结构化观察。字段语义至少包括记录 ID、类别、主体、作用范围、简洁正文、来源 Session/Turn/输入或结果提交位置、观察时间、证据类型、状态和替代关系。

| 类别 | 示例 |
|---|---|
| 用户偏好 | 用户明确说明日常闲聊不要自动给建议 |
| 共同经历 | 曾一起讨论城市小册子的封面与内页编排 |
| Origin 自我观察 | Origin 曾表示更喜欢雨滴照片的光线层次，并保留其理由 |
| 工作事实 | 某个项目决策已确认，某个文件已实际生成并核对 |
| 经验线索 | 用户反馈解释太早进入实现，后续在另一场景确认适用范围 |
| 注意力线索 | 某个问题仍值得继续，但需要用户提供样张 |

来源证据区分用户原话、Root 已发送的表达、工具观察和模型推断。相同内容来自不同来源可以作为支持证据；同一轮被多次摘要不能算多个独立证据。来源缺失或无法匹配真实提交记录的观察不进入可用集合。

明确的记住、纠正和忘记仍由 `revise_memory` 处理。后台提取不伪造用户修订授权。一个用户随口说「今天不想听建议」只对当前情境有效；助手说过一句话不等于已验证的长期偏好。工具调用存在不等于工具成功，失败、取消和未知结果要保留真实状态。

## 兼容与隐私

`agent/memory` 继续拥有 SQLite、来源占有和完成状态。新结构化字段可缺省，已有合法 `rollout_summary` 保持可用。若补充旧会话，只依据真实历史和来源身份，并优先新闭合来源，避免升级时无界重扫全部历史。

口令、访问令牌和私密认证信息继续按现有规则脱敏。影视剧情、角色设定、假设案例、用户讲述的故事与真实共同经历必须区分。被删除来源不再参与后续发布；记忆重置保留现有截止水位，避免旧回复转述复活已清除内容。

## 完成条件

- 用真实应用形成一条明确全局偏好、一条局部偏好、一次 Origin 自己的审美判断、一项有真实工具回执的工作事实和一段明确标记为虚构的故事。
- 在 Turn 闭合后核对后台来源扫描，确认来源身份、用户/助手/工具证据类型和项目范围正确。
- 局部偏好不升级为全局偏好；虚构故事不变成 Origin 的现实经历；子 Agent 内部发言不直接成为 Origin 自我观察。
- 普通聊天没有有价值内容时允许空结果；提取失败、取消或尚未发布时不能声称已经记住。
- 原有工作摘要仍然可用；不因升级无界重扫历史，不将旧 A0/B1/B2 实验材料导入新身份。
- 同步长期记忆设计中的来源选择、结构化提取和边界。

## 工程边界

- 目标环境为 Windows x64、`x86_64-pc-windows-msvc`、DX12 与 PowerShell 7；不为未要求的平台增加兼容层。
- 遵守现有 Workspace / Crate 职责和依赖方向。业务实现放在 `crates/`，不在 `app/` 增加业务逻辑；不修改 Bevy、Widgetry、BRP 或 Codex 上游源码。
- 复用 Account、LLM Model、Runtime、Conversation、Session Store、Memory、Project Context、Skills、ToolCatalog 和现有异步任务机制；不建立平行 Agent Registry、任务数据库、记忆数据库或 Skill 管理器。
- 不恢复用户可见的提示词管理页面、Project Skill 或人格工作台。不得通过人格、记忆或 Skill 扩大工具权限。
- 不接入 B 站账号，不执行浏览、评论、私信、上传、直播、定时发布或其他平台运营。
- 未经用户明确授权，不退出登录、不重新登录、不切换账号、不重置凭据，也不通过更换数据目录破坏登录状态。
- 项目禁止新增或修改测试代码、Benchmark 和 Example。按变更范围使用 Cargo 编译、格式、Clippy、真实应用运行、日志/请求/存储状态核对；涉及 GUI 可观察行为时必须使用实际应用和 `bevy_brp_mcp` 验证。
- 不声称未执行的验证已经通过。发现问题在对应功能增量内修复并复验受影响范围，不另设纯验收阶段。
