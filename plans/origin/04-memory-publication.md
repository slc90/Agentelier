# 在现有记忆发布中区分类别与访问范围

本增量把结构化观察纳入现有 Memory 整合和发布，形成可按类型与范围检索的记忆视图。它依赖前一增量提供可靠来源，但不改变 Session Store 的历史权威。

## 全局与项目范围

全局个人记忆保存用户明确偏好、共同交流经历、Origin 有来源的稳定自我观察和跨项目有价值的经验。项目记忆保存当前规范工作目录内的设计决策、工作事实、代码事实、未决问题和项目专属讨论。

项目内容不能因为 Origin 身份相同而自动跨项目可见。访问范围继续沿用现有规范工作目录和权限契约，不以 UI Project 名称或 Project ID 取代实际范围检查。全局导航可以指出存在某个项目记录，但不复制私人项目正文。

## 分类与状态

整合需要区分明确陈述、暂定观察、已支持、争议、被纠正、被遗忘、被替代和仅供历史追溯的记录。Origin 自我观察需要真实表达和后续支持，或用户明确认可其长期价值；单次观点可作为带时间的观察保留，不直接写入人格核心。用户偏好不能从助手建议推断。

用户明确修订沿用现有 `revise_memory`，并将范围和来源带入同一发布流程。人格核心文件 `persona/origin.md` 不由 Memory 整合器修改。

## 发布、预算与检索

发布继续由 `agent/memory` 在同一数据库事务和现有可恢复 Markdown 路径完成。新增分类索引属于同一发布身份，可由已确认正文重建；不新建 `soul.md`、`voice.md` 或第二套数据库。

默认请求使用短导航，复杂任务才读取详情。完整摘要继续受现有 10 KiB 上限约束；新增个人导航建议约 2 KiB，给原有工作导航保留预算。一次查询默认沿用最多五条结果，详情读取有界。首期使用现有关键词检索和类型/范围过滤，不新增 Embedding、向量数据库或独立搜索服务。

## 完成条件

- 全局偏好可以在不同 Session 召回，项目内事实只在其授权工作目录召回。
- 用户明确修订后，摘要、详情和分类索引同步更新；被遗忘内容不因旧来源仍存在而重新发布。
- 只读检索仍使用现有 `search_memory/read_memory`；无结果时如实表达，不进行机械全库搜索。
- 发布继续由现有 Memory 数据库事务和 Markdown 发布/恢复机制完成，不新增平行存储。
- 请求中使用的记忆材料能够追溯发布身份、类别、范围和来源。
- 同步长期记忆设计、项目上下文和记忆检索的真实契约。

## 工程边界

- 目标环境为 Windows x64、`x86_64-pc-windows-msvc`、DX12 与 PowerShell 7；不为未要求的平台增加兼容层。
- 遵守现有 Workspace / Crate 职责和依赖方向。业务实现放在 `crates/`，不在 `app/` 增加业务逻辑；不修改 Bevy、Widgetry、BRP 或 Codex 上游源码。
- 复用 Account、LLM Model、Runtime、Conversation、Session Store、Memory、Project Context、Skills、ToolCatalog 和现有异步任务机制；不建立平行 Agent Registry、任务数据库、记忆数据库或 Skill 管理器。
- 不恢复用户可见的提示词管理页面、Project Skill 或人格工作台。不得通过人格、记忆或 Skill 扩大工具权限。
- 不接入 B 站账号，不执行浏览、评论、私信、上传、直播、定时发布或其他平台运营。
- 未经用户明确授权，不退出登录、不重新登录、不切换账号、不重置凭据，也不通过更换数据目录破坏登录状态。
- 项目禁止新增或修改测试代码、Benchmark 和 Example。按变更范围使用 Cargo 编译、格式、Clippy、真实应用运行、日志/请求/存储状态核对；涉及 GUI 可观察行为时必须使用实际应用和 `bevy_brp_mcp` 验证。
- 不声称未执行的验证已经通过。发现问题在对应功能增量内修复并复验受影响范围，不另设纯验收阶段。
