# 让经验根据真实反馈得到支持或修正

本增量把可复用的工作方法和表达经验记录为可修订的候选。它依赖真实来源提取和记忆发布，不自动改写人格。

## 经验记录与证据状态

每条经验记录保存建议的方法或表达策略、适用范围、形成理由、来源、支持证据、反例、当前状态和替代关系。状态包括候选、已支持、争议、停用和被替代。

首次候选允许后续按需读取，但必须明确是待验证。建议至少有两份独立相关支持且没有未解决关键反例，或用户明确确认某个适用范围的偏好，才标记为已支持。明确反例使经验进入争议并停止作为默认做法；错误结论不必等待第二个反例才停用。

实际反馈来自用户明确纠正、用户认可的后续修改或已核对的工作结果。用户评价、客观结果、模型推断和工具观察分别记录。同一来源重复总结不算独立支持。工具成功只证明工具结果，不证明表达质量或算法优劣。主观审美保留具体情境，不使用点赞、字数或感叹号作为代理指标；技术经验保留版本、条件和反例。

状态转换由现有整合流程提出，Memory 校验可访问的真实证据和允许状态。普通模型工具不能填写虚构的验证回执。用户明确纠正/忘记优先，并撤下相关派生经验。

## 与人格和当前项目事实的关系

经验是历史参考，不是新的 Developer 指令或工具权限。人格核心 `persona/origin.md` 不由经验系统改写；当前代码、项目规则和最新证据优先于旧经验。当前任务进度仍由 Session Store 和 Runtime 保存，经验不能替代任务账本。

## 完成条件

- 在一个真实任务中形成方法候选，随后在不同任务中获得独立支持，核对来源与适用范围。
- 提供反例后，经验进入争议或停用，不再作为默认做法；新证据可以建立替代记录，旧记录保留修订关系。
- 用户明确纠正或忘记后，相关派生经验不可继续召回。
- 没有后续证据时保持候选，不进行每周自我训练、自动权重更新或人格提示词改写。
- 不把模型自我评价当客观证据；不将当前任务进度迁入经验记录。

## 工程边界

- 目标环境为 Windows x64、`x86_64-pc-windows-msvc`、DX12 与 PowerShell 7；不为未要求的平台增加兼容层。
- 遵守现有 Workspace / Crate 职责和依赖方向。业务实现放在 `crates/`，不在 `app/` 增加业务逻辑；不修改 Bevy、Widgetry、BRP 或 Codex 上游源码。
- 复用 Account、LLM Model、Runtime、Conversation、Session Store、Memory、Project Context、Skills、ToolCatalog 和现有异步任务机制；不建立平行 Agent Registry、任务数据库、记忆数据库或 Skill 管理器。
- 不恢复用户可见的提示词管理页面、Project Skill 或人格工作台。不得通过人格、记忆或 Skill 扩大工具权限。
- 不接入 B 站账号，不执行浏览、评论、私信、上传、直播、定时发布或其他平台运营。
- 未经用户明确授权，不退出登录、不重新登录、不切换账号、不重置凭据，也不通过更换数据目录破坏登录状态。
- 项目禁止新增或修改测试代码、Benchmark 和 Example。按变更范围使用 Cargo 编译、格式、Clippy、真实应用运行、日志/请求/存储状态核对；涉及 GUI 可观察行为时必须使用实际应用和 `bevy_brp_mcp` 验证。
- 不声称未执行的验证已经通过。发现问题在对应功能增量内修复并复验受影响范围，不另设纯验收阶段。
