# 提供适合正式文档的 Origin 写作工作流

本增量新增用户级 `origin-write` Skill，解决从聊天讨论转向独立文档时的风格和结构变化。它不改变 Origin 的聊天人格，也不要求正式文档采用角色口癖。

## Skill 定义

```yaml
name: origin-write
description: 在用户要求撰写、整理或修改独立文档、技术方案、研究报告或正式书面产物时使用；按读者、用途、来源和指定文体组织内容。不用于普通聊天解释或简短回答。
```

安装在现有用户 Skill 目录 `<data>/skills/origin-write/`，使用标准 `SKILL.md` 和可选 `agents/openai.yaml`。沿用现有用户 Skill 管理和按需加载机制，不恢复提示词管理页面或 Project Skill。

## 工作方式

1. 确认文档目的、目标读者、交付格式和用户指定的风格。
2. 区分已确认事实、来源材料、推断和未决内容，不擅自填补关键缺口。
3. 根据内容本身的认知顺序组织章节，不套统一报告模板。
4. 先解释设计思路或研究问题，再展开机制、证据、例子、接口和验证。
5. 检查术语、事实、引用、结构和格式；要求保存文件时核对真实路径和内容。

正式文档应采用适合读者的书面语。Origin 的人格体现在判断、取舍和清晰表达，不将聊天中的语气词、感叹号、玩笑或动作描写机械带入产物。用户指定了某个专业写作工作流或格式时，以用户要求为准。

## 完成条件

- 安装并发现 `origin-write`，对一项技术设计请求生成独立 Markdown 文档，结构、事实和术语满足要求。
- 同一任务的聊天交流仍然保留 Origin 自然表达，最终文档不强行加入口癖。
- 对科研报告，引用和结论与实际来源一致；没有来源的内容标为未知或待确认，不编造证据。
- 对用户只想讨论而没有要求产物的场景，不擅自生成文件。
- 文件交付检查真实存在、可读且内容与要求一致；没有声称未执行的检查已通过。
- 与现有 Skills 的显式/隐式触发、冻结和删除语义一致。

## 工程边界

- 目标环境为 Windows x64、`x86_64-pc-windows-msvc`、DX12 与 PowerShell 7；不为未要求的平台增加兼容层。
- 遵守现有 Workspace / Crate 职责和依赖方向。业务实现放在 `crates/`，不在 `app/` 增加业务逻辑；不修改 Bevy、Widgetry、BRP 或 Codex 上游源码。
- 复用 Account、LLM Model、Runtime、Conversation、Session Store、Memory、Project Context、Skills、ToolCatalog 和现有异步任务机制；不建立平行 Agent Registry、任务数据库、记忆数据库或 Skill 管理器。
- 不恢复用户可见的提示词管理页面、Project Skill 或人格工作台。不得通过人格、记忆或 Skill 扩大工具权限。
- 不接入 B 站账号，不执行浏览、评论、私信、上传、直播、定时发布或其他平台运营。
- 未经用户明确授权，不退出登录、不重新登录、不切换账号、不重置凭据，也不通过更换数据目录破坏登录状态。
- 项目禁止新增或修改测试代码、Benchmark 和 Example。按变更范围使用 Cargo 编译、格式、Clippy、真实应用运行、日志/请求/存储状态核对；涉及 GUI 可观察行为时必须使用实际应用和 `bevy_brp_mcp` 验证。
- 不声称未执行的验证已经通过。发现问题在对应功能增量内修复并复验受影响范围，不另设纯验收阶段。
