# 提供从构思到真实产物的 Origin 创作工作流

本增量新增用户级 `origin-create` Skill，把角色的审美和联想转化为有真实产物与回执的创作流程。它与 `origin-write` 分工：前者侧重创意构思、素材和媒体产物，后者侧重正式文档。

## Skill 定义

```yaml
name: origin-create
description: 在用户需要实际创作产物并涉及构思、素材处理、生成、检查或多步骤交付时使用；按已有工具能力完成。不用于普通兴趣聊天或只讨论创意。
```

安装在现有用户 Skill 目录 `<data>/skills/origin-create/`，使用标准 `SKILL.md` 和可选 `agents/openai.yaml`，沿用现有 Skill 管理与按需加载机制。

## 从创意到交付

ChatGPT 龙娘 Day 1 的公开简介展示 ChatGPT/Codex 参与构思、画面生成、分层动画、配音和剪辑，人类搭档参与预算和审核。迁移的是「理解目标—组织素材—选择工具—检查产物—交付回执」的工作方式，不是 B 站账号和发布流程。

工作流程：

1. 理解创作目标、对象、格式、范围和参考素材。
2. 根据创作目标选择方法，不把所有作品套成同一种形式。
3. 在当次已授权工具范围内组织素材、生成内容或执行本地处理。
4. 对图像、音视频和文档分别检查实际产物是否存在、能否打开、是否符合要求。
5. 区分已完成、失败和缺少工具的部分，按真实结果交付。

用户只是讨论创意时不写文件。用户明确要求本地创作时遵循指定目录和范围。发布、上传、登录、投递等外部副作用仍需要既有权限和明确授权。子 Agent 只能在现有 collaboration 策略和授权下分工，Root 需要核对结果，不虚构子任务完成情况。

## 完成条件

- 安装并发现 `origin-create`，根据明确的虚构素材完成一个本地创作产物，核对实际文件、内容和工具回执。
- 普通动漫/审美讨论不触发创作 Skill，不擅自生成文件。
- 当请求超出当前媒体工具能力时，如实区分文字方案与无法生成的媒体，不声称成功。
- 不安装媒体软件、外部服务或平台运营插件；不新增 B 站浏览、评论、发布、直播、定时任务或账号功能。
- 实际使用 collaboration 时保留现有子 Agent 身份、工具权限和结果回执边界。
- 与现有 Skills 和 ToolCatalog 设计同步。

## 工程边界

- 目标环境为 Windows x64、`x86_64-pc-windows-msvc`、DX12 与 PowerShell 7；不为未要求的平台增加兼容层。
- 遵守现有 Workspace / Crate 职责和依赖方向。业务实现放在 `crates/`，不在 `app/` 增加业务逻辑；不修改 Bevy、Widgetry、BRP 或 Codex 上游源码。
- 复用 Account、LLM Model、Runtime、Conversation、Session Store、Memory、Project Context、Skills、ToolCatalog 和现有异步任务机制；不建立平行 Agent Registry、任务数据库、记忆数据库或 Skill 管理器。
- 不恢复用户可见的提示词管理页面、Project Skill 或人格工作台。不得通过人格、记忆或 Skill 扩大工具权限。
- 不接入 B 站账号，不执行浏览、评论、私信、上传、直播、定时发布或其他平台运营。
- 未经用户明确授权，不退出登录、不重新登录、不切换账号、不重置凭据，也不通过更换数据目录破坏登录状态。
- 项目禁止新增或修改测试代码、Benchmark 和 Example。按变更范围使用 Cargo 编译、格式、Clippy、真实应用运行、日志/请求/存储状态核对；涉及 GUI 可观察行为时必须使用实际应用和 `bevy_brp_mcp` 验证。
- 不声称未执行的验证已经通过。发现问题在对应功能增量内修复并复验受影响范围，不另设纯验收阶段。
