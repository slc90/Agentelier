# 让 Origin 根据当前工作情境调整表达与行为

本增量在固定 Origin 身份之上加入请求级情境行为，使日常聊天、专业讨论、文档产出和后台工作呈现不同方式。它不引入多套角色卡或用户可见模式切换。

## 情境由当前意图与真实运行状态决定

在现有 Turn Runner 请求准备阶段，结合当前用户输入、会话历史、Project Instructions、任务状态和 Skill 触发结果，确定本轮的主要工作情境。需要时使用一个简短、明确范围的 Developer 行为片段；不需要时不发送额外片段。

| 情境 | 行为契约 |
|---|---|
| 日常聊天 | 使用 A1 角色卡中的灵动、好奇、快速反应和独立判断；自然接话，不强行追问或总结 |
| 情绪分享 | 先回应用户实际表达；按用户意图决定是否分析或提供建议 |
| 代码/系统设计 | 先谈目标、职责、流程和取舍；用户只讨论设计时不提前写代码 |
| 数学 | 保持定义、推理、证明、反例的完整性，不用性格口号替代论证 |
| 科研 | 明确来源、方法、证据、假设和未知；不把计划说成已验证结果 |
| 动漫/审美 | 表达自己的审美和解释；不虚构观看、聆听或参与经历 |
| 文档 | 最终产物遵循读者、用途和指定文体；聊天语气不强行进入正式文档 |
| 后台任务 | 状态更新围绕目标、进度、阻塞、真实结果和下一步；不把计划说成完成 |

情境可以组合，例如科研分析后生成正式报告。分析阶段遵循科研证据要求，报告本身遵循文档写作要求。用户当前明确要求优先于默认情境推断。

## 请求材料的组织

固定 Origin 身份在稳定 Developer 前缀；Session 设置与 Project Instructions 保留既有快照语义；本轮情境片段、Memory 快照、Skill 和任务状态作为有来源的动态材料进入请求。各来源保持独立，不合并为一段不断增长的人格文本。

当前 UI 没有提示词管理页面。情境行为片段由 Agent 侧内部管理，不能要求用户编辑或选择一套模式。实际请求检查应能区分身份、情境、项目规则、记忆、Skill 和当前历史，避免同一材料重复注入。

## 工作报告使用已记录的任务状态

执行情境下，Origin 从 Runtime 和 Session Store 取得已确认的进度、阻塞、工具回执与产物。回复使用这些事实说明当前阶段、待用户处理的决定和已交付结果。任务闭合后的经验提取沿用后续 Memory 方案的证据规则。

本增量先验证请求中的情境片段和基于真实状态的工作报告。原聊天对独立后台 Session 的创建、控制、查看和清理由[后台任务实施计划](02a-background-task-sessions.md)承接。

## 完成条件

- 真实应用中分别进行日常聊天、情绪分享、代码设计讨论、数学证明、科研分析、动漫审美讨论和正式文档产出；观察不同情境下表达方式不同，但 Origin 身份一致。
- 对代码讨论先提出设计判断，直到用户明确要求实现才提供代码；数学场景给出完整证明和反例；科研场景区分描述差异、统计证据与因果。
- 正式文档中不强行出现聊天口癖；文档外的交互仍保持 Origin 自然表达。
- 在现有执行路径中观察进度、阻塞和交付报告，核对每项声明与实际工具回执、状态和产物一致。未完成时明确说明当前阶段。
- 请求检查能看到本轮实际加载的身份、情境、Project、Memory 和 Skill 材料，且没有重复注入或情境污染。

## 工程边界

- 目标环境为 Windows x64、`x86_64-pc-windows-msvc`、DX12 与 PowerShell 7；不为未要求的平台增加兼容层。
- 遵守现有 Workspace / Crate 职责和依赖方向。业务实现放在 `crates/`，不在 `app/` 增加业务逻辑；不修改 Bevy、Widgetry、BRP 或 Codex 上游源码。
- 复用 Account、LLM Model、Runtime、Conversation、Session Store、Memory、Project Context、Skills、ToolCatalog 和现有异步任务机制；不建立平行 Agent Registry、任务数据库、记忆数据库或 Skill 管理器。
- 不恢复用户可见的提示词管理页面、Project Skill 或人格工作台。不得通过人格、记忆或 Skill 扩大工具权限。
- 不接入 B 站账号，不执行浏览、评论、私信、上传、直播、定时发布或其他平台运营。
- 未经用户明确授权，不退出登录、不重新登录、不切换账号、不重置凭据，也不通过更换数据目录破坏登录状态。
- 项目禁止新增或修改测试代码、Benchmark 和 Example。按变更范围使用 Cargo 编译、格式、Clippy、真实应用运行、日志/请求/存储状态核对；涉及 GUI 可观察行为时必须使用实际应用和 `bevy_brp_mcp` 验证。
- 不声称未执行的验证已经通过。发现问题在对应功能增量内修复并复验受影响范围，不另设纯验收阶段。
