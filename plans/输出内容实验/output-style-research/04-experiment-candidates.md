# 第一阶段之后，哪些问题值得实验

这一页是从案例中提炼的候选研究方向，不是第二阶段已经确定的完整实施计划，也不要求第一阶段提前开发自动实验系统。

## 先保证比较的是表达控制

同一个模型、同一推理强度、同一种指令语言、相同输入历史下，先观察不加额外风格控制的结果。空白、官方完整主指令、官方表达片段分别是不同基线，不能混称“默认 Codex”。第一阶段的 Session 快照和有效输入检查，就是为了看清这些差异。

随后一次增加一类主要干预。只在固定输入的一轮比较时，可以保持所有历史相同；如果比较长期对话，两组之前的模型回答自然会分叉，应把它标成完整会话策略的比较，不能再声称只有当前这一句提示词不同。

## 候选方法与可以证伪的问题

| 方法 | 需要验证的问题 | 第一阶段能提供什么 |
| --- | --- | --- |
| 直接替换基础表达规则 | 是否减少模板化说明，同时保留必要信息？ | 空白与自定义基础文本、新会话 |
| 明确交流动作 | 能否区分确认、吐槽、追问、解释和文档请求？ | 连续多轮对话、稳定上下文 |
| 人工认可的范例 | 是否比抽象形容词更稳定？会不会照搬句式？ | 在自定义文本中加入范例 |
| 针对反例提炼规则 | 是否处理同类新问题，而不只修饰原例？ | 固定输入与原始回复复制 |
| 历史输出反馈 | 是减少重复，还是强化之前的坏风格？ | 会话历史；特殊反馈组织留给第二阶段 |
| 有上限的独立改写 | 可读性收益是否值得延迟？是否改变事实？ | 可手动发起改写，自动流程尚未实现 |

B 站案例支持把“回应场景”列入目标；dsh 的实现提供历史反馈和检查改写的机制线索；first-read 与 unslop 提供更具体的文档表达规则。这些来源均不能直接给出本项目中的收益大小。

## 观察材料要覆盖两类目标

聊天案例应包括简单确认、一个梗或吐槽、针对上文追问，以及从闲聊切回技术讨论。评价重点是有没有接住当前交流、是否恰当地展开、是否无故引入下一步、是否反复套用相同开头。

文档案例应使用同一组已经确认的事实，要求生成解释、设计说明或修改已有文档。评价重点是组织顺序、信息重复、无实际用途的防御性文字，以及事实和必要约束是否完整。这里不把“越短越好”当目标。

为避免只对熟悉案例调参，可以将材料分成调试用和保留用。候选策略在多个新 Session 重复运行，再由人工隐藏策略标签比较。保存实际文本、模型与设置，而不仅是“感觉更自然”的结论。保存和批量比较属于第二阶段；第一阶段只允许手动复制结果，不自动持久化会话。

## 如何判断改善没有走偏

短回答不一定自然，长回答也不一定防御。应该删除的是缺乏实际作用的内容，而不是删除真实风险。人格更鲜明也不是独立成功标准：如果它开始故意犯错、虚构经历、回避严肃解释，或在文档中塞入角色台词，就偏离了当前目的。

先用第一阶段验证模型确实收到正确的历史和指令，再谈风格效果。上下文遗漏、错误地把增量重复追加、模型暗中切换等环境问题，应先排除，不能靠加提示词掩盖。
