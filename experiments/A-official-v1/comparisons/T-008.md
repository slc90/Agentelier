**同步调用：调用后，要等这次操作结束，才继续往下执行。  
异步调用：调用后，不必等这次操作结束，就能先做别的事；结果稍后再处理。**

对你来说，可以先抓住一个问题：**“这一步还没做完，我能不能继续做别的事？”**

## 1. 同步调用：做完一件，再做下一件

你写过的顺序执行程序，大多可以这样理解：

```text
内容 = 读取文件()
显示(内容)
显示("处理结束")
```

执行顺序是：

1. 开始读取文件。
2. 等文件读取完成，拿到内容。
3. 显示内容。
4. 显示“处理结束”。

如果读取文件需要 3 秒，那么后面两行就得等 3 秒。

这就像你去咖啡店点单，**一直站在取餐口等，拿到咖啡后才去做其他事。**

## 2. 异步调用：先发起，结果稍后再拿

异步方式可以这样理解。下面是示意代码，不是某种语言的具体语法：

```text
读取任务 = 开始异步读取文件()
显示("文件正在读取，我先做点别的事")

内容 = 等待读取任务完成()
显示(内容)
```

执行过程是：

1. 发起读取文件的操作。
2. 不等读取结束，先显示提示，也可以做其他工作。
3. 到了确实需要文件内容的时候，再等结果。
4. 拿到内容后，继续处理。

就像你点完咖啡，拿到取餐号，**先去找座位，咖啡做好后再取。**

注意：异步调用刚发起时，拿到的通常**不是文件内容，而是一个代表“这件事正在进行”的对象**。不同语言可能把它叫作 `Task`、`Future` 或 `Promise`，暂时不用记这些名字。

## 3. 异步不代表什么？

有两个容易混淆的地方：

- **异步不等于更快。** 读取文件本身可能仍需 3 秒，区别是这 3 秒里，程序有机会做其他工作或响应用户操作。
- **异步不等于一定开了新线程。** “异步”描述的是如何发起操作、等待和取得结果，不规定底层必须怎样实现。

你以后还可能看到 `await`。它通常表示：**当前这段函数需要等结果，暂时停在这里，但不会因此把执行它的线程也一直占住，程序仍可能处理其他工作。** 所以，异步程序内部也可以保留“先拿到结果，再执行下一步”的顺序。

## 怎么选？

- **步骤简单，而且下一步必须依赖上一步的结果：**同步通常更容易写、也更容易理解。
- **需要等待网络、文件等操作，同时还想响应按钮、处理其他请求：**异步通常更合适。

一句话记住：**同步是“等它做完再往下走”；异步是“先让它做着，结果需要时再处理”。**

这里的关键是：**发起操作之后，当前这段程序要不要停下来等。**

比如，你的程序要做两件事：下载文件、计算一组数据。这两件事互不依赖。

同步调用就像这样：

```text
开始下载文件
等待……
下载完成
开始计算数据
计算完成
```

假设下载需要 5 秒，计算需要 2 秒，总共大约需要 7 秒。你熟悉的顺序代码通常就是这种感觉：上一行做完，才执行下一行。

异步调用可以这样安排：

```text
发起下载
下载还在进行时，开始计算数据
计算完成
等下载结果准备好，再处理文件
```

如果下载和计算能够重叠进行，总共可能只需要约 5 秒。**下载本身没有变快，只是等待下载的时间被用来做其他事了。**

可以把它想成在餐厅点餐：

- **同步**：点完餐，你一直站在取餐口等，拿到餐以后才去找座位。
- **异步**：点完餐，拿到取餐号，就可以先去找座位；叫到号时再取餐。

取餐号不是餐，而是一个“之后能拿到结果的凭证”。在程序中，你可能会看到类似的东西叫作 `Promise`、`Future` 或“任务对象”，具体名称取决于语言。

不过，异步有一个你需要特别注意的地方：**发起操作，不等于操作已经完成。**

下面是示意用的伪代码：

```text
下载任务 = 发起异步下载()

计算数据()                 // 不依赖文件，可以先做

文件 = 等待下载任务的结果()  // 到了需要文件的地方，再等结果
读取文件内容(文件)
```

你不能刚发起下载，就直接读取完整文件，因为它可能还没下载好。程序需要一种方式，在结果准备好后继续处理。常见方式有：

- **回调函数**：提前告诉系统，“完成后执行这个函数”。
- **`async / await`**：把“等结果、再继续”的逻辑写得像顺序代码。通常，`await` 会暂停当前异步函数，让运行环境有机会处理其他任务。

最后，别把**异步**和**并行**混为一谈。异步并不保证两段代码在同一时刻运行，也不一定需要新建线程。比如等待网络数据时，程序可以去处理别的事情，这就已经能体现异步的价值。

对你目前的背景，最值得先记住的是：**同步代码容易按执行顺序理解；异步代码还需要考虑“结果什么时候才准备好”，以及“哪些事情可以先做”。**

这里的 `当拿到天气时` 是一个**回调函数**：现在先告诉程序“结果到了以后，请执行这个函数”，而不是现在就执行它。

如果请求花了 3 秒，你会先看到：

```text
可以做其他事了
```

约 3 秒后，再看到天气。

## 3. 用生活中的例子理解

假设你去店里取一件需要准备的商品：

- **同步**：你站在柜台前等，拿到商品以后，才去做下一件事。
- **异步**：你留下联系方式，先去做别的事；商品准备好后，店员通知你。

准备商品都需要时间。区别是：**等待期间，你是否必须守在那里。**

## 4. 最容易混淆的三点

### 异步不代表事情本身更快

网络请求需要 3 秒，改成异步后，可能仍然需要 3 秒。

它的好处是：这 3 秒里，程序有机会处理其他事情，比如响应按钮点击，而不是一直等着。

### 异步不等于开一个新线程

线程可以先粗略理解为程序中的一条执行路线。

异步是一种安排任务和处理结果的方式，**不一定需要新线程**。一个线程也可以在等待网络结果时，转去处理其他任务。现阶段不用急着研究它的内部实现。

### 依赖结果的事情，还是必须等结果

比如：

```text
天气 = 异步获取天气()
显示(天气)
```

不能想当然地认为这里的 `天气` 已经是最终结果。异步调用刚返回时，天气可能还没查到；返回的可能只是一个“将来会有结果的对象”。

所以，异步程序需要明确安排：**结果出来后，再做依赖它的事。** 常见写法有回调函数、Promise，以及 `async/await`。

你现在可以先记住这一组区别：

|                  | 同步调用           | 异步调用                       |
| ---------------- | ------------------ | ------------------------------ |
| 发起调用后       | 等它完成，再继续   | 不必等它完成，就能交回控制权   |
| 结果何时处理     | 调用完成后直接处理 | 结果就绪后，再安排处理         |
| 写程序时的关注点 | 下一行做什么       | 现在能做什么，结果到了再做什么 |

从顺序程序过渡到异步程序，最需要适应的就是：**代码写在后面，不一定意味着它会在前一个任务完成后才执行。**

- **同步调用**：点完餐后，你一直站在取餐口等，拿到餐才去做其他事。

### 异步不一定让操作本身更快

“单线程还是多线程”说的是：**程序使用多少个执行线程。**

它们不是同一个概念。单线程程序也可以采用异步方式处理很多等待中的任务。

## 简单记法

- **同步**：这次调用完成了，再往下走。
- **异步**：先发起，往下走，结果稍后再处理。

另外，如果下一步必须用到这一步的结果，即使采用异步调用，也仍然得等结果准备好。异步能减少不必要的等待，不能消除事情本身的先后依赖。

程序最终需要结果时，仍然要面对“下载是否完成”这个问题。常见处理方式有：

- **通知我**：下载完成后，自动执行你事先指定的一段代码，常叫“回调”。
- **等这个任务完成**：通过任务对象等待结果，很多语言使用 `await`。

你以后可能看到这样的代码：

```text

统计字数(文件)
```

它看起来也像顺序执行，但 `await` 通常表示：

> 当前这段任务先暂停，等下载完成再继续；等待期间，运行环境可以去执行其他已安排的任务。

所以，**`await` 后面的代码仍然要等结果，异步不是让所有代码都无条件地往下跑。**

## 4. 两个容易混淆的地方

### 异步不等于多线程

异步说的是“如何发起操作、等待并处理结果”，多线程说的是“用几个执行线程来工作”。

一个线程也可以管理多个异步任务。因此，看到“异步”，不能直接理解成“新开一个线程”。

### 异步不一定更快

如果下一步必须依赖上一步的结果，例如：

```text

```

那么这些依赖关系不会因为改成异步就消失。

异步尤其适合**网络请求、读写文件、查询数据库等需要等待的操作**：等待时，程序还能处理其他工作。但它也会增加任务协调、错误处理等方面的复杂度。

**先记住一句话：同步是“等结果，再继续”；异步是“先发起，等待期间可以安排别的工作，结果好了再处理”。**

程序执行到 `下载文件()` 时，必须等它返回，才能执行下一行。即使整理笔记不依赖下载结果，也得排队等着。

这就是你熟悉的顺序执行方式。

## 2. 异步调用：先发起，之后再取结果

换成异步方式，可以这样安排。以下是**伪代码**，用来表示执行思路：

```text

整理本地笔记()              // 下载尚未完成时，可以先做这件事
文件 = 等待下载完成(下载任务)
使用文件(文件)
```

执行过程变成：

```text
下载：    ├──────── 5 秒 ────────┤
整理笔记：├── 2 秒 ──┤
                              使用文件
```

关键区别是：**发起下载后，程序先拿到的是“任务凭证”，而不是下载结果。** 有了这个凭证，之后才能查询任务状态或等待结果。

在下载和整理笔记确实能够重叠进行、且忽略额外开销的情况下，总耗时可能从约 7 秒变成约 5 秒。

## 3. 用生活中的例子理解

想象你去餐厅点餐：

- **同步方式**：点完餐就站在取餐口，拿到餐后，才去买饮料。
- **异步方式**：点完餐拿到取餐号，先去买饮料，叫到你的号码时再取餐。

取餐号就像上面的“任务凭证”。

异步没有让厨房做饭更快，只是让你**不用把等待时间空在那里**。

## 4. 三个容易混淆的地方

### 异步不等于“一定更快”

如果你发起下载后，马上就等待它完成：

```text
下载任务 = 发起下载()
文件 = 等待下载完成(下载任务)
使用文件(文件)
```

中间没有别的事情可以做，就不一定比同步方式更省时间。

### 异步不等于“多开一个线程”

多线程是实现任务重叠的一种方式，但不是唯一方式。异步下载也可以由操作系统处理网络等待，不一定需要专门开一个线程一直等。

刚开始可以先记住：**同步、异步描述的是调用和等待结果的方式，不是线程数量。**

### 有依赖的步骤，仍然必须等

“整理本地笔记”不依赖下载结果，所以可以提前做；“使用文件”依赖下载结果，就必须等文件下载完成。

异步不是让步骤随便乱序，而是让**互不依赖的事情有机会重叠进行**。

---

一句话总结：**同步是“做完再往下走”，异步是“先发起，能做别的就先做，需要结果时再等”。**

**调用已经返回，不代表下载已经完成。** 这是异步调用最需要记住的一点。

代码里的“下载完成后执行……”叫作**回调**：你提前告诉程序，“等这件事完成了，就执行这段代码”。实际编程中，也常用 `Promise`、`Future`、`async/await` 等机制处理异步结果，现在先理解这个思路就够了。

## 3. 用生活中的例子理解

**同步调用**像去柜台点餐后，一直站在那里等，拿到餐才能去做别的事。

**异步调用**像点餐后拿到取餐号，你可以先去找座位；餐做好后，店员叫号，你再去取。

注意：拿到取餐号，相当于“请求已经受理”，**不是“餐已经做好”**。

## 4. 两个容易混淆的地方

**异步不等于事情本身变快。** 下载需要 3 秒，改成异步后可能仍然需要 3 秒。好处是调用方不必把这段时间都用来等待，例如界面可以继续响应用户操作。

**异步也不等于多线程或并行。** 它描述的是“调用后要不要等完成”，而不是“一定有几个线程同时工作”。有些异步程序只用一个线程，也能在等待网络响应时处理其他事情。

一句话总结：**同步调用是“等它做完，再继续”；异步调用是“先发起，继续做，完成后再处理结果”。**

理解同步和异步，可以从一个问题入手：**调用一个操作后，必须等它做完，才能继续往下走吗？**

## 1. 同步调用：等做完，再继续

假设程序需要下载一个文件，然后处理它：

```text

处理文件(文件)

```

如果“下载文件”是同步调用，执行过程就是：

3. 处理文件。

## 2. 异步调用：先发起，结果稍后再拿

异步调用把“发起操作”和“拿到结果”分开了。

下面是示意代码，不对应某个具体语言的语法：

```text
下载任务 = 发起异步下载(网址)

打印("下载已发起")
做一些不依赖文件的事情()

文件 = 等待下载任务的结果(下载任务)
处理文件(文件)
```

执行过程可以理解为：

1. 发起下载，先拿到一个代表“这次下载”的任务对象，而不是文件本身。
2. 下载尚未完成时，可以先做不依赖下载结果的事情。
3. 真正需要文件时，再等待结果。
4. 下载完成后，处理文件。

这就像点咖啡后，**拿到取餐号，先去找座位；等叫号了再取咖啡**。取餐号不是咖啡，就像“任务对象”不是最终结果。

结果准备好后，程序可以通过不同方式继续处理，例如让系统调用你提前提供的函数，也就是“回调”；或者使用许多语言里的 `await`，等待结果后继续执行。

## 3. 异步不是“不等待”，也不等于“同时计算”

**异步并没有消除等待，而是让等待期间有机会做其他事。**

例如，下载文件需要 5 秒，另有一件独立的工作需要 2 秒：

```text
同步：下载 5 秒 → 其他工作 2 秒       总共约 7 秒
异步：下载期间做完那 2 秒的其他工作   总共可能约 5 秒
```

这里假设两件事可以互不影响地推进。下载本身并没有因为异步就变快。

另外，**异步不等于多线程，也不保证代码在并行执行**。单个线程也可以在某个操作等待网络时，转去处理别的任务。你暂时只需要记住：异步关心的是“结果还没准备好时，程序如何安排接下来的工作”。

## 什么时候值得用异步？

对于简单计算、步骤之间紧密依赖的小程序，同步通常更容易写，也完全够用。

当程序经常需要等待网络、数据库等外部操作，或者等待时仍要响应用户操作，异步就很有用。例如，下载文件时，界面仍然可以响应点击，而不是一直卡住。

**一句话总结：同步是“等这次调用完成，再往下走”；异步是“先发起操作，把结果留到稍后处理”。**

| 对比点     | 同步调用                 | 异步调用                                   |
| ---------- | ------------------------ | ------------------------------------------ |
| 发起操作后 | 等操作完成再继续         | 不必等操作完成就能继续                     |
| 怎么拿结果 | 通常直接从调用中拿到结果 | 通常通过回调、代表未来结果的对象等方式获取 |

比如，先发起下载 A，再发起下载 B：

- 同步调用：A 下载完了，才开始下载 B。
- 异步调用：A 还没下载完，就可以发起 B；**B 也可能比 A 先完成。**

### 异步不一定更快

一张图片下载需要 5 秒，换成异步后，可能仍然需要 5 秒。

异步描述的是“发起操作后如何继续、如何接收结果”，不是规定底层必须怎样执行。

**可以先记住一句话：同步是“等做完，再往下走”；异步是“先安排，完成后再处理”。**
