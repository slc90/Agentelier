# 聊天会话与流式回复

主界面先刷新模型目录、选择模型及推理设置，再点击“创建会话”。会话固定这份设置和当前账号身份；之后修改准备区不改变已经创建的会话。当前保留一个内存会话并支持连续多轮交流，关闭应用后不会恢复记录。

输入框支持多行和粘贴，Enter 发送、Shift+Enter 换行，发送按钮提供相同操作。空白输入不能发送，正文中的换行和空白保持原样。IME 预编辑及候选提交帧不触发发送。业务接纳前保留草稿；接纳后清空尚未继续编辑的原草稿，生成期间可以编辑下一条内容，但不能排队或并行发送。

回复以原生 Markdown 持续显示，每个消息输出项保持自己的身份和公开阶段，例如 commentary 和 final_answer。内容段按服务顺序排列；流式更新修改同一行，不为每个片段创建新消息，不重建输入框。切换设置页不取消生成，返回时恢复当前记录。标题、段落、强调、删除线、行内代码、引用、分隔线和链接已有排版；列表、围栏代码和表格暂保留可读原文。

只有合法完成响应及可接受的完整输出才标记完成，并以最终正文校准此前增量。失败或取消保留部分回复并说明状态；未完成内容不冒充完整答案。没有可展示正文时只显示完成状态。普通拒绝正文正常显示，工具输出明确失败，不执行工具。

聊天使用 `store=false`、固定流式请求，不加载自定义风格提示词。无总生成时长上限，合法 SSE 事件或心跳维持 120 秒空闲期限；连接超时为 15 秒，单事件上限 4 MiB、总流上限 16 MiB。超时、超限、断流、服务拒绝和不完整结果保留实际原因，输出开始后不自动重放请求。

任务真实结束并回收后才发布最终状态。普通关闭取消生成，等待必要凭据提交及 Tokio 结束，保留账号会话。自然凭据续期不清空聊天；账号身份改变后不能继续沿用旧会话。

实现关系见[总体架构](../design/architecture.md#内存聊天与流式投影)。协议依据：[Responses 流事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)。

## 连续交流的上下文

上一轮的真实终态和任务回收完成后，才允许发送下一条消息。下一次请求由执行侧的已提交协议历史和当前输入组成，不读取 UI 气泡拼接上下文。会话内可以持续追问、修订前文和整理文档；历史消息保留在滚动列表中。

只有成功轮次把用户输入和完整模型输出一起提交到历史。失败、取消、断流和未完成的尝试仍可回看，但标明未进入后续上下文；后续提问继续使用之前成功的记录。原有公开阶段、消息顺序和所需的加密 reasoning 项按协议保留，加密内容不进入 UI 或日志。

生成中仍可编辑草稿，发送不可排队。修改准备区的模型或推理强度不会改变活动 Session 的设置，后续请求继续使用创建时快照。上下文超限时显示实际错误并保留记录，不自动摘要、压缩、裁剪或截短输入。

## 停止生成

生成期间可点击“停止”。界面先显示正在停止，等待对应任务真正结束与回收后才恢复发送。停止保留当前账号、会话和已显示正文，并标注取消及未进入上下文。控制路径独立于正文传递，按会话、轮次与操作身份核对；已经确认完成的结果不会被迟来的停止回滚。

## 重试最近尝试

最近一次失败或取消的尝试在任务回收后可手动重试。重试使用同一输入、活动会话设置和此前成功历史，分配新轮次及操作身份；同一个用户输入只显示一次，旧尝试及部分正文继续保留。新尝试不携带旧部分回答或错误文本，接纳不清空正在编辑的新草稿。后续已继续交流时不能回到旧失败条目原位重试；没有自动重试或分支回滚。

## 新建和重置

“新建会话”复制准备区的模型与推理设置，“重置当前会话”复制当前活动会话设置。已有会话时先提示记录未持久化，点击确认后才清空全部展示与协议历史；输入草稿保留，保留按钮撤回清空。新会话身份重新分配，账号和数据目录不变。生成、停止中或尚未回收时两项操作均禁用，执行侧同样保护运行中的会话。

## Markdown 阅读

助手正文保留原始 Markdown，由原生 Bevy/Widgetry UI 展示；HTML 按字面文本显示，图片仅显示替代文字和目标，不下载远端内容。链接正文保留样式，下方按钮只在用户点击时打开 HTTP/HTTPS 目标；其它 URI 显示但不执行。

生成期间只重新解析发生变化的消息，未变化的块保持实体。位于底部时跟随新内容；向上翻阅后保留阅读位置，点击“回到底部”恢复跟随。切换设置页后恢复记录及阅读位置，不重新发起生成。
