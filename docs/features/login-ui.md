# 登录与目录设置界面

`agentelier_login_ui` 使用 Bevy BSN 和 Widgetry 构造数据目录启动界面。当前实现目录启动流程和“设置 → 数据与存储”，不提供账号认证。

宿主安装现有 Bevy、应用 Asset、窗口和日志体系，再通过 `LoginUiPlugin::new` 传入已保存目录、`Arc<OnceLock<DataEnvironment>>` 及线程安全的目录保存操作。将 `LoginUiHost` 挂到 Widgetry 窗口的内容节点；同一插件实例只接纳一个宿主。

未保存路径时显示 Widgetry `PickDirectory`，明确确认后才检查。已有路径直接检查；失败界面显示路径及原因，提供重试、重新选择和取消。目录检查与保存操作在共享 JobManager 的后台线程执行。保存回调由宿主拥有，不能访问 ECS；应在统一提交入口合并最新配置、完整提交，并通过 `io::Result` 返回真实失败。启动和目录设置复用同一个回调。

新路径保存成功或旧路径检查成功后，环境写入共享单次初始化槽；任务真实完成后发布 `DataDirectoryReady`。宿主据此更新界面和配置投影。取消选择或失败恢复会请求正常退出，关闭窗口也沿宿主退出流程执行。

宿主必须在主循环结束后停止并等待共享 JobManager 的所有任务结束，再关闭日志，最后释放共享环境槽。界面不安装第二套日志或事件循环，不把凭据内容放入反射状态或事件。应用装配见[总体架构](../design/architecture.md)，存放与错误契约见[数据目录与启动](../design/mechanisms/application-data.md)。

## 数据与存储设置

数据环境准备完成后显示主界面“设置”入口。设置页从环境读取固定当前路径，提供打开当前目录、更改下次启动目录和返回主界面。路径完整换行显示，长正文可纵向滚动。

更改使用 Widgetry `PickDirectory`，候选检查和配置提交在 JobManager 后台线程执行，不持有第二份环境锁。成功后才更新待生效路径；取消或失败保持之前的选择。选择当前目录可撤回待生效更改。打开目录通过环境的 Windows Shell 操作处理，失败反馈保留在本次操作区域。

操作以 ID 关联，只接纳一个在途任务。返回主界面会取消未确认的选择；已确认 I/O 继续到真实结束，重开页面时仍禁止重复提交。下一次启动才采用保存的新位置，当前环境、账号文件和日志归属始终不变。
