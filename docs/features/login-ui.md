# 登录与目录设置界面

`agentelier_login_ui` 使用 Bevy BSN 和 Widgetry 构造数据目录启动界面。当前实现目录启动流程、“设置 → 数据与存储”、主窗口账号恢复及浏览器授权界面。

宿主安装现有 Bevy、应用 Asset、窗口和日志体系，再通过 `LoginUiPlugin::new` 传入已保存目录、`Arc<OnceLock<DataEnvironment>>` 及线程安全的目录保存操作。将 `LoginUiHost` 挂到 Widgetry 窗口的内容节点；同一插件实例只接纳一个宿主。

未保存路径时显示 Widgetry `PickDirectory`，明确确认后才检查。已有路径直接检查；失败界面显示路径及原因，提供重试、重新选择和取消。目录检查与保存操作在共享 JobManager 的后台线程执行。保存回调由宿主拥有，不能访问 ECS；应在统一提交入口合并最新配置、完整提交，并通过 `io::Result` 返回真实失败。启动和目录设置复用同一个回调。

新路径保存成功或旧路径检查成功后，环境写入共享单次初始化槽；任务真实完成后发布 `DataDirectoryReady`。宿主据此更新界面和配置投影。取消选择或失败恢复会请求正常退出，关闭窗口也沿宿主退出流程执行。

宿主必须在主循环结束后停止并等待共享 JobManager 的所有任务结束，再关闭日志，最后释放共享环境槽。界面不安装第二套日志或事件循环，不把凭据内容放入反射状态或事件。应用装配见[总体架构](../design/architecture.md)，存放与错误契约见[数据目录与启动](../design/mechanisms/application-data.md)。

## 数据与存储设置

数据环境准备完成后显示主界面“设置”入口。设置页从环境读取固定当前路径，提供打开当前目录、更改下次启动目录和返回主界面。路径完整换行显示，长正文可纵向滚动。

主界面账号区域由 `AccountState` 驱动，分别保存非敏感账号摘要、凭据状态、在途操作和错误。恢复中显示“正在读取账号”，无会话显示“未登录”，失败显示固定原因和“重新读取账号”入口；已有会话显示账号摘要及是否过期。重新读取发布 `RestoreAccount` 业务事件，由应用连接 Bridge；读取中或后台失效时禁用该入口。返回主界面时使用最新投影构造内容，不影响已进行的目录设置。

更改使用 Widgetry `PickDirectory`，候选检查和配置提交在 JobManager 后台线程执行，不持有第二份环境锁。成功后才更新待生效路径；取消或失败保持之前的选择。选择当前目录可撤回待生效更改。打开目录通过环境的 Windows Shell 操作处理，失败反馈保留在本次操作区域。

操作以 ID 关联，只接纳一个在途任务。返回主界面会取消未确认的选择；已确认 I/O 继续到真实结束，重开页面时仍禁止重复提交。下一次启动才采用保存的新位置，当前环境、账号文件和日志归属始终不变。

## 浏览器登录

`LoginAction` 发布登录、补充同意、重新打开浏览器、复制链接、取消与重试保存请求，由宿主连接 Bridge。`AccountPhase` 独立表达读取、准备、等待、交换、保存、待重试保存与取消；`AccountState` 同时保留原账号摘要和实际会话/订阅状态，错误不伪装成退出登录。

等待区复用当前尝试地址；自动打开失败保留重新打开和复制入口。保存失败仍占用同一操作，重试不兑换授权码。取消先显示正在取消，只有后台终态才结束操作。未授予直接订阅使用范围时显示已登录但订阅未开启，可显式发起补充授权；没有模型请求或其他计费入口。

按钮只使用 Widgetry 公开的 Loading/禁用接口，并由运行侧再约束重复操作。授权 URL、Token、授权码及 PKCE 不进入 AccountState 或面板；浏览器密码和二次验证只由用户处理。

## 退出登录

已登录或存在待清理会话时显示“退出登录”。`LoginAction::SignOut` 请求退出；AccountPhase 的 SigningOut/Revoking/Clearing 展示真实进度，并禁用重复退出及其他账号操作。现有会话重新授权或续期过程中仍可退出，数据与存储设置保持可用；初次未完成的浏览器授权继续使用“取消登录”。

本地失败进入 SignOutFailed，仅提供“重试退出登录”，保持禁止新请求。成功后隐藏已退出账号的身份文本，显示未登录卡片；远端未确认时反馈“已退出本机登录；远端撤销未确认”，不会把它当作本地清理失败。只关闭窗口保留会话，且不改变数据目录和配置。

## 会话检查与续期

`LoginAction::CheckSession` 请求可用凭据；主窗口“检查会话”只检查或续期，不调用模型。`SessionActivity` 独立表达检查、刷新、保存与保存失败，账号摘要持续显示；已有过期会话可明确尝试续期。保存失败入口变为“重试保存凭据”，先提交运行侧的新记录，不重新交换旧刷新凭据。检查/保存期间禁用冲突操作；明确失效显示重新登录，临时故障只更新错误，客户端配置错误禁止重复发起浏览器登录。`session_error` 保留认证运行中的错误，与当前界面操作错误分开；重新读取成功后由认证运行重新投影已有失败防护，不能将读取成功当作认证恢复。`session_retry_at` 仅包含安全重试时间，不包含秘密。
