# 把补丁变成可核对的文件变化

Shell 已能读文件和调用 Git，但修改源代码需要一个更明确的入口：模型给出预期变化，工具定位旧内容，写入新内容，再报告哪些文件真正改变。`apply_patch` 承担这个职责，不经过 Shell 二次解释补丁文本。

## 保留补丁语言，适配现有工具协议

Codex 的补丁语言使用 `*** Begin Patch` / `*** End Patch` 包裹文件动作，支持 Add、Delete、Update，以及 Update 中的 Move to。它的工具处理走 freeform 路径；当前应用则只接收 JSON function tools。[补丁格式与处理依据](sources.md#codex)

本阶段选择 JSON 包装，参数为 `patch` 和 `workdir`。两者都在严格 schema 的 `required` 中；`patch` 是完整补丁文本，`workdir` 为字符串或 `null`。模型通过正常 `function_call` 调用，既不增加 `custom_tool_call` 协议，也不把助手正文中的补丁自动执行。

```json
{
  "patch": "*** Begin Patch\n*** Add File: notes.txt\n+hello\n*** End Patch\n",
  "workdir": "C:\\Users\\<用户>\\Downloads\\counter-tool-exam"
}
```

工具名称仍为 `apply_patch`。在工具描述中直接给出接受的补丁标记和 JSON 用法，不能把 Codex 的“不要包成 JSON”原文一起带过来。

## 先算清变化，再触碰文件

```mermaid
flowchart LR
    A[完整 JSON 调用] --> P[解析全部补丁动作]
    P --> V[读取旧文件并计算新内容]
    V --> C[确认路径和结果预算]
    C --> W[按文件提交变化]
    W --> J[实际变化记录]
    J --> R[成功或部分失败结果]
```

解析阶段检查标记、动作结构、路径与重复目标。计算阶段验证 Update 的旧内容、删除源文件以及移动目标条件，把本次操作需要的旧文件内容和预计新内容准备好。任一动作存在可提前发现的格式或匹配错误，整份补丁在写入前返回失败。

本阶段采用明确上下文的精确文本匹配，不实现自动猜测或宽松空白纠错。多个位置都能匹配时，要求增加上下文；上下文已经变化时，要求重新读取文件。这样模型能根据错误重新形成补丁，而不是工具把修改安放到不确定的位置。

支持 UTF-8 文本，保留已有 UTF-8 BOM，以及正常的 LF / CRLF 行尾形式。新增文件统一使用 UTF-8 无 BOM、LF 行尾；遇到不支持的编码或无法明确处理的混合行尾，返回具体错误，不静默重编码整个文件。Move to 支持同次内容更新；目标已存在时不无条件覆盖。

相对路径从本次解析后的 `workdir` 出发，绝对路径按本机路径规则处理。工作目录不构成沙箱；路径中包含空格、中文或 Windows 前缀时也必须保持正确身份。重复或别名目标在可识别时于预检查阶段拒绝，避免同一补丁中的动作相互覆盖。

## 变化记录比“全部成功”更重要

预检查可以避免大多数无效补丁造成半份修改，但多个文件的落盘并不是一次文件系统事务。预检查之后，文件可能被其他程序改变，磁盘写入或重命名也可能失败。

每个动作提交前重新确认必要的旧内容或身份条件。单文件写入使用同目录临时文件和受支持的替换方式，避免直接截断原文件后才开始写完整内容。删除和移动具有各自的完成点；移动若实际分成建立目标与移除源两个动作，失败结果必须说明实际停在哪一步。

结果按动作保留源路径、目标路径、变化种类和实际完成状态。完整成功返回全部已完成动作；中途失败返回已完成动作、失败动作、尚未开始动作及原因。目录创建、临时文件清理失败等已经产生的辅助变化也要被记录，而不是被“补丁失败”四个字盖住。

不提供跨文件自动回滚，不自动重放失败补丁，不用 `git reset` 或 `git checkout` 代替错误处理。模型读取实际状态后决定下一次修改。工具历史保存的是实际执行结果，不能仅保留预计 diff。

## 停止发生在文件修改中间时

补丁开始前收到取消，则不写文件。准备阶段收到取消，则放弃尚未提交的准备结果。进入某个文件的提交操作后，先等待该操作取得真实结果，再停止后续动作。

文件 I/O 可以在阻塞工作线程执行，但外层不能因为取消了等待 Future 就发布“已取消”。任务需要等待写入工作收敛，保存完成日志，清理尚未使用的临时文件，再返回取消结果。已经写入的文件保留原状，取消不表示撤销。

原有 15 秒期限在这里改为协作式截止请求：准备阶段可停止；已经开始的提交要完成结果核对。工具结果区分超时或取消，以及实际完成的文件变化，不报告一个看似干净、实际上仍在后台写文件的终态。

## 有界输入和结果

补丁参数继续使用 64 KiB 上限。本阶段另设每份补丁最多 64 个文件动作、单个被读取文本文件最多 8 MiB、一次准备的文本总量最多 32 MiB，均在实际分配前检查。预计变化报告必须能装入 64 KiB 文本结果预算，否则在写入前拒绝。

这些限制用于控制一次工具调用的资源，不借此引入通用大型补丁服务。用户需要修改更大文件时，可以通过后续明确任务重新决定范围。

## 接入后的可观察结果

`agent/tools` 持有解析、匹配、文件修改和实际结果；`llm_model` 只负责把结果关联到 `call_id`；`conversation` 保存封闭步骤；UI 工具记录展示修改文件、结果状态和必要的错误详情。

参数、完整文件内容与补丁正文不进入常规日志。日志记录工具调用身份、动作数量、结果类别和耗时。原始补丁及有界结果只出现在本次工具记录所需的展示中，继续保护账号凭据与模型私有数据。

实现参考 Codex 的格式和机制，按本项目职责写入现有工具库。当前 Codex 补丁库已经依赖执行服务器抽象，本阶段不为取得补丁能力一并移植执行服务器，也不维护修改版上游源码。
