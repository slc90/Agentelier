# 会话存档、执行记录与单写入者

`agentelier_session_store` 管理本次固定数据目录中的会话文件，依赖 Conversation 定义的 InitialSession、StoredSettings 和 SessionSummary，不依赖 Bevy、Bridge、账号或模型执行器。Conversation 不反向依赖存储。

## 初始记录的提交边界

Runtime 从已有数据环境的凭据路径取得同一父目录；Store 仅写入该目录下的 `sessions/<uuid>/`，不读取认证文件，也不改变数据环境占用。会话 UUID 贯穿 Conversation、Bridge、UI 和取消控制，连接 operation ID 仍为本次进程内的独立身份。

Conversation 准备创建或 Reset，不立即替换当前会话。Store 工作者创建专属目录，将完整 JSONL 初始记录写入同目录临时文件，Flush 和 sync 后以不覆盖方式提交 `session.jsonl`。目录已存在时拒绝创建，不清理既有目录。初始记录提交前的失败只清理本次新建的空目录，清理失败保留实际错误。

每条记录有 `format = agentelier.session`、`version = 1`、`sequence` 和类型字段。初始 Created 记录序号为 1，之后的事件由同一写入者统一递增；实际提交身份和序号通过回执交给 Runtime 或 Runner。事件带所属会话、记录时间和 Conversation 定义的类型，不从界面文本还原协议。

初始名称为“新会话”；第一次接纳普通输入或待办输入时，使用首个非空片段的前 40 个字符作为本地标题，不发起命名模型请求。权威记录提交后，再完整替换可重建的 `summary.json`，保存标题、创建时间、最后活动时间、最后序号及删除状态。输入接纳、Steer 接纳和任务终态更新活动时间，流式片段不更新排序字段。摘要失败单独返回并记录错误，不能将已经提交的记录解释为不存在。写入者首次接管及目录扫描按日志重建摘要状态，丢失或落后的摘要可以重建，不能用于构造模型请求。

## 扫描与读取不依赖认证

Runtime 建立后主动扫描本数据根的受控 UUID 目录，按权威活动时间倒序及 UUID 的稳定次序返回安全条目，并在没有当前会话时打开第一份。UI 提供固定左侧平铺会话列表与刷新入口；读取不要求模型目录或认证成功，打开失败保留当前内容。初始扫描、目标加载和账号处理沿独立回执推进，文件操作仍只在 Store 工作者执行。

逐条检查文件格式、会话身份和连续序号，并保留损坏位置。有效日志的摘要在扫描时核对并按需完整重建；读取或重建失败作为条目或本次操作的错误显示，不重置其他会话、凭据或提示词库。

无换行的残缺末行只恢复此前完整前缀。准备继续写入时，先同步保存 `session-before-recovery-*.jsonl` 原件，再核对前缀 SHA-256，通过临时文件完整替换有效前缀与 Recovered 说明，重新接管写入位置后才交付打开成功。中间坏记录、重复序号、未知格式或损坏附件不自动覆盖原文件。打开与规范化不更新活动时间。

业务恢复由 Conversation 解释，模型层验证协议项并构造中断占位，附件由 Store 受控读取；Store 不执行历史命令。新旧身份与队列合并见[会话与协议历史](conversation.md#恢复只还原数据)。

## 记录与副作用的先后关系

Runner 保存普通输入和输入身份，完整模型响应通过业务校验后先保存整个协议输出；每个工具开始之前确认开始记录，返回后立即保存实际状态与类型化结果。图片结果引用已提交的会话附件。全部结果封闭后记录工作历史；失败或取消仍保留此前提交的步骤，部分流式展示只在收尾时记录，不逐 token 刷盘。

ProtocolArchive 由 LLM Model 解释原始助手、reasoning、函数调用与 call_id 配对。文字结果保持文字，图片保持描述符，不将 ToolView 文字当作原始载荷。存储只序列化业务事件，不执行旧工具、不构造模型请求，也不将不透明协议正文写进 tracing。

Steer 在可靠接纳回执之前保存接纳状态；实际进入下一次请求材料时保存应用状态、请求序号和工作历史。Queue 由 Conversation 准备变更，Runtime 等待同一写入者提交后才应用并返回回执；等待期间继续处理正文和凭据。队列变更只合并自己的队列字段，迟到回执不能覆盖任务状态或解除失败后的暂停。

工具进程收尾后，Runner 记录 Finalized，保留停止、失败时的部分展示、未应用 Steer 和独立进程清理报告。Runtime 真正回收任务句柄后再记录 Finished，确认提交才向界面交付终态并决定是否启动队列；终态保存期间继续处理账号命令，普通替换仍被拒绝。

每次追加都完整写入、Flush 和 sync，提交前核对已知文件长度。外部改动、残缺末行、未知格式或不连续序号会拒绝追加；发生未确认写入后该会话写入游标被阻断，不盲目重试。调用批次或开始记录失败时不启动副作用；已经取得工具结果后保存失败，保留内存载荷，停止后续请求和工具，阻止继续执行并暂停队列。保存失败不表示已修改的文件被撤销。

Runtime 等待创建结果时继续消费账号、凭据及控制命令；等待期间拒绝启动另一项模型、会话或队列操作。成功后核对提交 UUID 和当前账号身份，再安装准备好的 Session；账号在等待期间变化时保留磁盘存档但不切换旧投影。初始记录不含账号所有权字段。

## 工作者的真实结束

Store 使用容量 16 的命令通道和独立阻塞 I/O 线程。命令接纳、权威记录提交及线程退出分别表达；等待者消失不取消已开始的操作。所有文件句柄在该次操作结束前同步并关闭。Runner 取得可克隆的有界客户端，任务真实回收后释放客户端，再关闭 Store；客户端不拥有第二个写入线程。

## 附件只引用本会话已提交的内容

图片存于 `sessions/<uuid>/attachments/<sha256>.png` 或 `.jpg`，摘要仅接受 64 位小写十六进制，扩展名由实际支持的 MIME 选择。逐级核对 sessions、会话和附件目录的规范父目录并拒绝重解析点；读取最终文件时以 OPEN_REPARSE_POINT 打开，再核对普通文件和真实长度。不会将原始项目路径作为恢复候选。

单写入者将原发送载荷写入同目录临时文件，Flush、sync、核对完整编码内容后以不覆盖方式提交。已有同摘要文件必须重新核对，不覆盖损坏内容。临时文件失败显式关闭，清理失败报告实际路径。提交成功后才返回 StoredImage；这个引用保留来源说明，不携带 Base64。

Tools 的受限构造接口按描述符验证 MIME、长度、发送尺寸、静态格式与 SHA-256，完整解码核对有效性，但保持编码字节不变。Store 的受控读取用同一接口重建 ImagePayload。Runner 在保存后读回已提交附件用于后续协议，源文件之后改动不会影响该载荷。原始读取预算、单图 4 MiB、发送最长边 2048、工作上下文累计 16 MiB 和请求 32 MiB 的限制均保留；磁盘附件不按活跃上下文预算自动删除。

普通关闭先停止接纳运行命令，回收模型执行，关闭 Store 的发送端并等待已接纳操作排空、真实 join 存储线程，再结束 Account 与 Tokio。收尾中的在途创建仍核对实际结果，存储失败向运行收尾传播。辅助 Job、日志和数据目录锁继续由原宿主顺序收尾。
