# 会话存档、执行记录与单写入者

`agentelier_session_store` 管理本次固定数据目录中的会话文件，依赖 Conversation 定义的 InitialSession、StoredSettings 和 SessionSummary，不依赖 Bevy、Bridge、账号或模型执行器。Conversation 不反向依赖存储。

## 初始记录的提交边界

Runtime 从已占用的数据环境取得本次运行的根目录；Store 仅写入该目录下的 `sessions/<uuid>/`，不读取认证文件，也不改变数据环境占用。会话 UUID 贯穿 Conversation、Bridge、UI 和取消控制，连接 operation ID 仍为本次进程内的独立身份。

Conversation 准备创建或 Reset，不立即替换当前会话。Store 工作者创建专属目录，将完整 JSONL 初始记录写入同目录临时文件，Flush 和 sync 后以不覆盖方式提交 `session.jsonl`。目录已存在时拒绝创建，不清理既有目录。初始记录提交前的失败只清理本次新建的空目录，清理失败保留实际错误。

每条记录有 `format = agentelier.session`、`version = 1`、`sequence` 和类型字段。初始 Created 记录序号为 1，之后的事件由同一写入者统一递增；实际提交身份和序号通过回执交给 Runtime 或 Runner。事件带所属会话、记录时间和 Conversation 定义的类型，不从界面文本还原协议。

初始名称为“新会话”；第一次接纳普通输入或待办输入时，使用首个非空片段的前 40 个字符作为本地标题，不发起命名模型请求。权威记录提交后，再完整替换可重建的 `summary.json`，保存标题、创建时间、最后活动时间、最后序号及删除状态。输入接纳、Steer 接纳和任务终态更新活动时间，流式片段不更新排序字段。摘要失败单独返回并记录错误，不能将已经提交的记录解释为不存在。写入者首次接管及目录扫描按日志重建摘要状态，丢失或落后的摘要可以重建，不能用于构造模型请求。

## 扫描与读取不依赖认证

Runtime 建立后主动扫描本数据根的受控 UUID 目录，按权威活动时间倒序及 UUID 的稳定次序返回安全条目，并在没有当前会话时打开第一份。UI 提供固定左侧平铺会话列表与刷新入口；读取不要求模型目录或认证成功，打开失败保留当前内容。初始扫描、目标加载和账号处理沿独立回执推进，文件操作仍只在 Store 工作者执行。

逐条检查文件格式、会话身份和连续序号，并保留损坏位置。有效日志的摘要在扫描时核对并按需完整重建；读取或重建失败作为条目或本次操作的错误显示，不重置其他会话、凭据或提示词库。

无换行的残缺末行只恢复此前完整前缀。准备继续写入时，先同步保存 `session-before-recovery-*.jsonl` 原件，再核对前缀 SHA-256，通过临时文件完整替换有效前缀与 Recovered 说明，重新接管写入位置后才交付打开成功。中间坏记录、重复序号、未知格式或损坏附件不自动覆盖原文件。打开与规范化不更新活动时间。

Conversation 从连续的响应、开始、实际结果及追加记录重建各来源调用。Recovered 记录本次补入结果的原响应序号、call_id 和恢复依据。已有结果引用原保存序号，旧 Recovered 快照仍可读取。最终日志追加或尾部修复的回执确认后才安装恢复状态。模型层验证协议关联，Store 受控读取和校验实际结果引用的附件。新旧身份与队列合并见[会话与协议历史](conversation.md#恢复只还原数据)。

长期记忆后台通过同一个 Store 工作者列出会话 ID 并读取只读来源快照。快照使用权威日志的连续提交序号和 SHA-256，选取已结束的 Turn，暂缓当前仍在执行或尾行不完整的来源。会话已提交删除标记但目录清理尚未完成时，记忆候选仍按删除事实排除。读取快照不执行会话恢复、摘要写回或附件读取。

记忆重置由同一工作者读取全部现存会话的有效提交序号与最后轮次身份，包括正在执行的会话。如果存在损坏日志，会话存储返回读取失败，Memory 保留原有提取边界。

## 记录与副作用的先后关系

Runtime 提交普通输入与输入身份。Conversation 校验完整模型响应后，`Response` 在同一条记录保存原始协议输出、追加位置、异步任务登记和本次确认的交付集合。开始与返回记录携带任务与执行实例身份。提交回执后才允许派发或公布任务状态。图片结果引用已确认的会话附件。`ResultAppended` 通过保存序号、原 `call_id` 和历史区间引用已有结果记录，逐个确认结果进入历史。

ProtocolArchive 由 LLM Model 解释原始助手、reasoning、compaction、函数调用与 call_id 配对。文字结果保持文字，图片保持描述符，不将 ToolView 文字当作原始载荷。存储只序列化业务事件，不执行旧工具、不构造模型请求，也不将不透明协议正文写进 tracing。

Runtime 收集独立句柄的终态。Runner 在请求边界按保存序号把结果追加到历史。同一会话可以有来自不同 Turn 的待收齐响应，迟到记录通过原 `call_id` 和执行实例找到来源请求。收齐某个响应的结果后写入 `ResponseClosed`，引用原响应序号。旧存档仍可读取批次快照 `Sealed`。裁剪工作窗口的 `Compacted` 绑定冻结历史的序号、项数、前缀摘要和替换前缀。恢复核对原前缀和替换边界，并在新窗口接回已确认尾部。旧封闭批次的检查点仍可读取。单写入者完成 Flush 和 sync 后确认检查点。队列和改名记录独立提交，保持历史覆盖位置。检查点确认后才替换工作窗口。恢复优先采用已经确认的替换窗口，保留完整时间线与附件。提交状态不确定时，继续发送之前须重新加载存档。

Steer 在可靠接纳回执之前保存接纳状态；实际进入下一次请求材料时保存应用状态、请求序号和工作历史。Queue 由 Conversation 准备变更，Runtime 等待同一写入者提交后才应用并返回回执；等待期间继续处理正文和凭据。队列变更只合并自己的队列字段，迟到回执不能覆盖任务状态或解除失败后的暂停。

任务取消请求、停止全部的派发暂停与已核查的远端效果确认使用独立提交，恢复沿调用身份重放。MCP 无法确认的终态仍保留在原调用结果中，提交确认只解除对应调用的后续派发门槛。

进程登记、退出及消费独立保存，使用会话、创建 Turn、原始调用和执行实例关联。退出记录保留有界输出和实际清理证据。提交确认才释放进程持有的独占许可。恢复只重建摘要，旧进程不再可控制。

来源记忆读取已确认日志，由 Conversation 组装最早的连续完整 Turn。Store 分开返回读取水位及来源修订。队列、进程尾部消费等无关记录可推进读取水位，来源修订仅随纳入的证据改变。

Runner 在合法前台边界记录 Finalized，保留已确认历史、未应用 Steer 和相关清理报告。Runtime 真正回收前台句柄后再记录 Finished。原生会话的前台终态可包含已接纳的异步调用，追加结果与批次关闭按原调用身份继续。Finished 确认才释放前台，关闭时仍以真实回收和保存为准。

每次追加都完整写入、Flush 和 sync，提交前核对已知文件长度。外部改动、残缺末行、未知格式或不连续序号会拒绝追加；发生未确认写入后该会话写入游标被阻断，不盲目重试。调用批次或开始记录失败时不启动副作用；已经取得工具结果后保存失败，保留内存载荷，停止后续请求和工具，阻止继续执行并暂停队列。保存失败不表示已修改的文件被撤销。

Runtime 等待创建结果时继续消费账号、凭据及控制命令；等待期间拒绝启动另一项模型、会话或队列操作。成功后核对提交 UUID 再安装准备好的 Session；本地会话不受创建账号归属约束。初始记录不含账号所有权字段。账号变化的 QueueSuspended 通过相同写入者提交，不携带凭据或覆盖历史；暂停保存失败阻断执行并显示真实存储错误。

## 工作者的真实结束

Store 使用容量 16 的命令通道和独立阻塞 I/O 线程。命令接纳、权威记录提交及线程退出各自确认。Runtime 转交 Runner 的记录与附件操作，在等待实际确认时仍处理会话控制和账号事件。所有文件句柄在操作结束前同步并关闭。

## 附件只引用本会话已提交的内容

图片存于 `sessions/<uuid>/attachments/<sha256>.png` 或 `.jpg`，摘要仅接受 64 位小写十六进制，扩展名由实际支持的 MIME 选择。逐级核对 sessions、会话和附件目录的规范父目录并拒绝重解析点；读取最终文件时以 OPEN_REPARSE_POINT 打开，再核对普通文件和真实长度。不会将原始项目路径作为恢复候选。

单写入者将原发送载荷写入同目录临时文件，Flush、sync、核对完整编码内容后以不覆盖方式提交。已有同摘要文件必须重新核对，不覆盖损坏内容。临时文件失败显式关闭，清理失败报告实际路径。提交成功后才返回 StoredImage；这个引用保留来源说明，不携带 Base64。

Tools 的受限构造接口按描述符验证 MIME、长度、发送尺寸、静态格式与 SHA-256。Store 的受控读取用同一接口重建 ImagePayload。Runtime 保存并读回已确认附件，再交给 Runner 提交工具结果。原始读取预算、单图 4 MiB、发送最长边 2048、工作上下文累计 16 MiB 和请求 32 MiB 的限制继续适用。

生成原图存于同一附件目录下的 `generated-<sha256>.png` 或 `.jpg`。原图字节按独立的 32 MiB 单文件及 256 MiB 会话预算保存。写入者在同步落盘并校验可解码内容后返回路径。Runner 随后提交带原始 Turn、调用 ID、提示词、图像模型和描述符的 ToolReturned。恢复沿该记录在所属会话内校验文件。若文件提交后日志提交未确认，已留下的文件计入预算，恢复依据日志决定工具终态。

生成图片的模型回看材料从 Store 读取已确认原件后派生，沿普通有界图片附件路径提交。同一 ToolReturned 记录关联原图、派生图和原始调用，历史恢复从各自描述符核对附件。

草稿音频在后台完成读取和解码校验，再由 Store 将原件提交为 `audio-<sha256>.wav` 或 `.mp3` 并追加 `AudioDraft`。恢复核对文件长度和摘要，再按后续 `Accepted` 记录重建草稿或带附件的用户输入。历史引用与外部文件路径无关，会话删除识别并清理相同命名的音频文件。

音频转写通过 `TranscriptionStarted` 记录输入附件、摘要、引擎和文稿版本，通过 `TranscriptionFinished` 确认完整文本、失败或取消。恢复以唯一版本配对开始和终态，仍缺少终态的记录显示中断。重新转写追加独立结果。

普通关闭先停止接纳运行命令，回收模型执行，关闭 Store 的发送端并等待已接纳操作排空、真实 join 存储线程，再结束 Account 与 Tokio。收尾中的在途创建仍核对实际结果，存储失败向运行收尾传播。辅助 Job、日志和数据目录锁继续由原宿主顺序收尾。

## 名称属于独立元数据

Conversation 校验单行非空标题，控制字符转换为空格，保留 Unicode 和路径样式文本。Renamed 作为独立日志记录与任务事件共用同一单调序号，不携带任务状态或协议历史。UUID 决定目录，名称不进入路径。最新手动标题覆盖默认取名并阻止后续输入再次取名；名称提交不更新活动时间。

Runtime 独立等待名称回执，期间继续处理任务、Stop 和凭据；Connection 以 operation 和目标 UUID 关联该回执，不释放活动聊天。权威记录提交后才更新列表和当前标题，摘要失败同时保留名称成功事实与可见错误，扫描从日志修复摘要。关闭等待已接纳名称操作完成后再结束存储工作者。

## 删除先提交事实，再清理自身目录

Deleted 元数据由同一写入者分配序号、Flush 与 sync；提交之前的错误保留正常会话。提交后拒绝加载和追加，并从普通列表隐藏，摘要落后不能覆盖日志中的删除事实。Runtime 将删除作为互斥替换操作，拒绝活动任务、加载、队列提交、名称写入和回收期间的删除，完成时只移除目标当前会话。

文件句柄关闭后，将受控 UUID 目录移到同一 sessions 根下的 `.deleting-<uuid>`。清理再次核对规范父路径和删除日志，只接受会话日志、摘要、恢复备份、临时文件与本会话附件，拒绝重解析点、额外目录和未知文件。逐文件删除，不递归跟随路径；删除日志最后移除，最终删除空目录。名称、工作目录和工具参数均不参与清理路径构造。

提交后清理失败仍保持逻辑删除，回执和侧栏独立显示残留错误。启动或刷新扫描继续核对并清理受控待删除目录，也处理仍留在原 UUID 位置的删除标记；失败单独返回，不挡住其他正常条目。已清空且没有日志的受控待删除空目录只执行空目录删除，不清理未知内容。此机制不提供回收站或恢复入口。

## 项目指令请求记录

单写入者新增 ProjectPublished 与 RequestPrepared 事件。前者保存完整来源、确定正文和可选候选历史，后者通过 StoredState 保存请求引用和安全投影。恢复不读取源文件；项目项有对应发布材料校验。只有实际追加协议项的项目事件推进历史覆盖序号，空快照和准备元数据不推进。

项目发布保留 Initial、Replacement、Removal 类型；相同内容不重复写来源。StoredState 额外保留最近采集错误，以便重开后区分旧材料与本次未发送。协议发布与用户成功保留仍是独立事实。

CompactionCheckpoint 额外保存源项目发布身份，安装与恢复时核对最后确认发布和源窗口。新窗口状态由检查点 window 与项目发布 window 共同持久表达；检查点之后尚未补发与已补发的恢复位置可区分，不依赖易丢失的内存标志。

RequestProgress 保存已准备请求的发送阶段与传输回执。HTTP 保存响应状态，Codex WebSocket 成功发送后保存所用连接的升级状态。请求进度属于元数据，不推进历史覆盖序号。冻结请求另存开放调用与压缩策略。ContinuedWithoutCompaction 用原失败请求及输入身份持久记录一次性继续，随后请求沿用原 Turn 且使用新序号。旧存档缺少这些字段时保留未知，不从完成气泡反推发送事实。历史核对所需的来源与最终包装正文全部来自 ProjectPublished，不因源文件消失而重新采集。

## 子 Agent 创建与执行记录

子 Agent 使用同一 Session JSONL 中的 `AgentCreated`、`AgentExecution` 与 `AgentTurn` 记录。身份记录包括父级及来源调用、冻结配置和独立历史起点。各条轮次记录关联子 Agent ID 和 Thread，承载内层 Runner 原有事件。单写入者确认外层 Session 后，以该 Thread 作为内部提交回执的归属。附件保存在所属 Session 的原有资源目录。重开时校验身份、记录顺序和 Thread 归属，缺少已确认终态的 Agent 保留身份并显示执行未确认。
