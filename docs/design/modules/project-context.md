# 项目上下文

`agentelier_project_context` 独立负责项目边界发现、规则链读取、来源快照与确定性表示，不依赖 Bevy、账号、提示词库、网络或会话存储。项目 `AGENTS.md` 作为具有独立发布身份的 user 协议项加入请求，不改变固定基础 developer 快照。

## 发现和材料边界

输入是当前会话已提交的规范绝对工作目录。向上寻找最近 `.git` 文件或目录作为边界，不执行 Git、不解析标记内容；没有标记时只检查会话目录。只沿边界到会话目录的路径从父到子读取 `AGENTS.md`，不扫描兄弟或下级目录，不加载全局规则、override、fallback 或 Markdown 引用。工具临时执行目录和会话的项目归属均独立于该工作目录。

长期记忆也使用规范工作目录作为项目内容的访问范围。结构化观察以各 Turn 接纳时的目录为准，修改会话目录只影响之后接纳的观察及检索。全局个人导航可跨目录使用，私有项目详情通过当前目录校验后读取，界面 Project 名称和身份不参与校验。见[长期记忆](../mechanisms/long-term-memory.md)。

每个来源保存原始路径、作用目录、完整正文和 SHA-256。快照保存会话目录、可选项目边界、有序来源、原始字节数及确定的模型可见表示和摘要。正文按严格 UTF-8 解码，仅去掉一个文件开头 BOM，其他换行和空白保留。空白来源仍可核对，但不形成规则正文；无有效正文时渲染文本为空。有效表示包含目录范围与来源顺序，不含时间戳或文件修改时间，相同内容重存不改变摘要。

整条链的原始文件材料合计上限为 32 KiB，BOM 和空白文件都计入。每次读取最多取得剩余预算加一个探测字节，超过预算整体失败，不发送残缺内容。失效目录、读取错误、非普通文件、无效编码及超限均明确失败，不解释为空。文件链接沿普通读取语义跟随目标，失效链接保留错误；探测后消失的普通规则文件视为本次未发现。路径读取和比较使用路径值，仅在 UI 通过路径显示库格式化。

## 执行和展示所有者

Runner 在每个逻辑模型请求前重新发现并有界读取整条链，包含工具批次封闭后的继续推理、后续输入、主动 Retry 和实际启动的 Queue 任务。同一批次工具之间不刷新；认证内部重发只用冻结字节。同一工作窗口内，相同模型可见内容沿用原发布；变化追加完整替换，确认由非空转空追加清除，持续为空不重复清除。旧协议前缀不改写。压缩后的窗口重新发布依据见[项目指令设计](../project-instructions/README.md)。

采集在 `spawn_blocking` 中执行，取消令牌在目录发现和文件读取之间协作式检查；Runner 始终等待真实工作句柄结束，Stop 不遗留脱离任务的文件工作。读取失败作为普通 Failed 终态归还可信活动记录，不设置永久 `execution_blocked`，保留原输入的重试资格；工作者异常、存储不确定或进程回收失败仍沿原有阻断路径处理。

最近采集状态由 Conversation 持有，通过 SessionView 发布。状态区分尚未采集、成功为空、取得规则和失败；失败时可以保留上次成功材料供核对，并明确本次未重新确认、没有发起模型请求。首次成功快照（包括空快照）通过 ProjectPublished 记录持久保存，重开存档使用保存的来源恢复，不重读项目文件；无项目记录的旧存档显示尚未采集，不从聊天正文猜测来源。

Conversation Bridge 显式转换状态、路径、摘要和来源正文；UI 不读项目磁盘。现有“会话与请求核对”入口提供来源展开、作用目录、摘要及独立的 `WidgetryReadOnlyTextField` 原文。展开选择按会话保存，普通页面重建可以恢复；规则不会伪装成用户聊天消息。正文允许导航、选择、复制和控件滚动，UI 不将只读控件设为 Disabled，也不直接写内部 EditableText。

普通日志只记录来源数量、字节数、摘要和错误，不输出项目正文、聊天或凭据。采集成功表示取得材料，不表示模型收到规则或遵守规则。

## 请求准备和持久发布

ActiveTurn 拥有发布和协议历史。首次取得规则生成类型化 ProjectItem，空快照只保存来源事实。Runner 确认 ProjectPublished 后安装候选历史，再经模型层 prepare 完成同一份请求的组装、冻结字节及安全摘要；确认 RequestPrepared 后才调用 generate。网络及认证恢复只使用冻结字节，不重新构造请求。项目规则来源链上限为 32 KiB。

项目全文只保存在发布事件中，后续准备记录以发布身份引用材料，包含窗口、Turn 内请求序号、基础摘要、有序协议类型、载荷字节数与 SHA-256。自动项目项独立于普通 User，即使用户粘贴同名标题也不改变类型。完整原始输出、reasoning 和工具结果的对应关系保持不变。项目项和 user 角色包装参与 token 估算，来源存档不另行重复计量。

项目发布实际追加历史时才推进 source_sequence，空发布和请求准备元数据不推进。项目确认后准备失败仍保留项目，不发 HTTP；提交结果不确定沿原有历史确认阻断路径处理。自动项目项不推进 committed_steps，也不将待发送用户输入变成已保留输入，因此请求失败后仍按原有资格 Retry。恢复校验来源路径、范围、顺序、完整正文和摘要及发布引用，不依赖当前源文件。

## 压缩后的明确发布

完整来源及发布身份保存在活动历史之外。已确认发布的 window 与 ContextState.window 一起决定当前窗口是否已明确发布；不从 compaction 密文猜测原文。检查点记录其覆盖的项目发布身份，恢复与安装均校验该身份。只有持久确认并安装新窗口后，窗口差异才触发下一请求的重新发布；失败或取消不提前推进窗口。

新窗口第一次成功采集有规则时追加一份 Republished 完整替换；曾有规则而当前为空时追加 RepublishedRemoval。始终为空仅记录新窗口确认事实，不制造空消息。文件变化和窗口变化合并成一次最新状态，确认后同窗口未变化请求不重复。采集失败不改变发布窗口，重开存档按已确认项目事件及检查点恢复位置。项目实际发布推进历史覆盖序号，准备元数据不推进。原始 compaction、reasoning、调用和结果顺序保持，来源存档和旧请求仍可核对。
