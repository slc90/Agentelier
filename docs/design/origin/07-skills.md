# 探索、写作与创作 Skills

## Skill 管理工作方法，人格仍由 Origin 身份提供

Origin 不需要为日常聊天、代码、数学、科研和动漫分别准备角色卡。固定人格与本轮情境规则决定表达方式；只有需要可复用、步骤明确的工作流程时，才加载 Skill。

Agentelier 当前 Skills 机制发现用户数据目录中的标准 `SKILL.md`，支持显式 `$skill-name` 和按描述隐式匹配，并在实际请求中冻结读取结果。当前内置 Skill 为 `skill-creator`；本设计只增加用户级 Skills，不恢复 Project Skill，也不创建第二套 Skill 商店或管理器。

## `origin-explore`：从资料中形成值得继续的问题

适用于用户明确要求深入探索、专题研究、从已有材料继续追问或验证假设的任务。不用于普通知识问答、随口聊天或仅仅提到一个兴趣。

工作流程：

1. 明确用户给定的范围和实际资料来源。
2. 阅读已提供或明确获准取得的材料，区分全文、摘录和缺失内容。
3. 选择一个有价值的问题，或直接回答用户明确提出的问题。
4. 区分观察、推断、假设和未知；数学问题给定义、推导与反例，科研问题区分数据、方法、相关性和因果，代码问题依据当前源码和真实工具结果。
5. 只有存在实际新发现时，才提出有理由的后续关注；可选择继续、等待或结束。
6. 实际结果进入正常 Session 历史，后续由 Memory 后台提取，不要求每次额外写日记。

Skill 不会自动获得联网、文件修改、外部发送或安装权限。缺少工具或资料时说明缺口，提出的探索方案不等于已经执行。

## `origin-write`：生成适合用途的独立文档

适用于用户要求撰写、整理或修改独立文档，例如设计说明、技术方案、研究报告、分析备忘录、项目说明和正式邮件。普通聊天中的解释、观点讨论和简短回答不自动触发。

工作流程：

1. 确认文档目的、读者、交付格式和用户明确要求的文体。
2. 识别来源材料、已确认事实、待确认内容和不可擅自补全的缺口。
3. 根据内容组织阅读路线和主题结构，不套统一报告模板。
4. 先把设计思路或研究问题说明清楚，再展开机制、证据、例子和必要细节。
5. 检查术语、事实、引用、结构和交付格式；需要文件时核对真实文件与保存位置。

文档本身采用读者需要的书面风格。Origin 的人格体现在判断、取舍、清晰度和表达倾向，不把聊天口癖、感叹号或角色动作强行写进正式产物。用户已经指定某个文档工作流或风格时，优先遵循明确要求，不叠加互相冲突的模板。

## `origin-create`：把创意推进到真实产物

适用于需要交付实际创作产物的多步骤任务，例如视觉设计草稿、插画策划、故事、演示材料或本地媒体。讨论动漫情节、审美偏好或只写一句话不要求启动。

工作流程：

1. 理解创作目标、对象、格式、范围和参考素材。
2. 选择合适的方法，不把所有作品套成同一种形式。
3. 在当前已授权工具范围内组织素材、生成内容或执行本地处理。
4. 检查成品是否存在、能否打开、是否符合要求；图像、音视频和文档分别检查实际产物。
5. 区分完成部分、失败部分和无法使用的工具；只报告真实结果。

用户只是讨论创意时不擅自生成文件。用户要求本地创作时遵循指定目录和范围；发布、上传、登录、投递等外部副作用仍需要既有权限和明确授权。本 Skill 不提供 B 站发布、评论、私信或账号运营能力。

## Skills 的选择与执行边界

| Skill | 主要触发 | 不应触发的情况 |
|---|---|---|
| `origin-explore` | 明确的深入探索、专题研究或证据验证 | 普通知识问答、随口分享 |
| `origin-write` | 需要独立文档或正式写作产物 | 只讨论一个观点、简单解释 |
| `origin-create` | 需要实际创意产物或多步骤创作 | 只聊动漫、审美或脑洞 |

三个 Skill 都安装在现有用户 Skill 目录，沿用现有管理窗口和按需读取机制。显式 `$origin-explore`、`$origin-write`、`$origin-create` 可以指定工作流；隐式匹配应由任务描述触发。修改或删除用户 Skill 时，正在执行的任务继续使用本轮已冻结内容。

## 防御性边界

- Skill 只定义工作流程，不改变 Origin 身份，不授予额外工具权限。
- 记忆学习不能自动创建、安装或修改可执行 Skill。
- 不预装 B站、浏览器运营、自动评论、定时发布、Live2D 或其他外部平台 Skill。
- 任何媒体或文件能力都以当前 ToolCatalog 中实际存在的工具为准。
