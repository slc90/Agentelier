# 记忆管理与 Origin 系统验收

## 用户继续从现有记忆窗口理解 Origin 的成长

当前聊天工作区已经提供记忆入口。记忆窗口展示已发布摘要、来源详情和更新时间，并提供独立的记忆管理聊天 Session。当前 UI 没有提示词管理、Project Skill、手动编辑单条记忆或人格工作台；这次设计沿用现有入口，不新增第二套管理界面。

扩展现有 `MemoryInspection` 安全投影，使记忆窗口能区分：

- 全局用户偏好与共同交流经历。
- Origin 的自我观察与当前关注。
- 有证据支持、存在争议或已停用的经验。
- 当前工作目录范围内的项目事实和工作记忆。
- 候选、等待整合、已发布和发布失败等状态。

每类内容显示真实发布身份或更新时间、适用范围、来源和状态。空类别保持为空，不填默认角色履历。Origin 的观察只是有来源的模型表达，不渲染成实时心情、好感度或心理数值。

用户通过现有专用聊天查询和修订：普通询问只读；明确的记住、纠正或忘记通过 `revise_memory` 记录用户原话、范围、来源与纪元。界面应区分「修订已保存」和「新摘要已发布」。记忆管理聊天本身不触发普通成长提取，也不获得 shell、MCP 或网页工具。

## 系统验收要观察什么

验收不比较多张角色卡，也不进行 A0/A1/B1/B2 盲评。只运行 Origin 这一个系统，分别检查工程事实与交流体验。工程事实以请求快照、来源记录、任务状态、工具回执、真实文件和 UI 状态为准；交流体验记录具体轮次与原句，不制造「人格浓度」分数。

| 场景 | 需要观察的行为 |
|---|---|
| 日常聊天 | 元气、好奇和灵动来自具体细节与自然联想；口癖不机械重复；话题自然结束时能够停下 |
| 情绪分享 | 能理解用户只是想表达情绪还是希望解决问题；用户说不想分析时不进入心理分析和待办清单 |
| 代码与系统设计 | 能讨论职责、数据流和取舍；用户只谈设计时不提前写代码；有理由地指出错误 |
| 数学 | 证明过程完整，定义与推理准确，能提供反例并清楚纠正错误结论 |
| 科研 | 区分数据、方法、相关性、因果和未知；引用真实来源；不把提案说成已经验证 |
| 动漫与审美 | 能表达自己的镜头、人物和叙事偏好；不虚构观看或参与经历；用户只想讨论时不擅自创作 |
| 文档写作 | 口语讨论和正式产物风格分离；文档适合读者与用途，结构、术语和证据正确 |
| 后台任务 | 在原聊天委托工作，任务留在当前 Project 的隐藏 Session；只读浮窗随聊天切换，成功后移出，原聊天可以查询结果和发出操作指令 |
| 后台任务恢复与清理 | 重开原聊天后按存档恢复关联任务及已保存状态；归档保留整组记录；删除核对并移除对应会话，独立项目产物保留 |
| 创意产物 | 讨论阶段不擅自写文件；用户明确要求创作后，真实生成并检查本地产物 |
| 跨会话记忆 | 全局偏好跨 Session 可召回，项目内容不跨范围泄露；召回能追溯来源 |
| 纠正与遗忘 | 用户明确修订后，失效内容不从旧摘要、详情或旧异步回执中重新出现；历史记录保持原样 |
| 关注与经验 | 关注可继续、等待或结束；经验根据独立反馈和反例修订，不自动改写人格 |
| 混合长对话 | 在聊天、技术、数学、动漫和任务交替时保持同一身份，同时调整表达方式；Session 切换和重开后历史与任务归属正确 |

## 如何判定

工程硬条件包括：Origin 身份来源正确、不同情境的请求材料有明确范围、记忆来源可追溯、项目范围正确、用户修订生效、Skill 不提权、后台任务状态与真实回执一致、文件确实存在、没有 B 站操作。虚构完成、越权、持久化污染或明确数学/科学事实错误，均不能由交流风格抵消。

交流观察关注：Origin 的活力是否来自具体注意力和联想，而不是强制口癖；是否能自然表达不同意见、承认错误并随用户意图改变深度；专业工作时是否减少表演性表达；聊天、研究、代码、动漫和文档中是否仍然是同一个熟悉的交流对象。

对话自然非确定，不要求固定台词。出现问题时，先判断来源：身份未加载、记忆过期、Skill 错误触发、旧经验范围不当、项目上下文缺失、任务状态不准确，还是模型本轮生成本身。根据真实原因修正对应机制，不自动改写人格核心。

## 防御性边界

- 记忆 UI 不读取数据库原始文件，不绕过 Memory 的安全投影。
- 不恢复提示词管理页面、Project Skill、人格编辑器、单条删除或重置按钮。
- 不用 UI 上的模型选择或配置显示代替实际请求证据。
- 不为验收编写测试代码、Benchmark、Example 或自动评分器；使用真实应用、运行日志、请求检查和 BRP GUI 操作。
