# 多项工作怎样执行、等待和停止

## 每次执行带着自己的来源

独立运行首先要求独立输入。当前 `ExecutionContext` 同时持有目录、图片能力、进程表和 `ToolUserTurn`，Executor 在整个 future 生命周期里借用其可变引用。目标把它分成固定的调用材料与有明确所有者的共享资源。

调用材料在接纳时固定：工具来源与参数、会话与原始 Turn、工作目录、模型图片能力、用户陈述、显式技能来源及记忆纪元。后来的 Steer 只影响它被实际应用之后的新调用，不改写已经开始的任务。旧任务不能从“当前 Turn”动态读取新的用户授权。模型身份与请求权限继续由前台任务的 `ExecutionIdentity` 管理；后台工具不能自行启动模型请求或自行续签另一套身份。

进程表、准入许可与执行句柄由会话范围的运行资源持有。Tools 提供工具执行和资源控制，Runtime 持有并回收真实句柄；Conversation 保存业务身份和可恢复状态，不持 OS 进程、锁或 Tokio JoinHandle。固定材料可以被独立任务持有，共享资源必须经过受控接口，不能用一把覆盖整个 future 的可变上下文锁把所有工作重新串起来。

## 登记之后，才决定什么时候真正开始

完整响应通过验证后，在同一次提交中记录响应和任务登记映射。提交成功才进入准入。每个执行开始前必须确认对应的开始记录。等待期间取消的调用可以形成明确的 `NotExecuted` 结果。

每次完整响应都按稳定顺序接纳获准的调用，再按资源许可调度。会话所有者持续结算旧结果的交付状态，只有包含该结果的完整响应通过验证才确认交付成功。历史身份记录继续保留，旧 ID 不得复用。此前因登记额度拒绝的调用仍可按存档结果恢复。

## 并发许可与异步声明分开

参考 Codex 对可并行和独占工具的区分，本次采用会话范围的共享只读与独占副作用许可。工具注册者声明可解释的并发策略；模型提供的参数、工具文字说明或 MCP 的只读提示，不直接提升权限。

| 类型 | 调度规则 |
| --- | --- |
| 经应用确认的独立只读操作 | 共享许可，可以和其他共享操作并行 |
| 任意 shell、文件修改、未知 Extension/MCP 副作用 | 独占许可，同一会话中的这类操作按接纳顺序执行 |
| 某个既有进程的输入输出 | 使用该进程自己的串行控制入口，可以控制其已经持有的许可 |
| 任务列表、等待、取消和 UI 控制 | 走独立控制通道，不取得被等待工作的资源许可 |

这是一种保守的准入策略。它能避免应用自行制造的已知交错修改；任务可以同时登记，只有取得许可的任务真实执行。它不分析 PowerShell 文本来猜测任意文件访问，也不新增通用资源调度平台。

等待准入的任务可以取消。共享和独占操作使用公平的许可队列，后来的只读工作按顺序等候已经排队的独占工作。开始执行前再核对取消和会话执行状态。

执行器的终态载荷通过真实任务句柄归还，由 Runtime 收集并归并；它不依赖可以合并或丢弃的 UI 进度通知，也不因前台取消而停止投递。唤醒丢失时可从已完成句柄和账本重新检查，不能把唯一一份工具结果放在一个随旧 Turn 关闭的通知通道里。线程或 future 异常退出也必须转成有来源的未知/失败事实，并触发必要的资源回收。

普通 shell 创建的进程继续持有副作用许可，直到真实结束并完成持久回收。显式后台启动在持久登记后释放启动许可，进程句柄仍归会话所有。普通同步工具遇到活进程独占时，在同批进程控制结束后返回未执行及阻塞 ID，让模型可以使用专用控制入口。

## 用稳定 ID 查询和等待

原工具的参数 schema 保持不变。应用接纳调用后分配任务 ID，通过三个自定义同步管理工具暴露控制能力。这些工具进入同一个 Direct 工具目录，使用同样的调用记录与结果保存路径。

| 工具 | 本次契约 |
| --- | --- |
| `list_async_tasks` | 查询本会话任务，返回任务 ID、原始 Turn、工具来源、安全参数摘要、执行/保存/交付状态和资源阻塞原因；不把真实工具结果复制成另一份输出 |
| `wait_for_tasks` | 接受非空、去重的已知任务 ID，`mode` 为 `any` 或 `all`，等待上限 30 秒；返回状态快照，超时只结束此次等待 |
| `cancel_async_tasks` | 接受明确 ID 集或明确的全部后台范围，回报取消请求与可确认状态；不把“已请求取消”伪装成资源已经停止 |

列表默认优先显示全部未完成交付项目，同时显示仍持有活进程或未消费退出结果的来源调用，即使原函数结果早已用于成功请求。此类行包含 `session_id`、来源任务/Turn、进程状态及许可阻塞，使模型在历史压缩后仍能发现需要控制的进程。已处理历史通过明确 ID 或有界分页查询。单页至多 64 项，超过时给出可继续查询的游标/剩余状态，不悄悄丢项；结果仍受 64 KiB 文本限制。参数摘要遵守现有脱敏和输出边界，不暴露凭据、推理密文或完整危险大载荷。

`wait_for_tasks` 的 `all` 是所有指定任务都达到可报告终态，`any` 是至少一项；失败、取消、超时和未执行都属于终态。执行器已结束但结果尚未持久提交时，任务仍不可报告为结果可用。相关新结果必须能通过唯一出口排在 wait 自身状态之前；保存失败使等待明确失败并阻断后续采样，而不是返回“完成”。

已终止任务立即返回状态，已进入历史的结果不再追加。空集、重复 ID、未知 ID、其他会话 ID 都直接产生控制工具错误，不等待未来某个同名任务。等待订阅先建立、再检查账本；收到唤醒后重新检查条件，不能用一次通知代替条件本身。

同批调用先登记全部异步 launch，再执行管理工具。因此 `launch + list` 能看到本批任务。但应用分配的 ID 在模型生成这批输出时尚不可知：点名等待新任务需要先拿到列表，再发后续 wait。`launch + wait(猜测 ID)` 必须报未知 ID，不能自动匹配“最新任务”。

模型发出的显式 wait/cancel 以本次请求冻结时已存在的可引用任务集合校验，不能只查同批登记后的实时账本。即使猜测碰巧命中新分配 ID，也不得在这批中控制它；`list` 的结果在后续请求中才使新 ID 可用。模型的“全部后台”范围也按该冻结集合解释，UI 的全部停止则按用户动作被接纳时的真实会话范围解释。

普通调用等待独占许可时，不妨碍同批管理操作运行。尤其不能先同步 await 一个被旧进程阻塞的普通调用，再迟迟不处理能够终止该进程的控制操作；批次登记完成后，执行和管理各自推进，结果仍由统一历史出口收束。

等待期间继续处理 Stop 和 Steer。Stop 结束等待；Steer 接纳后结束旧等待，保存真实的等待状态/被补充中断事实，并在下一边界应用用户补充。两者都不借由“结束 wait”取消所有被等待的后台任务。

## 取消形成事实，回收确认资源

用户取消与任务自然完成可能同时到达。会话所有者串行裁决：已有持久完成结果时，取消为“已结束”；尚未开始时，记录未执行；正在运行时进入取消中，由执行器回报实际结果与回收情况。一次调用只形成一个协议结果。

已经产生的文件修改、已经写入的 stdin 和远端副作用继续如实记录。完成事实先到达并被确认时，不能用迟到的取消把成功改成取消；取消已经形成终态之后，迟到的进度/回报只用于核对同一执行实例与清理，不生成第二份结果。相互矛盾的终态阻断执行并保留诊断。

MCP 的取消通知送达不等于远端工作已停止。超时、断连或无法确认取消时，记录本地等待结束和远端效果未确认，不自动重试。未知副作用的许可不能因本地 future 消失而假装安全释放：暂停冲突工具派发与自动 Queue，并显示需核查的来源。用户核查后通过明确的“确认继续执行”动作，持久记录所确认的任务与范围，才解除相应派发阻塞；普通发言或 Queue 恢复不替代这项确认。原始“远端未确认”记录仍保留，不能改写为已证实停止。

这项确认只解除已经没有本地执行句柄、但外部效果未知的派发门槛。当前仍持有的待回收进程必须继续实际收尾；身份冲突、存储未确认也不能用它绕过。重启后没有可恢复句柄的历史未知记录是终止证据，不永久占用运行槽或阻止只读打开、切换和正常关闭；它对新副作用的暂停要求仍保留到明确确认。

普通工具失败只结束该任务，其他独立任务仍可完成并保存；只有持久化、身份冲突、资源回收未确认等破坏继续执行前提的问题，才阻断相关派发或整个会话的模型续接。超时沿用执行器实际契约，例如当前 MCP 调用的 60 秒超时；不为所有工具强加一个虚假的统一时限。无命令寿命上限的进程依靠明确终止和退出收尾管理。

## 进程会话成为独立资源

`exec_command` 的输出仍包含真实的 yield、输出片段与可选 `session_id`。原函数结果只能交付一次。进程登记同时保留会话、创建 Turn、来源调用、真实句柄和许可；后续 Turn 可用本会话仍存活的 ID 调用 `write_stdin`。其他会话或旧进程实例的 ID 立即失败。

同一进程的写入与输出消费保持串行，多个读取不能重复消费字节，非空 stdin 不自动重发。所谓控制可重入，只是允许 `write_stdin` 控制自己已持许可的进程，不是允许多个操作同时改它的输入输出。终止信号使用独立控制路径，不能被一次正在等待输出的 poll 永久挡住。

取消一次对旧进程的 poll/write，与终止该进程分开。取消停止本次等待或尚未完成的写入，并报告已经写入的字节；除非明确 `terminate`、取消其创建任务或触发会话收尾，不杀死旧 Turn 的进程。当前实现中“取消 poll 会杀进程”的行为需要随此契约调整。

进程退出后，资源所有者统一完成 wait/reap 和输出读取，保存必要的退出状态、剩余输出与清理事实，再释放许可。自动退出收集与 `write_stdin` 竞争时只能由同一个所有者推进输出消费位置，不能把同一尾部交付两次。

进程输出每流最多捕获 512 KiB，并记录截断或替换范围。交付给模型的单次文本结果受 64 KiB 约束。进程表达到 64 个软上限时，新调用优先收起最早创建且已持久化退出结果的登记。退出记录保留尾部摘要和退出码。正在运行的进程由原调用或用户控制，登记可暂时超过软上限。登记被收起前，`write_stdin` 可消费一次该进程的尾部输出。

切换/关闭前，该退出记录持久确认即可，不要求用户先读取；没有活句柄的尾部缓存不阻止替换。再次打开只显示已保存的资源终止摘要，旧进程 ID 仍不可执行，不把摘要重新追加成原函数的第二份 output。若后续模型需要解释这份历史摘要，由明确的任务查询结果提供带来源的终止状态与有界摘要，保持它与原函数输出的区别。

正常 Turn 结束不统一 cleanup。单任务取消在原 async 调用仍运行时也要停止它创建的进程；函数已完成之后，取消任务回报已结束，进程需要独立的终止操作。

## 各种结束的范围

| 动作 | 前台 | 后台与资源 | 后续模型请求 |
| --- | --- | --- | --- |
| 正常 final | 关闭接纳并真实回收前台 | 已接纳任务继续；进程继续 | Queue 按原规则；空闲结果只提示 |
| Stop 当前 Turn | 停请求、等待和本 Turn 派发 | 取消本 Turn 创建的工作；旧来源工作保留 | Queue 暂停，不自动因结果完成重启 |
| 取消某项 | 当前等待可被唤醒 | 只处理指定任务；回报精确范围 | 后续在合法边界交付其终态 |
| 停止全部后台工作 | 不伪装为一个普通工具结果 | 停止全部后台调用与存活进程，等待回收 | 暂停自动 Queue；前台可继续说明状态 |
| 切换、Reset、删除 | 由替换操作统一核查 | 有活动工作、未保存结果、未确认清理时拒绝 | 不隐式停止或迁移后台工作 |
| 用户主动登出/切号 | 停前台并暂停接纳 | 取消并回收当前会话工作，保存原来源结果 | 新身份下只由用户明确发起续接 |
| 正常关闭应用 | 关闭新接纳与派发 | 停工具、进程和等待，保存终态并 join | 排空 Store，再关闭 Account、Tokio 和宿主 |

账号动作延续已有身份隔离；开发验收不得为了覆盖该行擅自退出登录或重置凭据。正常关闭失败应显示真实的回收/保存错误；强制结束后按恢复规则处理，不假称上次已经完成清理。
