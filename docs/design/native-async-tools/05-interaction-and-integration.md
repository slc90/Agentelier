# 用户看到什么，模块各自负责什么

## 输入仍由前台 Turn 接纳

用户发送时若已有活动 Turn，继续走现有 Steer；显式排队继续走 Queue。没有活动 Turn 时才启动新 Turn。后台工具的存在不占用这个前台槽。

“关闭当前输入接纳”和“确认最终是否还有已接纳 Steer”必须在同一业务边界裁决。恰好撞上 final 的输入，要么明确属于当前 Turn 并在下一请求应用，要么得到已经结束的回执后保持草稿或由明确的新请求接纳；不能显示 Accepted 后静默丢弃，也不能既补充又新建一次。

参考 Codex 的 `start_or_steer`、输入队列与结束临界区，保留应用当前的 Accepted、Applied、NotApplied 差别。新输入不要求抢占或改写已经发出的 HTTP 请求，也不要求本次引入 WebSocket steering。

Stop、等待、工具结果和前台 final 都经过相同的会话控制边界。停止全部后台工作同时暂停新的副作用派发；正在返回的模型响应若又请求启动工作，应形成明确的未执行结果。只有用户明确恢复/开始新工作后才能解除这个派发暂停，避免“刚停止全部，模型又自动启动一批”。正在进行的前台文字回复可以收束。

## 状态展示同时回答两个问题

聊天区跟踪当前前台阶段，侧栏按 Session ID 合并前台与后台状态。转圈表示仍有工作，出现异常时优先显示红色感叹号。

任务的原消息工具卡保留稳定调用身份、来源 Turn、执行状态和已保存的结果。前台与后台状态都保留各自的业务水位。

对仍有进程的 `exec_command`，继续显示“调用已返回，进程仍在运行”，并提供进程终止入口。任务取消与进程终止使用各自的身份和可用状态。点击只发一次控制请求；按钮等待真实回执，在取消中避免重复提交，结果先完成时显示已结束。

进程已退出但仍有未消费结果时，显示退出码、剩余输出摘要和是否发生截断，允许查看或明确收起该可继续读取的登记。未知远端副作用单独显示“确认继续执行”，这项动作不出现在存储未确认或身份冲突等不可绕过错误上。非法压缩响应只提供与失败请求绑定的一次性“不压缩并继续”，普通 Retry 不得从头重跑已产生副作用的任务。

前台结束后，输入框可用，后台数量仍可见。空闲结果完成时，显示“已保存，待处理”和“处理已完成结果”。该动作无需用户再手工输入一句催问；它也不会自动产生原请求授权之外的副作用。新普通输入可以同时消费全部适合本请求的就绪结果，结果处理按钮不会重复追加它们。

## 会话事件与前台事件使用不同关联

现有 `ChatState.operation` 过滤仍用于拒绝过期前台响应。新增会话任务投影携带会话 UUID、任务 ID、执行实例和单调业务修订；接收端先核对会话与身份，再更新对应任务。

不能为了让旧结果出现而直接取消 operation 过滤。当前前台来自新 Turn、旧任务来自旧 Turn，两条关联分别有效；其他会话、已经关闭的执行实例或旧投影的迟到更新仍被拒绝。任务清单的修订与协议历史位置分开，不用 UI 排序变化使请求快照过期。

Bridge 只发布可展示字段，保留安全摘要的惯例。原始协议、隐藏 reasoning/compaction、认证信息和附件字节不进入 Reflect、UI 或普通日志。日志记录会话/Turn/任务/请求关联、提交序号、状态转换、数量和必要错误，用它证明时序；不以完整用户内容替代关联信息。

日志沿用宿主的单一订阅与持久化，正文使用中文，结构化字段使用英文。用户控制及明确业务结果使用适当的 INFO，执行阶段使用 DEBUG，真实错误进入错误处理并记录；正常等待和取消不被标成 WARN。必要的临时 TRACE 诊断在交付前移除，不新增专用日志框架。

空闲时任务完成也必须经过现有 Connection 和 Winit 唤醒链。窗口没有新鼠标输入时，应能更新后台计数和状态；不能依赖用户下一次敲键才刷新。后台调度仍属于 Agent Runtime，Widgetry 的辅助 JobManager 不成为第二个 Agent 执行所有者。

## 保留阅读和输入状态

界面沿用 BSN/Scene 组合，以 Props 完成构造初始化，运行期通过持久 Component 和 Widgetry 公开控件接口更新。刷新任务行时不重建整个聊天区、输入框或滚动容器。物理行复用不能把任务 A 的展开、取消或终止动作落到任务 B；动作捕获稳定任务身份，并在业务侧再次核对。

后台更新不抢键盘焦点、不清空草稿、不跳到底部、不打断用户展开的工具详情。状态变化需要覆盖中间帧和最终收敛：例如先出现取消中，随后实际结束；不能瞬间显示成功又被迟到旧投影改回运行。Theme、文字、图标和按钮禁用状态一致更新。

会话替换被阻塞时保留当前草稿和阅读位置，说明是哪项工作或保存操作阻塞，并提供已有控制入口。任务已终结且结果可靠保存后，即使尚未请求模型处理，也可以切走或正常关闭；再次打开仍显示待处理，不自动消费模型额度。

## 变化归入现有职责

| 模块 | 目标职责与修改重点 |
| --- | --- |
| `agentelier_llm_model` | 原生标志、最终响应校验、开放调用的原始协议表示、不可变请求、压缩条件与用量依据 |
| `agentelier_conversation` | 永久会话权威、活动 Turn 接纳、稳定任务账本、结果追加、恢复业务与可提取来源边界 |
| `agentelier_turn_runner` | 当前 Turn 的模型循环、同步依赖和管理工具等待；向所有者申请材料、报告事实，不带走完整 Session |
| `agentelier_tools` | 工具契约、固定调用上下文、执行策略、进程资源与结果边界 |
| `agentelier_mcp` | 固定来源绑定、每调用取消、断连/超时的真实含义；本地 Function 映射，不使用 hosted MCP |
| `agentelier_agent_runtime` | 单前台槽、后台句柄集合、准入、控制调度、存储回执协调与真实回收 |
| `agentelier_session_store` | 单写入者、响应与登记原子事实、结果/附件提交、开放历史恢复材料，不执行工具 |
| `agentelier_memory` 与来源读取 | 从闭合的来源账本组装证据，维护连续提取前缀及 reset/epoch 边界 |
| Conversation Bridge、Connection、Agent Host | 稳定会话任务事件、安全投影、唤醒与控制回执，保留前台 operation 隔离 |
| `agentelier_chat_ui` | 前台与后台并存展示、任务/进程控制、待处理结果动作、草稿/阅读状态 |

不新增承担整个 Agent 的总包，不把业务移到 `app/`，不修改 Bevy、Widgetry 或 BRP 上游。根 Workspace 的依赖规则、Windows x64 / DX12 / PowerShell 7 目标以及当前锁定依赖继续适用。[结构与 UI 参考](sources.md#结构与界面参考)解释资料的采用范围。

实施时，随着相应行为真正落地，同步更新总体架构、会话、模型请求、会话存储、长期记忆和 Direct 工具调用等现有设计。这里的目标文档不能提前替换尚未改变的事实，也不新建一套逐项功能说明目录。

## 实施时保持可验证的增量

执行方案先让协议模式、会话权威、开放历史与恢复可独立成立，再调整执行上下文和压缩边界，随后启用同 Turn 的非阻塞执行、管理控制、进程作用域、记忆来源和界面。最后一个真实功能增量才释放正常 Turn 结束与后台生命周期的绑定，完成跨 Turn。

这个顺序使原有同步路径始终有明确的验收入口。中间阶段没有达到的跨 Turn 能力不提前展示为已支持；同 Turn 异步阶段可以继续等待后台收束后再释放前台槽，避免过早开放尚未具备完整控制和投影的行为。最终产品采用本文组描述的跨 Turn 契约，不保留多套临时模式或为了迁移增加通用兼容框架。
