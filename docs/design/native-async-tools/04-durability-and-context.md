# 保存、恢复与压缩怎样维持关联

## 把可恢复事实放在真实副作用之前

跨 Turn 之后，日志不能再只保存“一批已经封闭的调用”。它需要独立表达合法响应、调用登记、执行开始、结果形成、历史追加和前台结束。仍使用现有 Session Store 单写入者、连续序号、Flush/sync 回执与本会话附件存储，不引入另一套任务数据库。

下面列的是必须表达的业务事实，事件名称在实现时可沿用或调整现有类型。

| 事实 | 持久确认与后续动作的关系 |
| --- | --- |
| 输入与请求准备 | 保存原输入身份、冻结历史前缀、来源材料、包含的结果集合及实际发送阶段 |
| 响应接纳与任务登记 | 完整响应和全部调用到任务的映射在一个原子追加记录中确认；之后才允许派发 |
| 执行开始 | 每个副作用开始之前确认；等待资源的登记不冒充已开始 |
| 工具实际结果 | 先提交图片附件，再保存带原始身份的不可变结果；保存成功才可用于历史 |
| 历史追加 | 记录所追加的唯一 output 及前后历史位置；不能用一份较旧 Session 快照覆盖后续事实 |
| 取消与资源清理 | 保存请求范围、执行终态与实际回收事实；取消请求和资源回收分开 |
| 前台终态 | 只表示前台结束和真实回收，不把所属异步任务强制改成未执行 |
| 压缩检查点 | 保存被覆盖的历史前缀、替换窗口、未配对调用关联和来源材料边界 |

任务 ID 在准备响应接纳记录时分配，随响应和映射一起提交，提交成功后才公开。崩溃不能留下“响应已接纳，但任务 ID 映射另存失败”的空隙。所有调用先通过身份、参数上限、模式和重复性校验；无效完整响应不进入正常可重放历史，也不启动其中任何工具。

同一记录的提交结果不确定时，沿用当前游标阻断语义，不盲目重新追加。结果已经取得而保存失败时，保留内存载荷、停止新的请求与副作用派发、暂停 Queue，继续回收必要资源。保存失败不撤销已经修改的文件。已有结果不以“再执行一遍工具”补救。

## 按崩溃发生的位置恢复

恢复只还原数据。加载日志后，先重建唯一历史、任务映射、结果事实与来源，再决定哪些任务需要中断占位。占位也必须持久确认，并标记为恢复产生的终止说明，不能伪造成工具的实际成功输出。

| 最后确认的位置 | 恢复行为 |
| --- | --- |
| 仅有请求准备或部分 SSE | 保留发送/部分展示事实；没有合法完整响应就没有可执行新调用 |
| 响应与登记已保存，开始记录尚无 | 记为 `NotExecuted`，为原调用补唯一的未执行结果 |
| 开始已保存，结果未保存 | 记为 `Unconfirmed`；副作用可能发生，补明确的未知结果说明，不重跑 |
| 附件已提交，结果记录未提交 | 附件不是调用成功证据；任务按结果未确认处理，不从文件存在猜测输出 |
| 结果已保存，尚未追加历史 | 使用已存载荷补唯一 output，不再次执行 |
| output 已追加，尚未准备后续请求 | 保留“已保存，待处理”，等待用户明确继续 |
| 请求已经发送，但完整响应缺失 | 保留请求结果未知；下次重放同一历史与同一结果，不重执行工具 |
| 前台 Finished 已保存，原工具后来完成 | 继续从任务事实重建旧来源工具，不能用 Finished 的旧快照覆盖结果 |
| 已发起取消，回收尚未确认 | 显示上次结束未确认；不从取消请求推断远端或本地副作用已经撤销 |

进程登记恢复为历史资源记录，不连接旧 PID、不猜测恢复 stdin/stdout。Windows 进程的实际关闭保障继续由现有 Job/句柄机制承担；下次打开时只陈述已保存的清理证据。旧 `session_id` 不得复用。恢复产生的“历史清理未确认”与本次进程中仍持有的待回收句柄分开：前者可作为持久终止证据，允许只读查看和会话替换，不等待重启后永远不会到来的 OS 回执；若涉及未知外部副作用，按明确的继续执行确认控制新派发。

重复加载应得到相同结果，不重复追加恢复占位。仍按现有规则处理残缺末行：先备份、校验前缀再规范化；中间损坏、重复序号、身份冲突和损坏附件明确拒绝，不以“恢复异步任务”为由覆盖原件。

已有同步历史继续可读；缺少异步字段对应同步模式。新增状态按本次真实需求表达，不建设多版本迁移框架，也不要求把旧历史重写成异步历史。恢复后的任务唯一性包含已经完成、取消和未知的历史任务，不能因列表收起而忘记这些身份。

## 已交付结果计入工作窗口

执行器各自规范化文本与图片输出。会话只在结果追加实际请求历史时计入它的文本和图片 token，待保存或已保存未追加的结果继续由账本追踪。当前工作窗口内已配对的图片参与模型请求，原始附件持续归档。每个调用都须交付唯一的结果或明确错误。

## 未配对调用改变压缩时机

这里的 pending 是协议概念：原始调用已经在历史中，但唯一对应 output 还没有追加。执行已结束、结果还在保存，也仍是 pending；相反，`exec_command` 已返回 `session_id` 后，进程继续运行不属于原函数的 pending。

本次采用保守边界：

1. 冻结请求快照时，只要还存在未配对调用，就不发送 Inline `context_management` 配置；不在请求发出后因任务刚完成而改判断。
2. 调用全部闭合后，恢复现有 Inline 压缩。压缩仍由普通 Responses 请求承载，计入原模型请求预算，不新增独立轮询或自动重试循环。
3. 返回的 compaction item 必须位于没有未闭合调用的合法历史位置，才允许作为替换边界。安全 compaction 在新 async call 之前时，可以保留该调用和后续结果关联。
4. 如果服务返回了越过未闭合调用的 compaction，整份响应在正常历史接纳、任务登记和副作用派发之前失败；保留请求错误与安全诊断，不安装这份响应或压缩窗口。

第 4 种情况不自动重发一套不同请求。错误状态提供一次性的“本次不压缩并继续”动作：绑定这次失败请求及原输入引用，确认没有新的用户 Turn 取代它后，从当前合法历史继续，只对这一次新请求省略压缩。已经追加的用户输入与工具结果不再追加，未提交的原输入按原身份接入；先前副作用不重跑。动作产生新的请求身份并计入预算，容量不足时保留输入并拒绝发送，再失败时停止，不循环重试。应用不能把非法响应当成已经成功接纳的工具批次。先前任务的结果仍按合法历史边界保存与追加，不被失败的压缩响应拖住。

官方文档说明了[有序保留不透明压缩项](https://developers.openai.com/api/docs/guides/compaction)的方式。此处的 pending 约束是本方案根据原始调用关联设定的应用规则，验收需要检查真实请求和结果续接，而不只检查本地列表还留着一个 ID。

## 达到压缩阈值时等待结果完成

按当前请求历史、模型材料和实际用量计算上下文。达到自动压缩阈值时，Runner 等待未配对调用的结果，在本地保存、追加结果，同时处理 Stop 和用户控制。调用闭合后，下一次请求带上 Inline 压缩配置。等待本身不发起模型请求。

需要跳过压缩时，发送前核对实际工作窗口是否超过模型有效容量。容量不足时保留请求输入和已保存结果，返回可解释的上下文错误。用量未知时保留未知状态，并继续检查发送格式和历史连续性。

## 压缩检查点只替换它覆盖的历史

checkpoint 绑定协议历史位置与被覆盖前缀，不绑定包含所有 UI 变化的全局版本。任务从 Running 变成完成、名称修改或 Queue 入队，不应让本来合法的压缩不断失效。

准备 replacement 时保留 compaction 之后的调用与未配对集合；持久化 checkpoint，确认后核对原历史前缀并安装新窗口。冻结之后确认的尾部结果或输入必须在新窗口尾部保留，不能由旧快照覆盖。若前缀不一致或回执不确定，阻断继续发送并重新加载权威存档。

原始公开时间线、任务身份和附件不因工作窗口裁剪而删除。调用尚未闭合时不跨过它的原始位置，也不从任务列表重新拼一份“补发调用”来修补被裁掉的历史。项目规则与 Skills/记忆材料仍按原有窗口与来源规则补发，调用模式和管理工具 schema 也进入请求计量。

## 长期记忆等待的是来源证据完整

当前记忆来源读取会从 Turn 终态固定证据。跨 Turn 之后，前台 Finished 不再代表所属工具与进程已经结束；若沿用第一份 Finished 快照，即使晚些时候再提取，也会漏掉迟到结果。

目标对来源 Turn 的闭合条件增加：前台已经结束，属于它的工具均有持久终态结果，资源已有持久可解释的终止说明，必要的历史归并没有不确定提交。本次仍有真实运行或待回收句柄时不能闭合；恢复生成的历史清理未确认则是可记录的终止证据，不要求补到已经不可取得的 OS 回执。记忆读取从日志与最终任务账本重新组装该 Turn 证据，包含晚到输出、失败、未知状态和实际清理事实；不把“调用成功、进程仍运行”或“历史结果未知”提取成工作成功。

本次维持按原始 Turn 的连续可提取前缀。较早 Turn 尚未闭合时，不把提取游标跨到较晚 Turn，以免永远跳过早期任务的结果；后台长时间运行可能延后这份会话的记忆提取，其他会话不受影响。来源完整不要求模型已经解释结果，但要求实际结果事实已经可靠保存。

记忆重置的 cutoff 按原始用户输入/Turn 的来源序号和纪元判断。重置前启动的任务即使重置后才完成，也不能被当作新的记忆证据重新导入；其工具执行也继续受旧纪元约束。点击“处理已完成结果”只触发模型续接，不提供新的用户授权；旧任务更不能借它调用记忆修改功能。
