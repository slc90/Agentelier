# 模型能力、Agent Role 与协作指令

多 Agent 模型选择由模型目录和创建策略共同决定。模型目录说明模型自身支持什么；Spawn 策略决定子 Agent 继承还是覆盖；Agent Role 定义职责与行为约束；协作指令则告诉 Root 何时委派、怎样协调和怎样汇总。这几层不能混为一个“Agent 类型”字段。

## 模型能力目录

Agentelier 从 Codex 模型目录取得模型 slug、显示名称、推理等级、上下文能力及 `multi_agent_version`。`ModelInfo` 将 `v2` 映射为支持，`v1` 和 `disabled` 映射为不支持，缺失、空值与未知版本映射为未知。字段类型异常会拒绝刷新。普通模型选择及请求只使用原有模型能力。子 Agent 的显式覆盖须选中当前目录中声明 V2 的条目，并核对此条目的推理档位。[Codex 模型目录字段](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/openai_models.rs)

模型能力来自服务端目录，不通过字符串前缀推断支持能力。代际筛选可使用目录元数据或经过确认的目录映射；模型 slug 的 `gpt-6` 字样本身不能证明功能支持。

## 子 Agent 模型选择规则

- 默认使用 Spawn 调用步骤中的父 Agent 有效模型和推理强度。
- 显式模型覆盖必须命中当前可用模型目录，并通过 Multi-Agent 能力检查。
- 显式推理强度必须是该模型支持的等级；省略时使用模型默认等级。
- 模型配置与能力快照要随 Agent 保存，冷恢复时按原有效选择恢复；目录更新导致原模型不可用时，进入明确的恢复错误/待处理状态，不静默换模型。
- 不允许把模型名称、推理等级或服务层级覆盖当作权限升级。

## Agent Role

Role 是职责预设，例如研究、实现、审查或默认通用角色。它可以提供专用指令、模型偏好、推理偏好和能力收窄项。Role 不是 Skill：Role 决定 Agent 的职责和行为边界，Skill 提供完成任务的可复用知识或操作能力。两者可组合。

Role 应有稳定名称和可解析配置。未知 Role、格式错误或引用缺失必须产生明确创建错误。Role 的配置应用在父 Agent 有效配置之上，只允许维持或收窄父级权限；Role 不得启用父 Agent 不具备的工具、网络、文件或审批权限。

## 协作模式与 Root 指令

Root 的协作指令控制是否委派以及如何委派。当前确认的模式为：

- **Explicit Request Only**：用户明确要求多 Agent 或并行协作时才创建子 Agent。
- **Proactive**：Root 可以根据任务复杂度主动拆分并委派。
- **Custom**：采用用户配置的协作策略文本或策略预设。

Root 指令需要解释任务拆分、并行条件、结果核验、冲突处理、等待策略和最终汇总。子 Agent 指令需要强调任务边界、不要重复扩张任务、完成后向父 Agent 汇报、需要更多工作时通过消息或 Follow-up 请求。子 Agent 不应把内部协作过程直接展示给用户。

## 提示词快照

Agent 创建时固定适用的基础指令和 Role 版本，避免用户之后编辑提示词导致运行中 Agent 的行为来源变化。新创建的 Agent 使用新的会话设置快照；已有 Agent 的冷恢复使用原快照。Prompt 来源、版本和哈希应与现有 `agentelier_prompts` 快照机制衔接。

## 验收模型策略

验收 Root Agent 固定使用 `gpt-6.2-sol`。子 Agent 模型从实际目录中选择 GPT-6 及以上代际的非 Astra 级别模型。子 Agent 可以按职责选用不同的合格模型，以验证模型覆盖功能；验收记录必须列出实际 slug 和推理等级。不得将 GPT-6 Astra 或其他 Astra 级别模型用于本次验收。

如果模型目录没有提供足以判断代际或 Astra 级别的信息，应先人工确认目录项，不得只凭猜测自动选择。若当前账号不可用 `gpt-6.2-sol`，不得更换 Root 验收模型并声称完成。
